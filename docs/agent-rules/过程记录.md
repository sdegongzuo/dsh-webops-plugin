# 过程记录管理

用于新增、补充或查找开发过程记录。人和 agent 共用，统一从 [过程记录入口](../records/README.md) 查找；当前操作和生效规则仍按 [长期文档](文档组织.md) 执行。

## 1. 收录范围

| 收录到过程记录 | 保留原职责 |
|---|---|
| 开发进展、排障经过、临时实验 | 当前使用指南、操作流程、规则、机制参考 |
| 单次合并验证、测试与验收报告 | 可重复使用的验证方法 |
| 某次安装、部署或发布的执行记录 | 对外 Release 说明 |

尚未实施的方案继续作为设计材料管理，不因为未落地就归为过程记录。混合文档只登记其中的过程章节，不把整份指南或方案改成历史记录。

## 2. 存放与登记

- 新记录放 `docs/records/YYYY-MM-DD-主题.md`，日期取本次记录开始日期；同主题同日有独立验证对象时加对象名区分。
- 先查 [记录索引](../records/README.md#记录索引)。同一次工作的补充追加到原记录；独立提交、产物或实验需单独报告时再建文件。
- 创建后登记日期、主题和文件链接。记录索引负责查找，正文负责结果；不在索引复制测试数字和详细结论。
- AGENTS.md 只保留统一入口。长期文档在需要解释结论或追溯证据时，链接到具体记录。
- 大体积日志、截图和原始回执保留在明确的 D 盘证据目录，正文登记路径与对应对象；不把凭据和认证 token 写入记录。

## 3. 最小记录内容

用短段落或表格写清以下内容，无需强套固定标题：

| 项目 | 要求 |
|---|---|
| 日期与进度 | 日期；进行中、已结束或被替代。结束不等于验证通过 |
| 对象 | 提交、版本、构建产物或实际实例；可定位本次工作 |
| 目的与操作 | 为什么做、实际做了什么，关键命令与参数 |
| 结果与限制 | 通过、失败、跳过和未验项分开；标明结果对应哪层验证 |
| 证据 | 原始输出、回执、报告或附件的路径与关联关系 |
| 后续入口 | 当前指南、遗留问题或后续记录；没有后续时不必添加 |

实现、验收、安装和发布状态分别记录。历史通过只证明对应对象，不代表当前版本或用户安装状态。

## 4. 补充、结束与替代

1. 进行中的记录按日期追加实际进展，保留失败尝试和限制。
2. 结束时写明结论和未完成项；稳定的操作、约束与方法提炼到长期文档，剩余任务接入遗留问题或对应设计。
3. 发现旧结论有误时，追加注明日期的更正和依据，指明被更正内容；不悄悄改写历史结果。
4. 后续记录替代旧记录时，补上双向链接和适用范围；旧记录继续保留，不能作为当前操作入口。

## 5. 既有记录

已有独立报告和长期文档中的历史章节先按原路径登记，不批量搬移、复制全文或删除。`docs/验收记录.md` 保留既有正文，并作为交付结论与证据索引；新的详细过程报告写到 records，验收记录只追加必要结论和链接。

单次报告即使验证已通过，也仍属于过程证据；只有可持续复用的指南、方法和规则才纳入长期文档标准。

## 6. 完成检查

新增或补充后，核对对象、结果、限制和证据对应，检查索引及相对链接。涉及当前行为变化时同步长期指南，涉及遗留任务时同步相应入口。文件操作和规模分别遵守 [项目规则](../../AGENTS.md#文件删除) 与 [文件规模规则](文件规模.md)。
