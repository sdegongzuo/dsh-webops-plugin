# 本机排障规则

遇到启动、网络、文件锁、工具输出或构建异常时按症状读取。详细操作见 [开发指南 §4](../开发指南.md#4-本机环境坑都不进生产但会浪费半天) 与 [打包与发版](../打包与发版.md)。

## 1. 启动与端口

- 启动桌面端检查 ELECTRON_RUN_AS_NODE；GUI 路径需清除该变量，主 exe 执行 Node 脚本时则按运行方式显式设置。
- 检查 NODE_OPTIONS 注入影响。exit=0 且输出为空不代表 GUI 真正启动，核对进程、端口与数据目录变化。
- 进程按端口或精确 exe 路径定位；避免过滤串命中自己的命令行，避免 CSV 文本被引号误导。
- 后台 GUI 需跨工具调用确认仍存活，同一调用内 sleep 后查询不能证明脱离工具生命周期。优先现有 portable:launch。

## 2. 构建与网络

- 本机 harness 构建使用 harness:build；registry 与 Electron 镜像从 local-env 配置读取。
- 新上游支持 registry 环境入口时直接注入；旧上游临时补丁必须无条件还原并校验哈希，失败保留备份路径。
- Electron 镜像依赖 @electron/get 的环境语义；下载失败时核对 downloadArtifact 调用是否仍支持该入口。
- 直接跑 harness tsx 时使用 Node 加 tsx/dist/cli.mjs 的实际路径，避免 MSYS 路径转换；调用 package-target 时核对 npm_execpath。
- 新 exe 路径可能受到本机网络放行限制；先做该 exe 的出网验证，不直接归因于包结构。

## 3. asar 文件锁

- EBUSY/EPERM 先用 scripts/who-locks.ps1 点名持有者，必要时 OutFile 落盘读取。列出的持有者不一定阻止删除，需区分共享模式。
- 工作区内可解析的 asar 可能被 IDE 持有；本机大件放工作区外，不把历史“安全软件锁”当成已确认原因。
- 已被持有的 asar 不靠等待、截断或目录改名解决；这些操作也不得用于绕过文件删除规则。
- 共享读可用于压缩，必要时走 scripts/zip-stage.py。修改缓存写入前检查是否依赖重命名或删除。

## 4. 删除垫片与工具异常

- safe-delete 垫片可能造成逐文件延迟或回收站助手 ETIMEDOUT；该错误可能没有 error.code，日志必须保留 message。
- 本规则不授权停用保护、运行 clean 或换子进程删除；涉及文件清理只提供精确手动命令。
- PowerShell 输出为空时可将结果 Out-File 后读取；输出正常时无需强制切换 shell。
- Bash 追加可能重复，优先精确编辑；确需追加时核对出现次数。
- 截图能力受限时使用现有脚本写出产物文件，不能把缺少截图当成视觉验收通过。
