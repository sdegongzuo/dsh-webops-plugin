# 验证与发版规则

修改测试、workflow，运行便携版验收、打包或发版前阅读。具体命令与步骤使用 [打包与发版](../打包与发版.md)，本文件列执行门禁。

## 1. 验证

- 配置或脚本修改后做对应回归；新增关键断言先反向验证，再恢复并复验。
- 打包态缺陷在打包态运行时验证。结构自检不能证明 GUI 可操作、真实模型回复或实际调用工具。
- 本机执行类型检查与单测；修改 `.github/workflows/*.yml` 必须重跑单测，bundle-patch.test.ts 读取 YAML 本身。
- 不把依赖 harness 本机构建产物的 typecheck/test 塞进发布 workflow；CI 门禁另建不阻塞发布的 workflow。
- AX 形状契约使用真 Chrome live 组验证；Electron 端点造成跳过时不得报告通过。
- 比 bundle 字节先剥 sourceMappingURL 中每次启动变化的 &rev=。
- 宿主自检前确认 19387 无其他实例；优先用现有 assertHostPortFree。自写探测使用 netstat 或无 host 的 listen，不能只 bind 127.0.0.1。

## 2. 固定测试目录

使用 DSH_PORTABLE_TEST_DIR，一次铺底、以后增量更新。操作细节见打包文档“本地测试的固定目录”。

- 插件更新用 portable:refresh；更新后必须重启才能加载新代码，不用 Ctrl+R 代替。
- refresh 不要求先停实例，但必须先核对脚本是否会删除文件；涉及删除时按根规则仅提供手动命令。
- 换 app 前先正常关闭目标目录实例；需要杀进程时取得授权并点名 PID，避免按镜像名误杀其他会话。
- set-app、--move 与其他换目录操作先检查实际文件行为，不因命令别名隐藏删除或移动。
- 固定目录可复用于 portable 自检；空出厂 patch 按内容判定，有内容的越权 patch 仍应失败。
- GUI 结果以页面侧效果和真实工具回执验收，不以启动成功、绿测试或 bundle 中存在代码代替。

## 3. 构建与包结构

- 本机重编桌面端用 harness:build，镜像由本机配置提供；改 packages/* 后先 build:lib:host，防止旧 lib 出货。
- 日常插件更新走增量包；三种 zip 的用途按打包文档 §10 区分。
- 缓存按 dsh 版本分槽，必须有 cache.json 完成标记与完整性校验；不可用时明确失败，不静默降级。
- 缓存写入保持 mkdir → 复制 → 校验 → 完成标记；不靠临时目录改名解决 asar 句柄问题。
- 增量更新保留用户 home 数据，默认不动用户 profile/package.json。
- 打包脚本可能覆盖或删除旧输出；执行前核对源码，选择未使用的明确输出路径，不能运行删除分支。
- zip 使用 testzip 校验，解压走 scripts/unzip-portable.py，并检查产物前 32 字节无 NUL。
- 出货不含 fake-llm；生产链 patch 的用途与允许内容按打包文档 §8 核对。

## 4. 发版门禁

- 推 tag 前，本机类型检查、单测、真实便携版增量验证与 GUI 验收全部完成，记录命令结果与版本。
- 显式版本来自 tag，并与 package.json 一致；取产物按确定文件名，不按目录首个 zip 猜。
- 找 win-unpacked 按 mtime 排序并核对完整性；校验哈希对应实际上传文件。
- workflow 负向验证从一次性分支用不存在的版本 dispatch，不能拿已发布版本试 upload --clobber。
- 已发布 tag 重指涉及 release/tag 处置与强推，必须先取得授权，不能原地覆盖已发布附件。
