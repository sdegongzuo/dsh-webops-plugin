# 网页交互改进实施方案

更新：2026-10-12。状态：execute 的 async 函数体接口、全工具参数校验、等待附快照、取消公开 revalidate、旧引用错误附观察、交还观察门禁及截图修复已进入 v0.2.17 独立插件与完整便携包。最终类型检查通过、847 项回归通过且无跳过，打包态真实模型对话已验；历史 execute 对照结果及本轮验证边界见 [验收记录](验收记录.md)，不能据此宣称所有模型的整体任务成功率提升。其他后续修复按下述复现条件启动。

## 1. 目标与范围

网页动作按意图生效；未生效时，回执明确说明已知原因、未知信息和可执行的下一步。

本方案管理点击、填写、滚动、历史导航、浮层、execute 和错误回执。上下文预算按 [上下文方案](上下文膨胀-实施方案.md) 执行；对话权限按 [标签占用方案](多会话防冲突-实施方案.md) 执行。CDP 行为依据见 [CDP 实测事实](CDP实测事实.md)，不在本文复制测试过程。

## 2. 已交付行为与维护约束

| 功能 | 保持的行为 |
|---|---|
| 旧 ref | 节点消失或文档变化使用 BROWSER_STALE_REF，提供恢复路径，不透出裸节点错误 |
| click | elementFromPoint 校验落点；命中遮挡**在派发前拒绝**（BROWSER_TARGET_OCCLUDED，零页面副作用，2026-10-07 独立验收）；无跳转时返回目标与下一步，不自动补 Enter/Escape |
| locate | centered 是测得的「真居中」事实（元素中心对齐视口中心，±16px 容差；超视口的轴按完全覆盖判），「看得见」不算居中；视口测不到或为零时恒 false；smooth 动画重测到居中为止（有界 ≤600ms） |
| 零视口窗口 | innerWidth/innerHeight=0（最小化 / 隐藏）时 click / scroll / locate 一律拒绝（BROWSER_WINDOW_NOT_VISIBLE），不派发任何事件、不代恢复（host.cjs 退化读数守卫是唯一权威） |
| fill | 保留现有 setter 路径；带联想的搜索框指导 fill 后对同一 ref 按 Enter，不自动点提交按钮 |
| scroll | 后台标签先激活或明确拒绝；wheel 使用 2 秒专用等待，允许返回“已投递未确认”，总体 3 秒内返回 |
| 历史导航 | url 与 history 恰好一个；back/forward 使用 CDP 历史接口，reload 使用 Page.reload；尽头明确报失败 |
| 导航后 | 作废 ref 与 find 缓存，下一步 snapshot，不直接 find |
| snapshot | 浮层提示在大纲顶部；无 dialog/aria-label 的浮层也尝试读取可读名字 |
| find | 只搜索已发出的缓存大纲；截断且零命中时提示增加 max_lines 后重拍，不自动补快照 |
| wait | 恰好选择一种条件；`time_ms` 为固定延时且不能与 `timeout_ms` 同用，文本/ref/stable 共用 1–30000ms `timeout_ms`（默认 10000ms）；命中或正常超时（`satisfied=false`）后返回完整快照，新 refs 可直接用且 find 缓存已刷新 |
| execute | 唯一模型参数为 session_id、code、可选 timeout_ms；code 是一次性 async 函数体。{}、[]、null 合法；undefined 明确标 has_value=false；DOM 与非 JSON 结果明确拒绝 |

浮层名字优先 aria-label/alt，再读自身或有文本祖先；向上最多 5 层且不读 body，片段最多 60 字。不得把整页正文当成浮层名。

execute 的 timeout_ms 范围为 1–30000，默认 5000 毫秒；provider 仍取请求预算与自身 commandTimeoutMs 的较小值。超时回执说明结果未确认，页面函数可能继续，副作用不会回滚。代码不自动补 return、不改写参数、不重跑。

每次调用把 code 放入新的 async 函数体，因此局部 const/let 不跨调用；window/globalThis 赋值、DOM 修改和网络请求仍可持续存在。返回数据限普通 JSON 值；页面内检查拒绝 DOM 节点、访问器、函数、循环引用、非普通对象和超预算结构，不调用 getter 或 toJSON。大文本会裁剪并标 truncated；大结构报错并要求只 return 所需字段。受控组件操作使用 click/fill/press，不把直接改 DOM 当成可靠输入路径。

## 3. 后续维护与启动条件

### 3.1 遮挡与落点诊断

点击回执应区分“已投递事件”和“页面已导航/控件已生效”，不把无页面变化的 click done 当成成功验收。

### 3.2 错误回执

下列项目是持续维护要求；本轮原始错误文本未统一展示内部 BROWSER_* 码，不能把已有场景通过等同于错误码呈现已验收。修改前先复现具体缺口。

- 模型可见文本包含对应 BROWSER_* 错误码，与工具描述一致；检查统一错误呈现路径，避免在各工具重复拼码。
- execute 超时从 CDP/Electron 通道的结构化超时类型映射；回执说明结果未确认、函数可能继续执行、副作用未回滚，不把其他命令超时误写成页面代码仍在运行。
- 非 execute 的协议超时不套用“页面表达式仍在执行”文案。
- 对节点失效、不可序列化、历史尽头、execute 超时分别断言完整文本与恢复建议。

位置：`src/tool-browser/index.ts`、`src/browser-cdp/provider.ts`、`execute.ts`、`protocol.ts` 与对应测试。实施时先查宿主实际错误渲染，确认文本最终到达模型。

### 3.4 旧 ref 恢复设计（2026-10-11，已接线，验收见记录）

取消模型侧 `webpage_revalidate`，采用「旧 ref 拒绝动作，并在同一次回执附带新观察」。不把现有 revalidate 直接接成 click/fill/press 的自动恢复或重试；文档、DOM 节点、role/name 相同不能证明所属业务记录未变。机制实测与限制统一记录在 [验收记录](验收记录.md)。内部精确身份检查可保留用于诊断，不作为写操作复活旧引用的授权。

| 状态 | 处理 |
|---|---|
| 当前 ref 有效 | 保持正常执行，不增加恢复快照或模型工具调用 |
| 可信错误确认 ref 已失效，且输入事件尚未派发 | 停止本次动作；在原租约和同标签操作序列中取得一次完整快照，随错误返回新 refs，让模型重新选择目标 |
| 导航或刷新导致旧引用失效 | 同样拒绝旧动作并返回当前文档的观察，不能按同名控件自动换目标 |
| 人工持有、标签不属于当前对话 | 保留拒绝，不自动恢复或观察他人的标签 |
| 交还后尚未完成完整观察 | 在 provider 的输入派发入口硬性拒写；可以附带一次交还后完整观察，但本次失败动作不能借此继续执行 |
| 输入已派发或状态未知、取消、超时、连接丢失 | 不重跑、不附加恢复动作；保留实际错误与结果未知边界 |

#### 执行接线

1. 优先补 provider 写入口对 `needsReobserve` 的硬门禁，未完成交还后的完整观察时报 BROWSER_SNAPSHOT_REQUIRED，不能只靠动态提示和旧纪元拒绝。随后在 ref 拒绝分支记录可信的 `dispatch_state=not_dispatched` 与失效原因；不能从错误文本猜是否派发。进入 click/fill/press 等写操作时先检查 holder、租约、交还观察标记，再解析 ref。只有成功的交还后完整观察可以清除 `needsReobserve`，revalidate 与人工期间观察都不能清除或绕过。内部诊断区分 document_identity_unknown 与 document_changed，不把缺少身份依据说成实际导航。
2. browser runtime 统一处理可恢复观察的错误，覆盖带 ref 的 click/fill/press/scroll/wait、locate、元素 screenshot 和区域 snapshot。execute 不参与 ref 恢复；find 继续使用当前缓存。权限错误不进入补拍路径。
3. 补拍保持原 owner、session_id 和租约代次；在取得观察前后核对归属，失去权限就停止。同标签调用排队，取消候补不能越过仍运行的前任；原操作和恢复观察是一个调度单元，期间不能插入另一操作。候补也计入在途租约，不能跨释放与重新领取的代次。后续观察仍可依法推进纪元，多个观察回执以最后一份为准。一次失败最多补拍一次，使用原 exec.signal 和剩余工具预算；恢复观察子预算最多 2 秒，剩余预算不足则只返回原错误。观察失败保留原错误，再注明未取得新观察，不覆盖成次要错误。
4. 新观察写入与 snapshot/wait 共用的 find 缓存路径；携带 epoch、truncated、page_changed 及可用 refs。回执明确「原动作未派发；不要重试旧 ref；使用本次观察的新 ref 决定下一步」。页面仍可能随后变化，不能承诺新 ref 永远有效。
5. 在工具执行阶段准备恢复内容，用宿主 `projectContent` 接入错误回执，保留 `isError=true` 和原错误码；该同步回调只投影已准备内容，不执行浏览器 I/O。调整现有 presentBrowserError 转换顺序以保留结构化错误与可信恢复信息；禁止把失败包装成正常成功输出。
6. 下线 revalidate 的工具注册、配置项、加载清单及模型恢复指引；内部身份检查与边界测试按职责保留。系统提示、description、错误文本统一优先使用回执附带的新观察；仅在未附带、截断或任务确需更多内容时另行 snapshot/find，不再指引调用 revalidate。

元素截图也复用节点连接与文档检查：正常元素截图增加一次 CDP 检查，不增加模型工具调用；已摘除节点在真正截取图片前拒绝，避免落成没有恢复分类的布局错误。

快照保留 ref 的 `anchor` 权限，并分别统计可操作控件与只读标题；不能把所有 refs 说成可操作元素。恢复回执显式提示 click/fill/press 只使用 `[ref=eN]` 控件，不能点击 `[anchor=eN]` 标题。误选只读锚点后，已有观察包含控件时无需再次全页重拍。

#### 验收与收益口径

- 正常引用无新增快照；旧引用被拒时页面零点击/填写，错误中只附一份观察；模型随后实际使用其中的新 ref，不重复拍完整快照。
- 覆盖同节点未变化、同节点换记录、同名节点替换、节点改名、导航/刷新、人工持有与交还；同节点换记录不能让旧目标悄悄变成新记录。另验证读型工具、观察失败、预算耗尽、取消、权限转移，以及两个并行操作不互相覆盖 refs。
- 接管期间明确拒写；交还后先尝试 revalidate/内部身份检查仍不能解除服务端观察门禁。若未满足交还后的完整观察，旧引用动作必须零派发。
- 对新增守卫做反向验证：移除 not_dispatched 判断、移除 needsReobserve 门禁、把错误标为成功、补拍后自动重跑输入，都必须被测试发现。
- 旧引用恢复路径从「动作失败 → snapshot → 新 ref 动作」三次调用缩为「动作失败并附快照 → 新 ref 动作」两次，目标减少一次调用；实际覆盖与收益以本次构建的原始回执为准。会增加失败回执体积和观察耗时，按完整请求、轮数与实际 token 计量。

### 3.5 click / press 后观察

状态：开发候选已完成真实基线及两轮对比，尚未进入公开 v0.2.17；实测数字与限制统一见 [验收记录](验收记录.md)。

`webpage_click` 与 `webpage_press` 默认只返回动作回执，不增加观察。需要读取动作结果时传 `observe=true`，在同一租约与标签队列内附一份全页快照；已知页面可见正文标记时可传 `wait_text`，按正文包含关系等待后附快照。`timeout_ms` 只设置该文本等待的 1–30000ms 预算，省略时为 10000ms；它只能与 `wait_text` 同用，`wait_text` 也不能和 `observe=false` 同用。文本命中与正常超时都会拍一次快照，超时以 `satisfied=false` 表示；不以 DOM/network stable 推断业务完成。

点击或按键成功派发后，若等待或快照失败，回执保留原动作事实并标 `action_dispatched=true`、`observation_error`，提示不要重发动作；等待失败不再追加快照。原动作未成功返回时继续沿用原错误和可信的派发边界，不进入这条后处理路径。所有阶段共用原 `exec.signal`，取消时不保证后处理回执仍能到达调用方。

## 4. 执行顺序

1. 查看 git status 与相关源码，核对待办是否已被其他会话实现；按符号定位，不沿用历史行号。
2. 为 §3.1、§3.2 的缺口写失败用例；页面脚本测试必须实际执行脚本，不能只由 fake-CDP 回预设值。
3. 实现诊断与回执，保留现有动作、导航与人工接管语义；条件任务仅在复现后加入批次。
4. 运行 `pnpm typecheck`、`pnpm test`；新增关键断言分别做反向验证，恢复后复验。
5. 按 [打包与发版](打包与发版.md) 更新固定测试目录并重启，使用真实工具对话跑 §5。
6. 记录提交、产物版本、实际回执与页面侧结果；单测或 Chrome 探针通过不能替代 Electron GUI 验收。

本机路径走 `.env.local`。GUI 测试错开其他会话的驱动时段，避免状态与布局干扰。

## 5. 打包态验收场景

| 场景 | 操作 | 通过条件 |
|---|---|---|
| A：连续输入 | Google AI 模式或可用流式页面，两轮 fill + Enter + 文本等待 | 两次输入与结果均实际出现，不在 busy 时加长 stable 空等 |
| B：搜索联想 | fill 查询后同 ref Enter | 提交查询与输入一致；导航后先 snapshot |
| C：打开、返回、再打开 | 直链、重定向、target=_blank，随后 navigate history=back | 导航或 opened_tabs 与页面一致；返回走专用工具；未导航时回执足以决定下一步 |
| D：旧 ref | 导航后不重拍，使用旧 ref | BROWSER_STALE_REF，文本有恢复指引，无裸 No node with given id found |
| E：浮层 | 全屏浮层，小快照，点击下方目标，关闭后再点，截断 find | 首屏有 OVERLAY；连续 3 次遮挡不丢；关闭后真实点击生效；零命中解释截断 |
| F：滚动 | 前台长文、另一站点、后台标签各滚一次 | 每次 ≤3 秒；激活或拒绝明确；记录页面实际滚动位置 |
| G：execute 边界 | return 的普通对象、{}、[]、null、undefined、DOM、循环与深对象；连续两次声明同名局部变量 | 空值类型明确可分；undefined 为 has_value=false；不可序列化有边界错误；局部变量互不冲突 |
| H：execute 超时 | 永不完成的 Promise，timeout_ms=2000 | 约 2 秒结束主等待；错误码分类明确，说明结果未知、代码可能继续和副作用边界；验证无自动重跑及超时参数范围 |
| I：空点与探测失败 | 空点夹具；注入 hitTest 异常 | 分别报告空点、无法探测，不能都呈现为无遮挡 |

Google AI 模式入口为 `https://www.google.com/ai`。若账户或地区不可用，记录环境阻塞并用可访问页面验证工具，不以猜网址绕过；没有真实输入与响应就不标连续对话通过。

## 6. 实施边界与完成记录

- 不自动关浮层或按 Enter/Escape；§3.4 仅允许在可信、未派发的引用拒绝中附带一次有界观察，禁止因此继续或重试原动作。
- 不为具体站点写键名白名单或专用操作适配器。
- 不新增默认 submit、自动 DOM 回滚、execute 聚合 console/network 或模型可选 isolated world。
