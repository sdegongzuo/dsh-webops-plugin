# 并发网页操作实施方案

更新：2026-10-13。状态：已实现并完成本轮实测修复，未发布。最终候选覆盖 13 组真实 Electron 受控场景，另有真实模型对话与原生接管证据；没有宣称整张矩阵穷举通过，构建边界与剩余证据见 [验收记录](验收记录.md)。适用于多个对话在同一浏览器窗口操作不同标签时的前台竞争。

## 1. 目标与当前依据

不同标签的后台读取、页面加载和结果等待可以并行；同一窗口内需要前台的动作按序执行。后台标签发起动作时等待输入权，取得后自动激活、重新准备并派发。正常并发竞争不直接返回“标签不可见”。

当前源码依据：

- [标签调用队列](../src/browser/tab-call-queue.ts) 与 [BrowserRuntime](../src/browser/index.ts)：同标签工具调用串行，包括失败后的恢复观察；候补计入租约在途调用。
- [CDP provider](../src/browser-cdp/provider.ts)：click / press 检查页面可见性并尝试激活；click 测量后再次检查，变成不可见时拒绝；scroll 使用独立的前台准备路径，fill 没有统一的可见性准备。
- [Electron 宿主](../src/browser-electron/host.cjs)：持有实际活动标签、视图和人工控制状态，最终派发 CDP 命令；激活、弹窗、布局与截图会影响前台或页面可见性。

以上是当前工作区源码结论，包含既有未提交改动，不代表已安装版本。对话权限继续以 [多会话方案](多会话防冲突-实施方案.md) 为准；ref、交还观察和动作回执以 [网页交互方案](webpage交互改进-实施方案.md) 为准。本方案只管理共享窗口的操作调度。

## 2. 调度边界与不变量

| 层级 | 资源与权威位置 | 持有范围 |
|---|---|---|
| 标签调用队列，已有 | BrowserRuntime，键为 provider + session | 完整工具调用及恢复观察 |
| 窗口输入队列，新增 | Electron 宿主，键为实际窗口实例 | 激活、输入准备、事件派发与必要收尾 |

固定获取顺序：标签队列 → 窗口输入权。窗口调度器不等待其他标签队列，不从持有输入权的动作内申请另一个窗口输入权。弹窗家族归属处理不得引入反向锁依赖。

必须保持：

1. 一个窗口最多有一个有效输入权；不同窗口独立调度。同一实际窗口的多个连接共享宿主队列，不能只按 provider id 创建互不知情的锁。
2. 输入权不跨模型轮次，不覆盖导航、wait_text 或常规观察等待；同标签队列仍覆盖这些阶段。
3. 所有 agent 引起的前台变更进入同一调度入口，包括显式 activate、open 的展示、关闭当前标签后的替补激活及弹窗展示。
4. 前台输入在取得输入权后重新验证文档、ref、控制状态和几何信息；排队前测得的坐标不得用于派发。
5. 人工接管立即撤销输入权；已派发、部分派发或执行状态未知的动作不得自动重放。
6. 释放输入权只表示共享资源可以交给下一动作，不表示业务动作成功。
7. 当前活动标签为人工持有时，窗口前台保留给人工；agent 的自动激活、open 展示与弹窗展示暂缓，后台读取继续。此规则与目标标签的 holder 检查分别执行。

## 3. 操作分类与临界区

| 操作 | 窗口输入权范围 | 释放后的工作 |
|---|---|---|
| click | 激活、确认可见、解析目标、滚入视口、测量、遮挡检查、mousePressed / mouseReleased | 导航等待、弹窗归属收集、附带观察 |
| press | 激活、确认可见、解析并重新聚焦目标、keyDown / keyUp | 导航与文本等待、观察 |
| fill | 首版整体纳入：激活、确认可见、解析目标、setter / 聚焦 / Input.insertText | 观察；不自动提交 |
| scroll | 激活、测量落点、wheel 派发、滚动有界稳定检查 | 页面观察 |
| locate(scroll=true) | 激活、滚动、等待有界稳定、最终几何测量 | 回执构造 |
| activate | 验证权限并完成激活 | 返回标签状态 |
| open | 将创建拆成不改变前台的准备与进入队列的展示；输入权只覆盖展示和布局 | 网络加载与快照 |
| 弹窗、close | 创建与关闭生命周期独立处理；展示弹窗、切换替补前台经过宿主调度 | 归属登记、观察 |
| screenshot | 普通读路径；临时改变视图可见性与合成层级时申请同一个窗口资源 | 编码与输出 |
| snapshot / find / console / network / locate(scroll=false) | 不申请输入权 | 按既有同标签队列执行 |
| navigate / wait | 不因页面加载或等待占住输入权；涉及的前台变更仍走宿主入口 | 后台加载、等待与观察 |
| execute | 不通过代码文本推断前台需求，保持同标签队列和现有权限检查 | 超时仍可能继续执行，沿用未知结果语义 |

fill 首版统一纳入，避免 setter 路径与 contenteditable 原生输入路径形成调度漏洞。后续缩小范围必须有实际输入效果证据。

scroll 的稳定等待有界，必须先核对现有 wheel 等待与整体预算，确定共同截止时间；持续动画或无回包不能无限占住窗口。到期如实返回未确认状态。截图只在改变共享视图状态时占资源，输入权内的动作不得再嵌套申请截图资源。

execute 可以通过 JS 修改 DOM、聚焦或滚动，不承诺任意页面脚本与其他标签输入完全隔离。真实输入使用 click / fill / press；若未来需要 execute 的前台能力，单独设计显式能力契约，不把全部 execute 串入窗口队列或自动改写代码。

## 4. 宿主协议与输入权状态

宿主为唯一窗口调度器。transport / bridge 增加内部申请、释放与取消协议；模型参数不增加锁、owner 或凭证字段。

申请包含 requestId、targetId、窗口身份、剩余预算和内部控制代次。成功返回不可复用的 ticket，绑定宿主启动代次、窗口、目标标签及本次操作。它是内部调度凭证，不替代 BrowserRuntime 的调用方与租约校验。

状态：queued → preparing → dispatching → finishing → released；取消前置阶段可直接转为 cancelled；接管、窗口销毁或代次变化转为 revoked；底层执行无法确认终止时转为 blocked。

宿主必须在最终输入投递边界验证 ticket、目标、控制代次、可见性及当前前台。操作中产生的 Runtime / DOM 准备命令通过同一上下文关联；其他任务的普通读命令可以继续。所有可影响活动视图的宿主入口都遵守该上下文，包括窗口布局与截图临时可见性。

queued 取消在候补移除并确认没有迟到授权后结束。preparing 取消须同时确认无业务输入、且激活 / 布局 / 截图恢复等共享窗口写入已经完成或在宿主最终写入边界被代次栅栏拒绝；只确认未发 Input 命令不足以释放。异步准备与 finally 恢复路径均须携带 ticket 或窗口代次，旧操作不得在下一动作测量之后改变前台、视图或布局。dispatching 阶段不放行新的冲突操作，直到确认底层派发结束并执行必要收尾。任意 release / cancel 均幂等，迟到消息与旧 ticket 明确拒绝。

blocked 状态下保留诊断和读取能力，暂停新的前台动作。恢复必须证明所有旧输入调用已实际 settle 且收尾完成，或确认承载旧输入的 WebContents / 窗口端点已销毁，旧输入不可能再落地；随后作废旧 ticket。仅重连、重新 attach debugger 或更换 ticket 代次不足以解除阻塞。定时器到期不直接交出输入权。具体恢复命令在实现时按真实协议能力确定，不自动杀进程。

取消协议须贯穿 provider、transport、bridge 与宿主。目前 bridge.command / activate 未接收 AbortSignal，父进程 request 超时移除 pending 不会撤销宿主操作。新增协议必须保留 requestId 的终态查询与取消确认；本地 promise 拒绝不能作为底层已终止的证据。若旧请求尚未确认结束，窗口与该标签仍保留执行占用，后续冲突调用等待或明确返回阻塞，租约也不得提前记为无在途操作。

## 5. 一次动作的执行顺序

以 click 为例：

1. BrowserRuntime 校验参数、调用方与租约，记在途调用，进入标签队列。
2. 申请窗口输入权；等待期间不激活、不滚动、不测量。请求取消或截止时确认候补移除。
3. 获得 ticket 后重新检查取消信号、租约、人工控制、交还观察状态、文档纪元和 ref。检查失败则释放 ticket，按现有恢复规则处理。
4. 激活目标标签并确认窗口可操作、页面可见。最小化或隐藏时明确拒绝，不自动恢复窗口。
5. 重新解析当前节点、滚入视口、测量坐标并检查遮挡。任一步骤改变文档或 ref 时拒绝旧动作。
6. 宿主检查 ticket 与派发条件，按顺序派发按下与抬起，记录派发阶段及完成情况。
7. 确认输入与收尾完成后释放窗口输入权；窗口队列允许下一标签进入。
8. 原标签队列内继续导航 / wait_text / 快照 / 失败恢复观察，最后核销租约记账。

press 必须在激活之后聚焦，防止激活改变焦点。click 的测量与派发中间不允许其他 agent 改变前台。调度前重新准备不等于自动重试已派发动作。

## 6. 人工操作、弹窗与故障

### 人工操作

- 普通人工标签切换在短临界区结束后应用，只保存最后一次明确选择；取消、标签关闭后丢弃无效选择。切换不是人工接管，不改变 holder。
- 人工接管立即执行，撤销本次 ticket，阻止后续业务输入。等待同一标签的候补取得输入权前重新检查 holder；收尾确认后，如果当前前台仍为 human，其他标签的前台动作继续暂缓。人工交还，或人工主动切到 agent 持有的标签后，窗口队列重新检查并恢复；后台 human 标签不能由 agent 激活。
- 人工保留前台期间，候补沿用原截止时间，不无限挂起；到期回执明确“窗口前台由人工使用，动作未派发”。不能用自动切换替代人工交还。
- 收尾只释放已确认由本次动作按下的按键 / 鼠标按钮，属于宿主专用路径，不补发新的按下、快捷键或剩余业务动作。mouseReleased 本身可能完成点击，keyUp 也可能触发业务事件，因此收尾不代表零副作用，回执仍记录部分派发或结果未知。若无法证明收尾不会作用于人工控制页面，则保持 blocked 并报告状态未知。人工控制状态立即切换；仍有旧按下状态时，网页输入开放必须与安全收尾协调，无法安全开放时明确显示输入尚在收尾，避免人工事件与旧输入混合。
- 交还后沿用完整观察门禁，旧 ref 不因输入权重新获得而恢复。

### 弹窗与窗口生命周期

当前 open 在 provider.open 返回后才登记租约，弹窗采用页面准备 / 加载后通知与收编；实施时须拆出早期生命周期协议，不能直接沿用加载后登记来保证早期展示安全。

新协议顺序：宿主创建后台标签并发送 created（targetId、openerId、创建请求、宿主代次）→ BrowserRuntime 核对创建方或 opener 的有效租约，登记家族归属并返回登记确认 → 宿主标记可展示。调试器可连接与页面加载成功 / 失败分别通知。登记确认前标签不得展示为可操作的 agent 标签，也不得通过 ticket 绕过占用。opener 已失效、关闭或归属代次改变时停止自动收编与展示，返回明确状态；登记幂等且校验创建代次。

弹窗在输入派发中出现时只创建后台页面并保留待展示请求，不抢前台。输入权释放、归属登记确认且人工前台保护允许后，再安排展示；慢页面无需持有父标签输入权等到加载完成。open 取消若已产生标签，回执保留创建事实与归属，撤销自动展示；不自动关闭用户可能已接触的页面。

每次人工选择更新窗口选择代次。自动展示请求记录请求时的选择代次，展示前如已发生更新的人工选择则取消自动展示，保留后台标签；输入临界区内暂存的最新人工选择优先应用。这样迟到的 open / 弹窗展示不会覆盖用户的新选择。

主动关闭目标、宿主销毁或窗口布局变化须撤销相关 ticket，作废准备阶段的坐标。普通 resize 等无法延后的原生变化在最终派发门检查；有变化则在派发前拒绝，不能复用旧测量。输入已经开始则按部分派发处理。

### 截止时间与回执

排队、激活、准备、派发和附带观察共用原工具总截止时间。取得输入权不重置预算。导航 / wait_text 的子预算继续受剩余总预算限制。

| 情况 | 回执要求 |
|---|---|
| 正常争用 | 内部排队后执行，不作为可见性失败 |
| 排队超时或取消 | 明确等待输入权阶段、动作未派发；候补已移除才确认结束 |
| 激活后不可见、最小化 | 保留可见性错误与未派发事实 |
| ref / 文档变化 | 原错误与依法取得的新观察；本次动作不继续 |
| 人工接管 | 保留人工控制错误及实际派发阶段 |
| 部分派发、断连、超时 | 已派发或状态未知；不重跑，不保证页面无副作用 |
| 输入完成，结果等待失败 | 区分输入已派发和业务效果未确认 |

实现时定义结构化阶段与错误码，并通过现有统一错误呈现路径输出。内部保留排队耗时、输入权耗时和撤销原因用于诊断；成功回执默认不堆积调度细节。

## 7. 实施顺序与完成条件

1. **盘点入口**：枚举激活、open、弹窗、close、标签条、layout、截图与控制权入口。完成条件：每个影响前台 / 可见性 / 输入的入口都有调度或撤销策略；核对外部 Chrome 的能力边界。**已完成**（2026-10-12：16 个宿主入口逐一给出策略；外部 Chrome 明确不宣称窗口级隔离）。
2. **宿主调度与协议**：实现窗口队列、ticket、取消、代次与故障阻塞。完成条件：只有宿主持有权威状态，取消候补、迟到消息与断连不能产生重叠有效 ticket。**已完成并经实测修复**（`src/browser-electron/window-input-queue.cjs`，协议与本轮实测见验收记录）。
3. **provider 动作接线**：统一输入准备，调整 press 聚焦顺序，缩小到输入阶段持权。完成条件：表中所有操作有明确处理，导航 / 文本等待不占窗口资源。**已完成并经实测修复**（click/press/fill/scroll/locate(scroll)/activate/open 展示段包临界区，open 建标签返回即放权；press 聚焦、节点解析均在得票和激活之后）。
4. **人工与生命周期接线**：接管、收尾、弹窗、关闭、布局和截图进入相同契约。完成条件：最终投递门能拒绝失效 ticket，旧测量不能跨视图变化派发。**已完成**（control bumpControlEpoch→revokeAll、shell closed/dispose bumpWindowEpoch、open 拆分准备/展示+选择代次栅栏、cdp Input./bringToFront 验票）。
5. **验证与记录**：按下节覆盖调度契约与打包态真实效果。完成条件：原始回执和页面效果一致，未完成边界写入验收记录，才将本文状态改为已实现 / 已验收。**本轮实测修复完成，矩阵仍有未覆盖组合**：13 组受控真实 Electron 场景、安装后真实对话和原生接管证据分层记录；类型检查、单测、Chrome live 与真实宿主增量更新已验证。最终构建、精确数字、原始回执与未覆盖项统一见 [验收记录](验收记录.md)，不把全部矩阵或正式发布标为通过。

外部 Chrome 的窗口身份、人工切换和派发边界未由 Electron 宿主控制，首版不宣称提供相同隔离保证。实现前必须明确该 provider 的回退行为和可观测能力，不能用 provider 本地队列冒充共享窗口保护。

## 8. 验收矩阵

修改测试、运行自检与打包态验收前按 [验证与发版规则](agent-rules/验证与发版.md) 执行；真实对话通过 [打包态对话驱动](打包态对话驱动.md) 保留 exec.agent.id。下表是必须检验的合同，2026-10-13 已补多行运行证据；最终构建中已执行与未执行的边界以 [验收记录](验收记录.md) 为准，受控宿主场景与真实模型对话分别标明，不能互相替代。

| 场景 | 必须取得的证据 |
|---|---|
| 两对话、不同 tab 同时 click / press / fill | 各页面事件记录与唯一提交各一次，无串页；同窗口输入临界区无重叠（2026-10-13 打包态已验通过，证据见 [验收记录](验收记录.md)） |
| A 点击后等待慢响应，B 点击 | B 在 A 的结果等待结束前完成输入；A 的观察仍归 A |
| 测量期间 B 请求 activate / open / 弹窗展示 | A 的测量到派发前台不变；B 有序展示，归属正确 |
| 慢加载或加载失败的弹窗、创建后取消 | 早期归属确认先于展示；加载不占父标签输入权；取消保留已创建事实，无无主 agent 展示 |
| created 到登记确认之间 opener 关闭或租约代次变化 | 停止自动收编与展示，旧确认幂等拒绝，不继承失效 owner |
| 人工选择与弹窗自动展示竞争 | 最新人工选择保留，旧代次自动展示取消，弹窗保留为后台标签 |
| 候补取消、排队超时、迟到授权 | 页面零输入，候补撤销确认，后续候补仍按序且无双 ticket |
| 准备期间取消，激活或截图恢复迟到 | A 的共享窗口写入已排空或被代次拒绝后 B 才获权；B 的测量与前台不受 A 的迟到操作影响 |
| 已按下后接管、取消、断连 | 输入阶段与收尾记录真实；未确认终止时窗口 blocked，无自动重复输入 |
| 输入超时后只重连通道、旧派发迟到 | 重连不解除 blocked；只有旧执行 settle 并安全收尾或旧端点销毁证据才能恢复 |
| 排队期间导航、交还、ref 失效 | 重新检查生效，旧 ref 拒绝；恢复观察不借机执行旧动作 |
| 后台截图与点击并发 | 截图可完成，临时可见性不打断输入准备，活动标签恢复按最新选择 |
| 人工持有前台，agent 请求另一标签输入 | 不自动切走人工页；后台读取继续，交还或人工切换后队列恢复，超时明确未派发 |
| resize、关闭目标、最小化、窗口销毁 | 旧 ticket / 坐标无效；未派发或部分派发如实返回 |
| 持续滚动、wheel 无回包 | 有界释放或故障阻塞符合实际底层状态，不无限占住窗口 |
| 不同窗口、多个连接同窗口 | 不同窗口可并行；同窗口只有一个宿主输入权 |
| 外部 Chrome | 回退行为明确，未支持的保护不宣称通过 |
