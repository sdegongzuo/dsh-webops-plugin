# 并行开发

本机同时推进多个开发任务时使用。单任务按 [开发指南](开发指南.md) 执行即可；本文件只回答「怎么让多个任务不互相踩」。

结论先行：**每个任务一条分支，并且同时给每个任务一个独立 worktree、一份独立 `.env.local`、一套独立产物目录。** 只切分支不够 —— 同一个工作目录里的 `lib`、`dist`、`node_modules`、构建产物和固定测试实例会被下一个任务直接覆盖。

## 1. 并行冲突从哪来

| 对象 | 现状 | 并行后的后果 |
|---|---|---|
| 仓库工作目录 | 一个目录只有一个检出状态 | `git switch` 会把另一任务未提交的改动一并换走，构建产物也跟着变 |
| `lib/`、`dist/`、`.metrics/` | 被忽略，跟着工作目录走 | A 的构建覆盖 B 的产物；`dev:desktop` 必须显式传 `--lib-dir`，指错就是验的别人那份 |
| `.env.local` | 被忽略，不在版本库 | 新 worktree 里没有它，脚本直接 exit=1。更隐蔽的一种：`buildRoot()` 缺 `DSH_DESKTOP_BUILD_ROOT` 时会**回落到本 worktree 根**，单测证据就攒进仓库里 —— `dsh-webops-pd` 的 `package-test-evidence/` 140 MB 就是这么来的（证据目录建于 10-16 00:37–00:57，那份 `.env.local` 到 00:59:54 才补上） |
| `node_modules/` | 每份检出各装一份（本机实测 87 MB） | 共用安装会让 `link:` 依赖指到别的源码树 |
| 固定测试实例 `DSH_PORTABLE_TEST_DIR` | 全机一份 | 两个任务同时安装/启动就是互相覆盖插件与 home |
| 固定端口 9229 / 9222 / 9230、19387 | 写死在脚本里 | 第二个实例起不来，或验到的其实是别人的进程 |

## 2. 前置

- **worktree 位置**：放 `D:/dev/cli/<任务名>`，与 `deepseek-harness` 同父目录、同层级。`package.json` 的 devDependencies 是 13 条 `link:../deepseek-harness/…`，按包根相对解析；换一层目录就装不上。
- **依赖安装**：每个 worktree 各自 `pnpm install`。pnpm store 在 `D:/Dev/pnpm/store/v11` 共用，不会重复下载。
- **本机配置**：复制主工作目录的 `.env.local`（模板 `.env.local.example`）。这不是可选步骤 —— `D:/dev/cli/dsh-webops-pd-integration-20261016` 缺这份文件时，`node scripts/portable-dev.mjs env` 报 `local-env: 缺 DSH_PORTABLE_TEST_DIR` 并 exit=1。
- **产物目录**：每个任务一套独占目录，例如 `D:/dsh-build/wt-<任务名>/`。构建根可以共用（复用 `.desktop-base` 缓存），但 `--out`、`--lib-dir`、`--stage-root`、`--scratch-root` 必须落在自己的目录、且指向尚不存在的路径。

## 3. 开工

在 Windows PowerShell 执行，把 `<任务名>` 换成短横线小写词。每步成功后再继续。

1. 先取最新远端基线，再从 `origin/main` 开分支和新 worktree：

   ~~~powershell
   rtk git -C D:/dev/cli/dsh-webops-plugin fetch origin
   rtk git -C D:/dev/cli/dsh-webops-plugin worktree add -b "feat/<任务名>" "D:/dev/cli/<任务名>" origin/main
   ~~~

   通过条件：新目录存在、`git -C "D:/dev/cli/<任务名>" status` 干净且分支名正确。`origin/main` 必须已 fetch 到本地，否则报 `fatal: invalid reference: origin/main`（exit=128）。

2. 进入新 worktree 补齐本机配置和依赖：

   ~~~powershell
   Copy-Item D:/dev/cli/dsh-webops-plugin/.env.local "D:/dev/cli/<任务名>/.env.local"
   cd "D:/dev/cli/<任务名>"
   pnpm install
   rtk node scripts/portable-dev.mjs env
   ~~~

   后两条必须在新 worktree 根目录执行。通过条件：`portable-dev.mjs env` 逐项打出本机路径和来源标记（`文件` / `环境` / `未设`），不报缺键。来源标成 `未设` 说明那份 `.env.local` 没拷对。

3. 建独占产物目录并做保留式构建（仍在 worktree 根目录）：

   ~~~powershell
   rtk pnpm exec tsdown --no-clean --out-dir "D:/dsh-build/wt-<任务名>/lib"
   rtk node scripts/copy-assets.mjs --out-dir "D:/dsh-build/wt-<任务名>/lib"
   ~~~

   通过条件：两步均 exit=0，`lib` 内 `index.js`、`client.js` 与 `browser-electron` 的 Electron 资产齐全（`scripts/package-portable.mjs` 的完整性前置会逐项检查这些文件）。不要用默认 `pnpm build`，它先删 `lib`。

4. 类型检查与单测，同样在 worktree 根目录执行，`TEMP`、`TMP`、`TMPDIR` 指向 D 盘已明确的目录：

   ~~~powershell
   rtk node node_modules/typescript/bin/tsc --noEmit
   rtk node node_modules/vitest/vitest.mjs run
   ~~~

   通过条件：类型检查零错误；测试通过项与跳过项分别记录，跳过原因写清。

5. 需要桌面联调或打包时，按 [本机打包与验收](本机打包与验收.md) 走，并把命令里的路径全部换成本任务目录。这类步骤受 §4 的串行约束。

## 4. 并行边界

| 可以并行（各任务同时跑） | 必须串行（同一时刻只允许一个任务） |
|---|---|
| 编辑各自 worktree 的源码与文档 | `dev:desktop` 开发态桌面联调 |
| `tsc --noEmit`、`vitest run` | 固定测试实例 `portable-test` 上的安装、启动与 GUI 验收 |
| 各自独占 `--out` / `--stage-root` 路径的插件打包（`package:portable`） | 固定 19387 端口的宿主自检 |
| 指向不同端点的 Chrome live 测试（`DSH_CDP_ENDPOINT`） | `package:desktop`：`--stage` 可分开，但 `.desktop-base` 本体缓存是共用写入点 |
| 读 `.desktop-base` 里已就位的本体缓存 | 改 `DSH_HARNESS` 那份 `deepseek-harness`：升级本体、重编、补丁再生 |

串行的原因都在脚本里，不是约定：

- `scripts/dev-desktop.mjs`：调试端口写死成 `9229 / 9222 / 9230`；`DEVELOPMENT_ROOT` 取 `buildRoot()/development-webops`，home、temp、`electron-user-data` 都在这一份里共用。
- `scripts/package-desktop-portable.mjs`：`STAGE` 默认 `buildRoot()/.desktop-stage`，不传 `--stage` 时两个任务抢同一个目录；`installBaseCache` 还会在共用 `.desktop-base/<dsh 版本>/` 下清理 `.new` / `.retired`。
- `scripts/run-packaged-host.mjs`：`assertHostPortFree` 固定挡 19387。
- `.env.local` 里的 `DSH_PORTABLE_TEST_DIR` 全机同一个值（本机两份 `.env.local` 的 SHA256 完全相同），所以固定测试实例天然是独占资源。想让两个任务同时验 GUI，只能按 [本地多实例测试方案](本地多实例测试方案.md) 另建实例，不能共用这一个。

`check:desktop`、`shot:desktop` 可以用环境变量 `RENDERER_PORT` 指向别的端口，但前提是那台实例本来就监听在那个端口。

## 5. 提交与合并

- 每个任务只提交自己的文件。提交前按 [项目规则](../AGENTS.md) 先 `git pull --rebase --autostash`；push 被判 non-fast-forward 时先 `pull --rebase` 解决分叉再推。
- 本仓习惯保留合入记录：功能分支用 merge commit 回 `main`，标题写清合入了什么并附主干回归结论（历史例子 `b7f4ee6`、`04a5444`）。提交说明用中文，标题可用 `修复:`、`功能:`、`文档:`、`门禁:`、`打包:`、`测试:`、`升级:`、`CI:` 这类前缀，正文写验证结果与未完成项。
- **冲突热点**（`git log -200 --name-only` 统计的改动次数）：`docs/验收记录.md` 77、`docs/遗留问题.md` 45、`docs/打包与发版.md` 42、`.github/workflows/release.yml` 34、`package.json` 29、`.github/workflows/release-desktop.yml` 29、`src/package-portable.test.ts` 25、`src/bundle-patch.test.ts` 23、`docs/打包机制参考.md` 23、`docs/harness-desktop-build.patch` 21。这些文件同一时刻只归一个任务，版本号在合入后由收尾任务统一改。
- 合入后必须在合并结果上重跑 `tsc --noEmit` 与 `vitest run`。两边各自绿不等于合并后绿。

## 6. 收尾与清理

顺序是先证明没有要留的东西，再删登记。删除动作按 [项目规则](../AGENTS.md#文件删除) 只由你手动执行。

1. **确认已合入**：`git branch --no-merged main` 输出里没有目标分支。有输出就说明还有未合提交。
2. **清点未跟踪内容**：`git -C <worktree> status --porcelain -uall`。未跟踪目录多半是验收证据（几十到上百 MB），删除前自己确认是否还要留档。
3. **先分清「真改了」还是「git 只是报了」**。`git worktree remove` 会因为任何未跟踪或标为已修改的文件拒绝执行，所以删之前逐个确认。判断某个 `M` 是真改动：

   ~~~powershell
   git -C D:/dev/cli/<任务名> diff --quiet HEAD -- <path>
   git -C D:/dev/cli/<任务名> hash-object <path>
   git -C D:/dev/cli/<任务名> rev-parse HEAD:<path>
   ~~~

   第一条退出码 0 且后两条哈希相同 → 内容与 HEAD 完全一致，只是索引里的 stat 记旧了。**此时不要加 `--force`**；确认哈希相同后执行 `git -C D:/dev/cli/<任务名> add -- <path>` 刷新 stat，随后 `git status --porcelain -- <path>` 与 `git diff --cached --stat -- <path>` 都应为空（内容没差，暂存区什么都没进）。这套判断在 2026-11-28 用索引副本实测过：`git add` 退出码 0，两项检查均为空。

   本机 `dsh-webops-pd` 的 `src/browser-electron/host.cjs` 正是这种状态：磁盘 65497 字节，索引记 66814 字节，`hash-object` 与 `HEAD:<path>` 却同为 `d3e3a63…`。直接 `--force` 删 worktree 会连带丢掉一份内容其实没变、只是索引认为改过的文件。
4. **删除 worktree 登记**：

   ~~~powershell
   git worktree remove "D:/dev/cli/<任务名>"
   ~~~

   有未跟踪文件时它拒绝执行，原文是 `contains modified or untracked files, use --force to delete it`（exit=128）。这是预期行为，按第 2 步清点后再决定。
5. **删除已合并分支**：`git branch -d <分支名>`。用小写 `d`；未合入时 git 自己会拒绝（`error: the branch 'x' is not fully merged`，exit=1）。分支还被 worktree 占着时会报 `cannot delete branch … used by worktree at …`，所以必须先做第 4 步。
6. 最后 `git worktree list` 应只剩 `main`，`git branch --no-merged main` 为空。
