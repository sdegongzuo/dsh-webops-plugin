# 桌面本体升级

仅在升级 DSH、修改桌面补丁或重建基包时使用。只更新插件走 [日常发版](打包与发版.md)，复用已验收基包。

先读 [验证与发版规则](agent-rules/验证与发版.md)。本机使用 Windows PowerShell，在插件仓库根目录执行；上游命令在其 harness 目录执行。构建过程可能调用删除或补丁恢复分支，先核对整个调用链的文件行为，不直接运行清理路径。

## 输入与前置条件

| 输入或检查项 | 来源与要求 |
|---|---|
| 上游源码 | release-desktop.yml 的 HARNESS_REF，依赖和所需 workspace 构建产物齐全 |
| 桌面补丁 | docs/harness-desktop-build.patch，与上游基线一致 |
| 构建路径与镜像 | .env.local 和 scripts/local-env.mjs；路径放工作区外 D 盘 |
| 桌面政策 | apps/desktop/.env.windows 通过当前政策校验 |
| 文件锁防护 | electron-builder 原生 moveDirAtomic 或本仓重试补丁至少一项在位 |
| 桌面版本 | 实际 app 的 desktop-runtime.json 中 release.version；不按插件版本推断 |

补丁职责和升级时的启动契约见 [机制参考 §1](打包机制参考.md#1-四个前置缺一必挂)；政策与短路径要求见 [§2](打包机制参考.md#2-桌面政策与路径)。

## 1. 核对上游与补丁

保存本地改动，检查补丁是否已应用，避免重复 apply。在干净上游核对可应用性，并逐个核对 hunk 语义和上游新增启动要求。已由上游修复的内容需重新判断，自动合并成功不代表语义正确。

通过条件：上游 ref、补丁基线与构建输入一致，改动完整、未覆盖他人工作；补丁生成和检查方法见机制参考。

## 2. 构建并验收候选

本机重编入口为 pnpm harness:build。执行前核对 scripts/harness-build.mjs 及其上游子脚本；改 packages/* 后先 build:lib:host。镜像从本机配置读取，缓存复用须通过 [缓存完整性检查](打包机制参考.md#3-本体缓存)。

构建后按 mtime 查找 win-unpacked，核对完整性并固定候选 app 的路径、版本和哈希。按 [本机打包与验收](本机打包与验收.md) 完成自检和真实 GUI 验收，并额外验证：

| 项目 | 通过条件 |
|---|---|
| Office 转 PDF | DOCX、XLSX、PPTX 均通过；构建与解压路径保持简短 |
| 出货补丁 | 满足验证规则的生产 patch 要求；PTC 与 sandbox 均使用实际包内 Node |
| 数据目录 | 用户数据保留、实例隔离和默认工作区符合 [目录契约](打包机制参考.md#便携数据归属) |
| 实例名 | 两个便携实例（根目录名不同）同时运行，窗口标题与托盘提示各自带自己的目录名；普通安装保持原样 |

首次启动、模型回复、工具调用、窗口操作分别记录，不能用构建成功替代。证据写入 [验收记录](验收记录.md)，必需项未通过时停止发布。

## 3. 发布桌面基包

确认新 `desktop-v<DSH版本>` tag 和 Release 不存在，将 tag 指向已验收提交并推送，由 release-desktop.yml 构建发布。内置插件仍用本仓 package.json.version，不随桌面版本改写。

等待 Actions 完成，核对 Release 状态及确定附件 `dsh-webops-desktop-v<DSH版本>-win-x64-portable.zip` 的大小、SHA256 和实际运行时版本。记录本机候选与 CI 产物的身份关系及验收范围，不将候选结果直接当作上传文件的验证。

## 4. 更新插件发布基包

新基包验收后，一起更新 release.yml 的 BASE_DESKTOP_TAG、BASE_DESKTOP_ASSET、BASE_DESKTOP_SHA256，并核对本仓三个 DSH peer 声明与基包运行时版本精确匹配。当前值从配置读取，文档不重复维护版本号。

配置或 workflow 修改后按验证规则回归；通过后，后续插件发版复用该基包，回到 [日常发版](打包与发版.md)。

## 失败处理

补丁、构建、验收或 CI 任一步失败都停止后续发布，保留输入和证据。文件锁、网络、启动问题按 [本机排障](agent-rules/本机排障.md) 定位；已存在的 tag、Release 和附件按 [发版门禁](agent-rules/验证与发版.md#4-发版门禁) 处理。
