# 打包态对话驱动（用 CDP 模拟真人点 UI）

## 0. 一句话

在打包态给宿主里的**真实对话**发 prompt，靠的是 CDP 连渲染页 `dsh-app://app/`，在页面里执行 JS 模拟真人「点侧栏会话 → 注入 composer → 点发送」，再轮询页面正文取尾部。**不走宿主 19387 的接口。**

## 1. 为什么不走接口

占用与归属校验认的是 `exec.agent.id`：每个对话一个 `Agent.id`，它等于 `SessionId`（源码级前置见 `packages/core/agent-loop/src/tool-calls.ts:70-78`）。只有消息真的从**某个侧栏对话**发出，agent loop 才会带那个身份去调 `webpage_*`。

- 宿主 19387 没有已知的「以某会话身份发消息」的接口；
- 即便有，绕过 agent loop 就拿不到身份，也就验不出「哪个对话持有哪个标签」。

⇒ 两个对话必须是两个**独立的**侧栏会话，靠点 UI 切换。不能在一个会话里换身份，也不能绕开 loop 直接调工具。

## 2. 前置

- 实例必须**带 CDP 起**：`node scripts/portable-dev.mjs launch --cdp 9333`（走 WMI，命令行追加 `--remote-debugging-port=9333`）。
- 核对宿主与 CDP 监听端口、精确 exe 路径、命令行和数据目录，确认连接的是目标实例；不能仅凭端口号认定实例身份或所有便携包共享单例。正常退出优先，杀进程须按 AGENTS.md 核对精确目标与授权，不解析 tasklist 文本猜 PID。
- 被测页优先使用可控本地夹具；真实网站按 [用户故事](用户故事与实测场景.md) 验收，外网不可用时明确记录环境阻塞。
- 以下 `.probe-chat-fixture.mjs`、`.probe-chat-drive.mjs` 为历史本机探针，未入库，不保证新环境存在。使用前核对文件、端口和当前 UI 结构；不存在时按 §3 实现驱动，不能把示例当作公共脚本。

```bash
node .probe-chat-drive.mjs --read                          # 只读当前对话尾部
node .probe-chat-drive.mjs --conv "实测场景 A" --msg "…"    # 切会话 + 发消息 + 等稳定
node .probe-chat-drive.mjs --conv "实测场景 B" --msg "…" --tail 6000
```

## 3. 三个动作（都在 `Runtime.evaluate` 里执行）

**① 切会话** —— 侧栏会话行是 `div[role=treeitem]`，按文本匹配后直接 `.click()`：

```js
const row = [...document.querySelectorAll('div[role=treeitem]')]
  .find(r => (r.textContent ?? '').includes('实测场景 A'))
row.click()   // 之后等约 2 秒让会话加载完
```

**② 注入 prompt** —— composer 是 `div[contenteditable="true"]`。优先用 `execCommand` 走真实输入路径（React 才能接管）；仍为空时退化成赋值 + `InputEvent`：

```js
el.focus()
document.execCommand('insertText', false, text)
if ((el.textContent ?? '').trim() === '') {
  el.textContent = text
  el.dispatchEvent(new InputEvent('input', { bubbles: true, data: text }))
}
```

**③ 点发送** —— `button[aria-label="发送消息"]`；不存在或被禁用时退化成给 composer 派发 Enter：

```js
const b = document.querySelector('button[aria-label="发送消息"]')
if (b && !b.disabled) b.click()
else el.dispatchEvent(new KeyboardEvent('keydown', { key: 'Enter', code: 'Enter', bubbles: true }))
```

## 4. 回读：轮询页面正文

没有流式接口可用。每 2 秒取一次 `document.body.innerText.length`，直到它在 `--settle`（默认 8000ms）内不再变化，就认为这轮跑完了；然后取 `innerText` 的**尾部**（新消息总在末尾），默认 2500 字符，用 `--tail` 调大。

## 5. 四条踩坑（都会伪装成「工具坏了」）

1. **夹具要常驻**：用 Bash 工具的 `run_in_background` 启动。写成 `&` 后台会随那次 shell 退出被带走，症状是 `net::ERR_CONNECTION_REFUSED`（看着像网页工具坏了，其实是夹具没了）。
2. **本地地址也走代理**：宿主浏览器连 `127.0.0.1:9788` 会过系统代理 `127.0.0.1:7890`。代理没起时，**连本地夹具也会被拒**（同样报 `ERR_CONNECTION_REFUSED`）。
3. **长历史会把模型拖慢**：对话历史一长，模型响应到 40s+，驱动常在结果出来前就超时退出。⇒ **判据不是当次回执，而是「超时后重读一遍」**。
4. **主 exe 没被放行外联，页面请求与模型请求全不通**：本机安全软件会在 `DeepSeek Harness.exe` 首次外联时弹「联网控制 / 发现程序联网行为」（数字签名「未知」，网络操作「外联」），默认高亮是「阻止」；没点「允许」时，CDP 本地调试端口照旧能连、`/json/list` 也正常，但工具与模型请求一律失败 —— 看着像「网页工具坏了」。改包前先确认这条，判据见 [本机排障 §2](agent-rules/本机排障.md#2-构建与网络)。
5. **窗口不吃输入时，`insertText` 回执照样是空的 success**（2026-10-17 在多实例场景里测得）：另一个窗口在前台时本实例的 `document.visibilityState` 会是 `hidden`，此时真实鼠标点 composer + `Input.insertText` 都静默失效 —— composer 读出来是 `""`，而回执没有报错。**注入后必须从 composer 读回完整原文再点发送**，读不到就明确失败、不要继续。提前台不必用 OS 后门：再启动一次同一个 exe，单实例锁会把焦点交给已有窗口后自己退出（`scripts/local-multi-instance.mjs` 的 `ensureVisible`）。
6. **实例重启/首次进界面会停在「选择一个工作区」**，那时页面上根本没有 composer —— 直接按选择器找会报「找不到 composer」，看着像驱动坏了。先点侧栏那一行工作区再找输入框（`scripts/local-multi-instance.mjs` 里的 `ensureComposer` 就是这一步）。

## 6. 边界：CDP 够不到什么

`curl http://127.0.0.1:9333/json/list` 里**只有 `dsh-app://app/` 一个 target**。受控标签和标签条（tabbar）住在独立宿主进程 `host.cjs` 里，而 `--remote-debugging-port` 是加在**主 exe**（`DeepSeek Harness.exe`）上的。

⇒ §6.5 的「接管 / 交还」按钮**点不到**，那一项的打包态证据只能人工补（手动点一次「接管」，再用另一对话验写操作被拒 `BROWSER_HUMAN_HOLDING`）。别再试自动化。
