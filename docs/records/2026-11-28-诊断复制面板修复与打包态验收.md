### 2.1 报告文本生成：页面 / 目标 / 未知三态分离

`pageOfCall` 改返回 `CallPage { page, source: 'receipt' | 'target' | 'current', fromCurrent }`：

- 只有回执自报（`(at …)`、`(now at …)`、open/navigate/snapshot 首行）能叫「页面」——工具确实到过那里；
- 参数里的 `url` 只有过 `^https?:\/\/\S+$` 才算地址证据，标签写「目标地址」——失败的 open/navigate 并没有落地；`ftp:`、`/api/q` 这类形状不算证据；
- 一条证据都没有时 `fromCurrent` 为真，报告打一行「地址未知」，**不再拿面板当前页冒充本条地址**。

### 2.2 报告文本生成：防伪造与三个统计口径

- 新增 `inline()` + `MAX_INLINE = 300`：所有**单行事实值**折行、反引号替换、超长截断，防止参数里的换行凭空多出事实行（实测注入过 `- 错误码: BROWSER_INVALID_PARAMS`）或 `## ` 变成真的 Markdown 标题。代码块里的原文不动。
- `errorCodeOf` 只认第一行，且首行只允许出现一个方括号码：正文里的方括号与拼接文本不再被抓成错误码。
- 参数检查分三档：空串（未提供参数）/ 合法 JSON / 不合法；`JSON.parse('null')` 成功，`null` 算合法 JSON。
- 统计行三个占位 `{total}` / `{running}` / `{failed}`；环境为空串时不再渲出 `- 环境: ` 这样的空事实行。

### 2.3 剪贴板与按钮状态机

- 兜底路径改由 **`copy` 事件 + `document.hasFocus()` 双判**，`execCommand` 的返回值不再作为判据；`finally` 里用 `focus({ preventScroll: true })` + try/catch 把焦点还给复制前的元素。
- `writeText` 加 `CLIPBOARD_WRITE_TIMEOUT_MS = 1500` 超时，超时按「这条路失败」继续走兜底。
- `CopyButton`：`text()` 与 `copyText` 分开 try/catch + `.catch`；`seq` 单调序号 + `mounted` 存活守卫（防连点竞态、防卸载后 setState，含 StrictMode 复挂复位）；文档失焦时把 success 降级为 failed；新增 `role="status" aria-live="polite"` 视觉隐藏播报区（复用已有 props）；复制中用 `aria-busy` 而不是 `disabled`。

### 2.4 `execute-script.ts` 的模型文案

- 非有限数文案给出兜底值，并点明 `Number("")` 是 0：原文案「用 `Number()` 再 check `isFinite`」会把 `""` 放行成 0。
- 截断改成「先吃路径、后吃文案」：长路径下 `?? null` 这类修法不再被裁掉。
- 稀疏槽位与访问器各给可执行修法，不再合并成一句。

### 2.5 工具侧回执与 Recovery

- `script_error` 归因从「这是页面的错误」改成「这是页面里那段代码的错误，通常是它自身的 bug」，保留 `"-"` / `typeof` / `Number.isFinite` 半句。
- `has_value: false` 的回执不再说「Use return」：模型写 `return d.missing` 时已经用过 return。
- `BROWSER_EXECUTE_RESULT_UNSERIALIZABLE` 的 Recovery 改成按 message 分派，不再无条件追加 DOM/函数/循环/访问器清单，也不再假定「message 里有字段名」（provider 路径的 4 类错误没有字段名）。

### 5.4 B6 反向验证：把 `hasFocus` 打成 false

在页面里用 `Document.prototype.hasFocus = () => false` 模拟文档失焦（原函数存在 `window.__origHasFocus`，验完还原）：

点击 → 按钮文字变**「复制失败」**、`data-dsh-browser-copy="failed"`、面板内 live region 播报「复制失败」。还原后重读，状态与播报都恢复。

**必须如实记下的偏差**：这个模拟只改 `hasFocus` 的返回值，改不了真实的窗口焦点状态。实测结果是 ——

| 场景 | `execCommand('copy')` 返回 | 收到 `copy` 事件 | 剪贴板 |
|---|---|---|---|
| 真实鼠标手势 + `hasFocus` 桩 false | `true` | 是 | **确实被写入**（哨兵值被 664 字符覆盖） |
| 无用户手势（`Runtime.evaluate` 里直接跑）+ `hasFocus` 桩 false | `false` | 否 | 未变 |
| 真实鼠标手势 + 真实焦点 | `true` | 是 | 写入 |

也就是说，`CopyButton.tsx` 注释里那条「Electron 44 失焦时 `execCommand` 返回 true 但剪贴板没写进去」的成因，**在本轮这种模拟里没有复现**（真窗口一直是聚焦的，模拟只骗过了 `hasFocus`）。新实现的行为是：只要 `hasFocus()` 明确为 `false` 就报失败 —— 宁可**误报失败**，也不误报成功。这条判据的方向是对的，但「真实切走窗口」的场景仍未验。

> **与本轮任务清单的一处偏差，按实测更正**：清单里写「旧实现在这个场景会显示「已复制」而剪贴板其实没写入」。本轮在 0.2.31 的产物上实测，真实鼠标手势下剪贴板**确实被写入了**（哨兵值被覆盖），所以这个模拟并没有复现出「假成功」。能站得住的结论只有一条：**改了 `hasFocus` 之后新实现如实报了失败**，这证明了降级判据接在 `hasFocus` 上；它不能证明旧实现会假成功。旧论断要成立得真实切走窗口，那一步本轮没做。

| `return { eps: window.__nope__.BASIC_EPS }` | `[BROWSER_EXECUTE_SCRIPT_ERROR] … threw a JavaScript runtime error: TypeError: Cannot read properties of undefined (reading 'BASIC_EPS')` ＋ `The error came from the code that just ran inside the page (the function body you passed in), so it is usually a bug in that code itself - an undefined name, a wrong type, or a property read on null or undefined - not a plugin failure.` ＋ `Recovery: fix the reported JavaScript syntax or runtime error; the function body is not automatically retried.` |

三条与旧版对照得到的结论（本轮实测）：

1. **`BROWSER_EXECUTE_RESULT_UNSERIALIZABLE` 的 Recovery 不再追加无关成因清单**：三条序列化失败的回执尾部都是同一句 `the message shows which case this is: when it names a $ field path, … when it reports a DOM node, a function, an empty object or an unawaited Promise …, return a primitive or a JSON string of the fields you need instead.`，`live DOM nodes, functions, cycles or accessors` 那条旧清单没有出现（这条上轮只在 Node 里验过）。
2. **`script_error` 的归因已经是「那段代码自身的 bug」**，不再是旧句 `This is the page's own error, not a tool failure.`。
3. **`has_value:false` 的回执不再说「Use return when you need data」**；`const x = 1;` 这种确实没写 return 的情况，回执给的是「没写 return **或** return 的表达式算成 undefined」两种来源＋两种修法。

#### 5.5.4 剪贴板失焦判据：能验到哪、验不到哪

先补一条**新测到的环境事实**：只要 CDP 调试器连着这个渲染页，`document.hasFocus()` 就一直是 `true` —— 把窗口最小化后 `document.visibilityState` 会变成 `hidden`，但 `hasFocus()` 仍是 `true`；把另一个窗口（日常实例 32636）调到前台后短暂读到过 `false`，但下一次 `Runtime.evaluate` 又重新变回 `true`。所以**「真实切走窗口」这个场景在 CDP 连着的时候做不出来**，这不是本轮实现的问题，是观测手段的边界。

在这个前提下实测到的：

| 场景 | 按钮 | `data-dsh-browser-copy` | live region | 真实剪贴板 |
|---|---|---|---|---|
| 正常（窗口可见、有焦点） | 已复制 | `copied` | 已复制 | 写入 6890 字符 |
| 窗口最小化（`vis=hidden`，`hasFocus` 仍 true） | 已复制 | `copied` | 已复制 | 写入 6890 字符 |
| `Document.prototype.hasFocus` 打成 `false` | **复制失败** | `failed` | 复制失败 | **仍然写入了** 6890 字符 |

⇒ 能站住的结论有两条：(a) 降级判据确实接在 `hasFocus()` 上，判成失焦就如实报失败；(b) 代价是**误报失败**——上面第三行里剪贴板其实写进去了，按钮仍报失败。这是有意的取舍（宁可误报失败也不误报成功），本轮实测把它量化了。

`aria-busy` 与 live region 仍只验到 DOM 文本变化，屏幕阅读器是否播报未验（§6.3）。

#### 5.5.5 验收时踩到的两个方法论坑（给后来人）

1. **面板收起时复制按钮的 `getBoundingClientRect()` 全是 0**，按坐标发鼠标事件会点到别的元素（本轮第一次就点到了 `<summary>` 与面板标题栏，剪贴板一直是哨兵值）。可靠做法是：先 `scrollIntoView({block:'center'})`，再用 `document.elementFromPoint(x, y)` **确认命中的就是那个按钮**，才发 `mousePressed/mouseReleased`。`D:\Temp\copy-click.mjs` / `copy-click2.mjs` / `copy-click3.mjs` 就是按这个顺序写的（未入库）。
2. **第一个 `[data-dsh-browser-copy]` 不一定是某条记录的按钮**：面板头部的「复制失败详情」排在所有记录之前，两套下标容易错位。按「记录状态 + 工具名」定位比按下标稳（`copy-click3.mjs --state success --record webpage_open`）。
