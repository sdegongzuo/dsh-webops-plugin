## 2. 设计：区域接口与策略（先定契约再实现）

### 2.1 统一的区域策略

`webpage_snapshot` / `webpage_wait` / click·press 附观察共用同一组区域参数，最多一个：

| 策略 | 参数 | 语义 | 可继承 |
|---|---|---|---|
| 显式结果区 | `region_ref`（旧名 `observe_ref`） | 已观察的标题 anchor 或容器 ref 的子树/章节 | 是（按锚点，锚点消失回退全页） |
| 文档尾部 | `region_tail=true`（新增，仅 `webpage_wait` / `webpage_snapshot`） | 按**文档顺序**取大纲最后 N 行（默认 200，`max_lines` 可调 1–800），与滚动位置无关 | 是（每次按当前文档尾部**重新求值**） |
| 当前视口 | `region_viewport=true`（仅 `webpage_snapshot`） | 按当前视口几何重新裁剪 | 是（provider 内部状态可按 `previous` 重算；工具层不向 wait/动作新增参数，避免 schema 预算超标） |
| 几何矩形 | `region_box`（仅 `webpage_snapshot`） | 文档 CSS 像素矩形 | 是（重算） |
| 动作区块 | `region.enclosing`（内部） | 被操作元素所在区块，动作后默认落点 | **否** |

**模型可见参数与内部能力的边界**：provider 的 `BrowserObserveRegion` 支持 `tail` / `viewport` / `box` / `ref` 四种可继承策略，四种都在 `lastObservationRegion.kind` 里有状态并可被 `previous` 重算；但工具层只把 `region_tail` 暴露给 `wait` 与 `snapshot`（连续对话的自然路径），`viewport` / `box` 沿用 `snapshot` 的既有参数。click/press 仍只有 `region_ref` / `observe_ref`，原因是 16 个工具 schema 有 14,000 / 基础组 9,000 / 合计 20,000 字符的硬预算，新增参数会把守卫打红。因此「press → wait(region_tail=true)」是本轮设计的自然两步路径，而不是给 press 硬塞一个尾部参数。

关键判据：**输入框所在区块不等于回复区域**。`region.enclosing` 是「动作的有效范围」，不是「本轮结果区」，因此不写入可继承状态；模型若确实要把回复读在输入框区块，必须显式传 `region_ref` 指向那个 ref。`scope_reason=previous_region_is_action_block` 明确报告「前次观察是动作区块，不作回复区继承」，不再把它伪装成 `no_previous_region`。

### 2.2 wait 的默认路径

```
显式区域 > 继承最近一次可继承区域（ref/tail/viewport/box，同 ref 纪元 + 同控制代次）
        > 默认文档尾部有界区域（scope=tail, scope_reason=default_reply_tail）
        > 全页（仅强制兜底条件）
```

**强制全页兜底**（保持既有正确性）：首次尚无完整观察、真导航（`navigated` / `page_changed.navigated`）、人工交还（`needsReobserve`）、新浮层（`guardGlobal` 命中 `global_overlay`）、继承区域过期（`previous_region_expired`）、锚点不可用（`anchor_unavailable`）、区域为空（`empty_region` / `tail_empty`）。

### 2.3 滚动后的语义与失效恢复

- `tail`：**不依赖几何**。按 AX 文档顺序取末尾行；滚动不改变读取范围；新回复追加到文档末尾时自动进入本次读取。回执报告 `scope=tail`、`tail_lines`、`tail_omitted_lines`（省略的头部行数，与「全页截断」的 `dropped_elements` 是不同口径）与 `scroll_top`（仅信息）。
- `viewport`：**每次重新裁剪当前视口**。滚动后读到的是新视口内容，不是上次视口的 DOM 节点；`scope_reason=inherited_viewport_recomputed`，回执明确「不保证包含本轮回复尾部」。
- `ref`：按锚点解析；锚点消失或区块无内容回退全页。
- 所有可继承区域都绑定 `ref epoch` 与 `controlGeneration`；任一变化即失效并回退全页。区域观察仍走 `adopt()`（不换表、不推进纪元、不作废其他 ref），`outsideRegion` 按实际范围报告，`find` 缓存只写**实际取得的范围**；全页 `publish()` 清空继承状态。

### 2.4 完成证据（结构化，不靠提示文案）

`webpage_wait` 与 click/press 的 `wait_text` 回执新增 `completion` 对象：

| 字段 | 取值 | 说明 |
|---|---|---|
| `condition` | `time` / `text` / `ref` / `stable` | 本次等待条件 |
| `condition_met` | bool | 条件是否在期限内成立 |
| `completion` | `verified` / `unverified` | 本轮回复是否**已验证完成** |
| `basis` | `exclusive_text_marker` / `preexisting_marker` / `quiet_only` / `node_only` / `fixed_delay` / `timeout` / `baseline_unavailable` / `wait_failed` | 结论依据 |
| `new_content` | `observed` / `not_observed` / `unknown` | 等待期间页面正文是否增长（仅事实，不证明完成） |
| `outline_complete` | bool | 附观察大纲是否未截断 |
| `text_complete` | false | 大纲是预览，完整正文须 `webpage_find(full_text=true)` |
| `scope` / `truncated` | string / bool | 实际观察范围与截断 |

判定：`text` 命中且**等待开始前该文本不存在** → `verified`；`text` 在等待前已存在（旧轮完成标记）→ `unverified` + `preexisting_marker`；基线读不到 → `baseline_unavailable`；后续等待本身抛错 → `wait_failed`；`stable` / `time_ms` / `ref` / 超时一律 `unverified`，分别标 `quiet_only` / `fixed_delay` / `node_only` / `timeout`。基线探测在等待**开始前**读取 `document.body.innerText.length` 与本轮标记是否已存在，受本次等待期限约束，失败保守报「读不到」；等待前后正文长度只写进 `new_content`，**不参与完成判定**。新节点、输入清空、页面安静都不单独证明完成；回执置于最前并写明「不得从截断大纲推断完整回答」，`outline_complete` 明确只针对所附范围、不代表整页。**不承诺通用检测所有网页 AI 的完成**。

### 2.5 有界读取与完整性分离

`tail` 只输出末尾 N 行，预览用于定位；`tail_omitted_lines` 与全页 `truncated`/`dropped_elements` 分别报告。`text_complete=false` 恒定（大纲是 120 字符裁切的预览），完整原文走既有 `find(full_text=true)` 同版本续读。含页面内容的回执保留完整不可信内容声明与引用安全契约；全页截断提示不变。

### 2.6 同批的非语义改动

- 非观察 fill/press/click/scroll 回执：URL 缩为 `origin+pathname`（标注 query 省略）、标题截短，保留动作结果、`navigated`/`page_changed`/`target`/`ref epoch`、宿主 `duration_ms` 与不可信内容边界；系统提示与含页面内容回执的安全声明**不移除**。
- `webpage_fill` 误传 `observe` 等字段：给出准确纠正路径（后续 `webpage_press` / `webpage_wait` 上设置观察），不再只列允许字段。
- `activate` 后仍 hidden：先核对恢复链，**能复现才修**；不凭猜测放宽可见性/输入门禁。

### 2.7 本轮不做

不实现增量快照、不调整全局 spill 阈值、不新增独立工具、不承诺通用网页 AI 完成检测。区域路径稳定且任务正确后，按 [观察优化方案 §5](../网页观察优化方案.md#5-第三阶段局部增量的启动条件) 取得至少三次同模型/同任务/同范围长会话样本，再决定是否满足增量门槛。

### 3.3 独立 review（已完成，逐项修复）

独立 reviewer（只读子任务）按 A–H 八项核对源码，结论为「可进入打包态验证」，提出 4 项「重要」问题，均已修复并复验：

1. `previous` 递归继承无条件把 `scopeReason` 覆写成 `inherited_ref`，会吞掉内层更重要的 `global_overlay` 兜底原因 → 改为仅当继承结果确实仍是 `ref:` 范围时才标 `inherited_ref`。
2. 动作区块（`enclosing`）观察会污染可继承状态，导致下一次 wait 把输入框区块当回复区 → `enclosing` 只写 `lastActionBlockObservation`，并作废此前按几何裁剪的 `viewport`/`box` 继承；无有效回复区时读 `tail` 并标 `previous_region_is_action_block`。
3. 尾部切片与 `find` 底稿的行对齐依赖对象引用，`normalizeDepths` 后两份数组元素已不同对象 → 引入 `lineId` 按标识对齐，并补「起点是折叠标记行」的反向用例。
4. `fill` 误传观察参数的纠正路径指向并不存在的 `press(region_tail)` → 改为「press 用 `region_ref`」+「`webpage_wait(..., region_tail=true)`」，与真实暴露的参数一致。

同时修正：`completion` 在观察失败/缺失时补 `wait_failed` 而非沉默；`tail_source_truncated` 单列原因（源大纲仍被深度/字符预算截断时，真尾部可能不完整）；`TAIL BOUNDED READ` 文案明确「主动省略 ≠ 全页截断」并与 `truncated/dropped_elements` 分开计数。
