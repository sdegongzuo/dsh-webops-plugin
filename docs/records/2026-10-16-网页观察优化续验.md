- 峰值回升只在动作密集场景出现，直接原因是“每次动作后默认全页观察”（候选 4 次全页）。下一步应先让动作后观察默认落在**被操作元素所在区域**、只有区域不可用时才回退全页，再按本协议重跑；改动前不宣称已解决。
- 长文场景另有一条未闭合：outline 抹掉 `<pre>` 的空行与缩进，原文只能二次读取，模型在 `find` 与 `execute` 之间摇摆（2/5 走 execute）。要压这类补读，需让 outline 对代码块保留原始空白或给出“需 `full_text` 读取”的指针，本轮未改。
- 还有一条模型侧问题与工具无关但会拉低长文通过率：本轮 6 次长文任务里 2 次输出中断（S11 的 A-02 只有 reasoning、日常实例复验停在 522 字符），`stopReason` 都是 `stop`，reasoning 里内容已取到。长文门禁因此不能只按“任务是否通过”读，需与工具错误分开记。
- `webpage_tools` 的字段容忍只消除一类拒绝；本轮长文两条件零拒绝可作修复后的独立复验，但 find 补读、execute 补读等模型侧弯路依然存在。

## 2026-10-18（续）：动作后默认区块观察——实现与首轮对照

### 实现

`shouldSnapshot` 在 click/press 没显式 `region_ref` 时一律重拍全页，是上一轮 S15 峰值 +9.80% 的唯一来源（两条件的区域观察次数都是 1）。本轮把它改成默认落在被操作元素所在区块，三层：

1. `page-scripts.ts` 的 `ENCLOSING_BLOCK_FUNCTION`：从被点元素向上最多 40 跳找最近的块级容器（标签白名单 + role 白名单），到 `body/html` 之前拿不到就返回 `null`。
2. `page-observation.ts` 的 `region.enclosing`（第四种区域形态）：`refs.resolve` → `resolveBackendNodeId` → `Runtime.callFunctionOn` 取节点 → `DOM.describeNode` 拿 backendNodeId → `DOMSnapshot.captureSnapshot` 的 `parentIndex` 建 children 表，DFS 出子树 backendNodeId 集合 → 只保留子树内的 AX 节点。**每一步都包在 try/catch 里返回 undefined，从不抛**；锚点解析不出或子树为空就 `regional=false` 回退全页，回执 `scope` 仍走 `ref:` 前缀。
3. `browser/index.ts` 的 `mutate()`：显式 `region_ref`/`observe_ref` 最优先 → click/press 的 `ref` 作 `enclosing` → 都不行才全页；导航、交还、首次、`needsReobserve` 仍强制全页。系统提示与 `observe`/`region_ref` 描述同步改口（「默认只回被操作元素所在区块」），schema 成本守卫未抬预算。

### 证据

- 单测 5 条新增（provider 4 条：只回本块 / 解析不出回退全页 / AX 空回退全页 / `enclosing` 与 `ref` 互斥；`browser/index` 1 条四段式：首次全页 / 默认区块 / 显式区域优先 / wait 无默认）。
- 真机探针 `.probe-enclosing-block-20261018.mts`（无头 Chrome + S15 同源 `chat` 夹具）：容器 `section`（backend 125）；全页 3879 字符 / 28 行 → 区块 93 字符 / 3 行且不含相邻「背景章节1」；点「发送」后 249 字符、含「第1轮回复」「【第1轮完成】」；按钮从 DOM 摘掉后同一路径返回 `null`（生产代码据此回退全页）。
