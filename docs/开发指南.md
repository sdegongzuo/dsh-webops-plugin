## 1. 本机路径

本机值配置在 .env.local，模板为 .env.local.example；脚本统一通过 scripts/local-env.mjs 读取，环境变量优先。构建、暂存、Chrome 独立 profile 与测试证据放 D 盘、工作区外。

~~~powershell
rtk node scripts/portable-dev.mjs env
~~~

构建根使用 DSH_DESKTOP_BUILD_ROOT，固定测试目录使用 DSH_PORTABLE_TEST_DIR。先核对实际值与来源，再执行对应流程。

## 2. 类型检查与测试

~~~powershell
rtk node node_modules/typescript/bin/tsc --noEmit
rtk node node_modules/vitest/vitest.mjs run
~~~

测试前把 TEMP、TMP、TMPDIR 指向已明确的 D 盘目录，并核对测试调用链的文件行为；删除与清理规则见 AGENTS.md。

Chrome live 测试使用 DSH_CDP_ENDPOINT 指向真实 Chrome。先检查 /json/version 与标签创建能力；Electron 端点或不可用端点导致跳过时，报告原因与实际跳过数量。用例数量以当前测试文件为准。

端口按实际占用选择；不能仅凭 9222/9333 判断 Chrome 或 Electron。桌面 UI 驱动与 Chrome live 测试使用独立端点。

## 3. 构建与桌面联调

默认 build 使用 tsdown 清理旧产物。保留式构建与资产复制按 [打包与发版 §2](打包与发版.md#2-命令链) 执行，输出路径先确认；不直接执行默认清理链。

桌面运行读取构建产物。插件安装、更新、重启与身份核对使用 [打包与发版](打包与发版.md) 的固定目录流程。启动后跨工具调用核对 exe、PID、CDP 和安装哈希；窗口出现或进程 exit=0 都不能替代验收。

dev:desktop 在构建根下装配全新 runtime project，插件登记写到实际 `DSH_HOME/profiles/desktop`，保留历史目录、更新前 profile 副本与用户 home，不关闭删除保护。必须传 `--lib-dir <本轮构建目录>`；`--prepare-only` 只做装配，不启动第二个桌面实例。Electron 直接读取 `.env.local` 的 DSH_ELECTRON_BIN 或明确的本机路径，缺失时报错，不触发 npm 模块自动下载安装；临时目录固定在构建根。`--build` 已拒绝执行，先按打包文档完成保留式构建；回放仅在 `--fake-llm` 显式启用。示例：`rtk pnpm dev:desktop -- --lib-dir <本轮构建目录> --prepare-only`。check:desktop、window:desktop、shot:desktop 的参数与端点先读脚本；这些检查仅证明各自的观察范围。

本地 CLI profile 安装与桌面安装是两条路径。CLI 使用当前 harness 的 dsh plugin 帮助和配置约定；不照抄旧机器绝对路径或未验证的 git 安装方法。

## 4. 本机排障

按 [本机排障规则](agent-rules/本机排障.md) 查启动、端口、网络、asar 锁和工具输出异常。构建镜像、缓存与 primary-runtime 细节见 [打包机制参考](打包机制参考.md)。

GUI 启动需核对 ELECTRON_RUN_AS_NODE、NODE_OPTIONS；主 exe 跑 Node 脚本时按运行方式显式配置。按监听端口与精确 exe 路径定位进程，并核对命令行、父子关系；结束进程先确认目标与授权。

界面可见但真实鼠标点不动时，检查窗口层与焦点。DOM .click() 成功无法排除其他原生窗口遮挡；使用真实输入事件与页面效果验证。历史 dsh-app://shell/* 协议缺失已由上游修复，不再作为当前待打补丁。

## 5. 模型与验收边界

src/fake-llm/ 是开发专用脚本回放，必须保留出货隔离与启用门禁。当前开发启动链需先完成 §3 的保留改造，不能为跑回放关闭删除保护。回放、直接 provider 探针与绿单测不能替代真实模型验收。

真实对话按 [打包态对话驱动](打包态对话驱动.md) 从渲染页 composer 发送，保留原始工具回执与页面效果，验证 exec.agent.id 对应的实际对话归属。测试结论、未覆盖边界与发布状态集中写在 [验收记录](验收记录.md)。
