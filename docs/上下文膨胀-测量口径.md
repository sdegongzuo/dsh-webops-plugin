# 上下文膨胀测量口径

本文件是可复用的上下文测量口径，供 [快照与上下文](快照与上下文.md) 的测量与验收使用。§1–3 是长期生效的方法；§4 起是带日期的单次测量记录，只证明当时对象，不作为当前版本结果，详细过程从 [过程记录入口](records/README.md) 查找。

## 1. 取数

- 从 `.env.local` 取得 DSH_PORTABLE_TEST_DIR，按实际轨迹查找 session.v*.jsonl.zstd；当前验收使用 session.v4.jsonl.zstd，不把历史版本文件名当固定契约。使用宿主的 Zstd frame 扫描器解压完整帧，不硬编码本机目录。
- 解压后以 tool/call.data.callId 与 tool/result.data.message.toolCallId 配对；字段随版本核对原始事件，不能直接套旧格式。按该配对，统计模型实际收到的 text 回执。
- 工具 schema 守卫按 `JSON.stringify({name, description, parameters}).length` 逐工具求和；宿主 request/header 另行统计，不混比两者。
- 分别记录调用步数、全页/区域快照次数、回执字符数、请求输入 token、输出 token与缓存命中；缺失值注明未知。
- 费用按真实模型计费和缓存记录核算。字符数只用于同口径体积比较，不能直接转换成精确 token 或费用。

读取 assistant/message.data.usage：分别累计 inputTokens、cacheReadTokens、outputTokens。累计输入含缓存口径为 inputTokens + cacheReadTokens，并同时报告未缓存输入；不能把缓存读取与输入重复计算。跨多轮会话是否完成，以最后一条 turn/start 或 turn/end 为准。

单次请求输入含缓存为该次usage的inputTokens + cacheReadTokens；会话峰值取这些单次输入的最大值，末轮输入取最后一次。它们描述模型请求的输入上下文，不含该次输出；累计值是跨请求求和，不能拿累计输入冒充单轮窗口占用。需要的usage字段缺失时标未知，不默认为零。

本轮U2部分事件省略cacheReadTokens。先核对该provider已有usage的总量分项关系；仅在inputTokens、outputTokens、totalTokens均为非负整数且totalTokens恰等于inputTokens + outputTokens时，按总量对账还原缓存读取为0，并另记派生事件序号。其他缺失仍为未知；总量不一致的样本不能用于精确token对照。

模型轮数按assistant/message的turn、step组合去重；网页调用按callId配对另计，同一模型轮可以并行调用多个工具。回执与schema字符数统一采用JavaScript字符串的UTF-16 length，不当成字节数、Unicode码点数或token。

工具耗时使用对应 call/result 的事件 time 差值，模型前后的时间标记会混入推理与调用往返。保存副本前脱敏凭据、一次性移交码和敏感页面内容，证据放 D 盘。

## 2. 快照比较

同文档相邻快照按一致预算与折叠规则比较：先剥离 ref 编号，再求行多重集合交集与后一份行数之比。导航前后不混入同文档样本。

完整快照会重编号 ref，未剥离编号的行文本会低估重复率。测量用行文本；实现 diff 的主键仍为 backendNodeId。

区分回执全文与 outline；记录 truncated、折叠、预算变化，不能把截断差异当成页面变化。

## 3. 对照与验收

- 固定任务、页面状态、模型、版本和配置；使用独立新对话执行前后对照。
- 提示中的字面输入与操作方式分别写清。若要求内容原样保持，可写“每条消息一次完整填写并发送”，避免“逐字发送”被解释成逐字符操作；协议改变后旧样本保留单列，不混入新协议统计。
- GUI 验收错开其他会话的驱动时段，避免页面状态与窗口布局干扰。
- 不能固定站点内容时使用本地夹具量机制，再用真实页面验行为。
- 按请求累计输入统计实际成本，不只看新增回执总量。
- 记录模型是否遵守恢复指引；仅总体积下降不能证明工具行为改善。
- 历史两份单 turn 样本不能代表多轮长会话，旧的步数差异不作为受控改善结论。
- **模型侧未响应单列，不混进成本分布**（2026-10-18 起）：整次对话零工具调用、assistant 消息里只有 reasoning 块（无 text）、累计输入恰等于首轮输入、`turn/end reason=completed` 的样本，是没有执行任务的空转，把它放进分布会让口径变成「做任务 vs 没做任务」。这类样本原样留在目录、记进 `state.attempts` 与报告的 `attempts{total,nonResponse,accepted}`，重采样只允许用在这一种形状上（`OBSERVATION_COHORT_ATTEMPTS`，默认 1 即不重采样）。报告必须同时给出「用了几个对话才凑到 5 个可比样本」。
- **成本中位数只算「完成任务的样本」，等价于每成功任务成本**（2026-10-18 预注册，`OBSERVATION_COHORT_RESAMPLE_INVALID=1`）：除未响应外，任务没做完、越界调用非网页工具、`webpage_*` 工具错误、原生验收不成立，同样是**模型侧偏差**而不是构建差异，却会把中位数拉向「没做任务所以便宜」。规则：两条件同一判据、同一上限（每例最多 3 次尝试）、指数耗尽即停机，全部尝试原样保留并写进 `state.attempts` 与报告 `attempts{total,invalid,nonResponse,accepted}`。报告既有严格门禁（两条件 5/5）也有这条分布，两者一起看：通过率是**另一个指标**，不能拿高成本条件的高通过率去补它的成本劣势。预注册文本在 2026-10-18 第二次 S15 重跑之前写入本文件，先于任何结果。
- 对照构建必须是**同一棵树只差一个旋钮**：2026-10-18 首轮 S15 对照的 control 取自更早的构建，连 `webpage_tools` 的 `session_id` 容忍都没有，对照组 3 例各撞一次派发前拒绝 —— 两条件差的不止一个旋钮，门禁失败无法归因。回退式对照构建见 `.probe-control-revert-20261018.mjs`。

## 4. 2026-10-10 工具定义优化记录

保留 16 个网页工具，精简重复说明，为 network.action、wait.ref_state、wait.until 增加 enum，并把 snapshot.region_box 改为四个必填数值字段的对象。execute 示例与副作用约束保持原样；snapshot 的上限说明统一为实际参数范围 1–5000，默认 800。

优化前取便携版 v0.2.16 的实际请求 header，优化后取当前源码注册的工具定义。两侧均按完整工具数组的 JSON 字符数比较：16791 → 12641，减少 4150 字符。沿用上下文插件的估算口径 `ceil(字符数 / 4) + 4`，为 4202 → 3165 tokens，减少 1037（24.7%）。这不是模型 tokenizer 或账单的精确计数；优化后的数字尚未由安装态请求 header 复核。

逐工具对象求和的测试口径为 12624 字符，将预算守卫从 18000 收紧到 13000。公共系统提示未改动，注册文本仍为 7591 字符，未把节省的说明转移进去。

验证：类型检查、保留模式构建和 103 项工具契约测试通过。真实 Chrome 通过当前工具注册层执行 9 次有效调用，确认中文及 emoji 输入后的实际提交值、隐藏等待和区域快照；另 4 种非法参数均在 provider 派发前拒绝。全量测试为 766 通过、3 失败，失败均是便携 home 补丁的旧字符串断言，与本轮修改文件无关，不能宣称全量通过。

证据保存在 `D:/dsh-build/tool-schema-opt-1791590001/`：`schema-comparison.json`、前后 schema、`chrome-tool-receipts.json` 和独立构建目录 `lib/`。本轮未启动新的 DSH 实例，未安装或发布版本，也未完成真实模型的前后调用成功率对照；当前结论限于定义体积下降及上述工具层行为回归。

## 5. 2026-10-11 第二轮优化记录

继续保留 16 个工具，增加 navigate.history、tabs.action、tabs.scope 的 enum，精简导航说明并合并公共系统提示中的重复工具介绍与恢复流程。标签所有权、30 分钟空闲释放、旧 ref 恢复、人工接管、当前回复完成标记、遮挡、execute 超时副作用和不可信页面边界均保留。系统提示预算设为 6500 字符，与工具定义合计的预算设为 19000；先临时设 5000 验证断言确实失败，再恢复预算复验。

同口径工具数组 JSON 为 12405 字符，估算 3106 tokens；公共系统提示为 6269 字符，估算 1572 tokens。上轮分别为 3165 和 1902，合计 5067 → 4678，进一步减少 389 个估算 tokens（7.7%）。对最初 4202 + 1902 的基线，合计减少 1426（23.4%）。这里按两项分别 `ceil(字符数 / 4) + 4` 相加；不能作为实际计费数字。逐工具对象求和为 12388 字符，含系统提示合计 18657 字符。

类型检查、独立保留模式构建、105 项工具契约测试和真实 Chrome 的 9 次有效工具调用、4 次非法参数拒绝通过。全量首次运行时 Chrome 尚未启动，结果为 761 通过、3 个便携 home 旧断言失败、7 个 live 测试跳过；启动独立无界面 Chrome 后另行运行 live 与工具契约组，112 项全部通过且无跳过。测试 Chrome 已通过 Browser.close 关闭，未新增 DSH 实例，未安装或发布版本；模型调用成功率对照仍未完成。

本轮证据：`D:/dsh-build/tool-schema-opt-round2-20261011/` 下的 `schema-comparison.json`、`chrome-tool-receipts.json`、`test-results.json`、`browser-final-results.json` 与 `lib/`。Chrome 用户目录位于同一证据目录；本轮页面效果由直接工具调用验证，不等于打包态模型验收。

## 6. 2026-10-11 安装态真实模型回归与初始工具建议

复用 `p016-check-1791593975` 测试目录，备份旧插件 lib，安装本轮独立构建并重启原实例。已安装工具入口 SHA256 为 `e6e8d9ebbdfcde8ed947b16ed6ebcd7aa4ad36c1ae29ba3fd3e453b7fbbfa263`。真实对话经桌面 UI 发送，原始 request/header 的配置为 unisound/u2-flash；16 个网页定义与候选源码注册结果完全一致，实际数组为 12405 字符，估算 3106 tokens。不是旧产物或直调 provider 的验收。

7 个独立普通对话累计 67 次网页调用：中文/emoji 表单、三轮生成回复、重复标题章节原文、历史返回、遮挡恢复、滚动定位、console/network 与 execute 超时。页面记录确认精确提交一次、三轮分别完成、甲/乙与返回导航顺序、关闭浮层后点击、页尾点击时 scrollY=1925.5；调试返回偶数和 22 与 API 值 17，故意挂起按 timeout_ms=1000 在约 1009ms 返回超时，后续只读调用仍成功。无参数格式错误；遮挡与超时两次失败均属预期边界。

接管登录另跑两次同对话续操作。实际标签条 agent → human → agent，人工测试账号登录后导航到 /account，模型沿用同一 session_id 保存“交还后继续🙂”。首轮接管期间的点击探针被模型服务 content_filter 拦截，不能算门禁通过；交还后模型先误用旧 ref，收到 BROWSER_STALE_REF 后重拍并保存。第二轮普通填写请求实际返回 BROWSER_HUMAN_HOLDING，未修改账号；交还后先完整 snapshot，再 fill/click、核对结果并关闭标签，流程通过。补验脚本最初将两轮页面保存累计误判为重复提交，按最后一次登录分段复核原始记录后，本轮保存次数为 1；未重跑或隐藏原来的脚本失败。

仍有两处模型使用偏差：第一轮生成等待用了 stable；原文读取已通过 find(full_text=true) 取得完整文本后又重复执行页面脚本，其中一次代码选错同名章节，随后自行修正。最终任务完成不等于这些流程已经最省，也不能表述为零失败调用。

| 阶段 | 网页工具 | 同口径估算与约束 |
|---|---|---|
| 新会话且没有自有标签 | open、tabs | 两项约 278 tokens；7 个普通场景的首次调用均为 open。tabs 保留已有/空闲标签的查询和领取入口。 |

open/claim 成功后自动在下一次模型请求展开常用组，不增加一个“加载基本操作”的模型往返。接管不释放对话占用，也不收起常用组；交还后旧 ref 仍失效，首次写操作前需恢复观察。扩展加载按 agent 作用域隔离，系统提示随可见工具调整；不得让错误指引引用无法加载的工具。被测宿主 lib 已含 scoped tools.restrict，实施时需维护其 disposer，而不能叠加不可撤销的限制。

以上两项子集数字不含其他宿主工具、加载入口和系统提示。此次实测仍暴露全部 16 项，尚未验证隐藏工具后的模型行为；该清单是由实际调用与恢复需求形成的实施建议。
