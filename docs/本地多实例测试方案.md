# 本地多实例测试方案

用途：部分实现的混合方案，包含已实现调度器的操作约束、验收记录与后续设计。适用范围按下方 2026-10-17 状态和各阶段说明判断，不能把未验收的共享 app 与并行网页能力当作可用功能。

状态：2026-10-17 完成阶段 A 实跑与阶段 B 部分实跑。调度器已实现（`scripts/local-multi-instance.mjs` + `scripts/local-multi-instance-lib.mjs`，命令见 `pnpm mi:*`），单测 25 项全绿。实测数据、已完成判据与遗留阻塞见 [§6 实测记录](#6-实测记录2026-10-17-首轮)：身份与装配（阶段 A）已通过；双实例并行启动、端点归属、端口冲突、同目录重复启动聚焦、双实例真实对话与 cookie 隔离已通过。2026-10-18 两实例并行时都能取得 `webpage_*`，此前「同一时刻只能一个实例持有」未复现；但并行下的真实输入会互相打断，因此仍不宣称「实例间网页能力可并行」。以下再进行的多轮本地测试以本文档为准；正式发版命令仍以 [打包与发版](打包与发版.md) 为准。

## 1. 复用边界

采用“构建一次、固定产物、多个独立实例消费”的方式。同一轮源码只构建一次插件；桌面壳未变时复用已经核验的本体。每个实例保留自己的运行状态和证据。

首期交付范围：固定便携 app 与插件产物 → 复制装配 A/B → 独立数据目录 → 发现实际宿主端点 → 双实例真实对话验收。开发态依赖快照与直接共享 app 目录各设后续门禁，不计入首期完成条件。

| 对象 | 复用方式 | 约束 |
|---|---|---|
| 插件 lib、静态资产、插件包 | 同一份构建供多个实例复制安装 | 冻结后不得再构建写入；安装后比对逐文件哈希 |
| 桌面 app、primary runtime、出厂 profile 模板 | 复用固定来源，初期复制到每个实例 | 不为每个实例重编、压缩、再解压；模板不含用户凭据和会话 |
| 依赖下载缓存 | 构建阶段复用 | 运行实例的可写依赖状态仍独立 |
| home、profile、会话、设置 | 每实例独立物化 | 不共用可写 profile，不从正在运行的用户目录复制 |
| Electron、浏览器 Cookie 与站点数据 | 每实例独立 | 同一实例内各标签共用；实例间不得串登录态 |
| 工作区、DSH 临时文件、日志、采样、证据 | 每实例独立 | 夹具原件可共用，测试可写副本分开 |

“复用 app 的构建结果”可以立即作为方案基线；“多个实例直接运行同一个 app 目录”需要另行实现。当前便携入口从 exe 所在包根推导 home/data，并覆盖继承的其他实例目录；仅换 DSH_HOME 或 CDP 端口不足以隔离。初期不用 junction、symlink 或硬链接共享 app/profile，以免路径解析、更新写入和单实例锁串到其他实例。

## 2. 当前缺口

- `scripts/dev-desktop.mjs` 每次生成独立 project，但默认 home、electron-user-data、temp 和采样目录仍共享；调试端口固定为 9229/9222/9230。显式传 DSH_HOME 只能解决其中一部分。
- `scripts/prepare-development-profile.mjs` 将运行依赖 junction 到 harness 工作区，开发启动也直接使用该工作区桌面入口与 primary runtime。只复制插件无法固定全部运行代码；首期不得复用这条开发启动链作为便携实例装配器。
- `scripts/portable-dev.mjs --dir` 可指定不同包根，`launch --cdp` 可分开渲染调试端口；缺少实例清单、端口分配、运行中更新保护和产物身份回执。
- 宿主自检有固定 19387 的占用守卫。`verify-portable` 的 `--port`、`--cdp-port` 不能作为所有自检均已支持并行的证据；未完成端点参数化的检查串行执行。
- 当前 harness 桌面宿主使用 `--port 0` 动态绑定，通过 IPC ready 报告实际 URL（`apps/desktop-host/src/index.ts`）。固定 19387 的自检与桌面 GUI 启动是不同契约；具体便携基包还须核对其实际构建，不从源码版本推定包内行为。
- 现有 refresh/set-app/clean 和默认 build 包含删除风险，不能直接成为新调度器的后端。新流程只创建不存在的目录，不覆盖旧实例或旧产物。

## 3. 目标流程

目录全部位于 `.env.local` 配置的 D 盘构建根、工作区外。以下是布局示意，不是已实现的命令：

```text
<构建根>/local-tests/
  inputs/<snapshot-id>/      # 固定构建输入；源码与资产来自同一快照
  artifacts/<artifact-id>/    # 冻结构建、出厂模板、manifest、完成标记
  instances/<instance-id>/   # app、home、data、工作区、实例清单
  evidence/<run-id>/         # 启动身份、步骤回执、截图和测试结果
```

1. **固定输入并构建**：按下节建立输入快照，确认新输出目录不存在，从同一快照完成保留式编译与资产复制。桌面壳只在其输入身份变化时重建；复用已有 app 必须记录该成品的文件摘要、来源与验收记录，不能把当前 harness 源码认作它的构建来源。打包仅用于交付门禁，普通本地实例直接消费目录产物。
2. **固定身份**：manifest 记录 snapshot-id、相关仓库 commit、实际输入清单摘要、锁文件、构建配置、上游与补丁摘要、平台架构、Node/Electron 版本和输出逐文件 SHA256。脏工作树不能只用 commit 作缓存键。全部校验成功后最后写完成标记；失败目录保留且不可消费。
3. **装配实例**：从完成产物复制 app 与出厂模板，安装同一份插件。使用全新实例目录；已有同名目录直接拒绝。实例清单记录 artifact-id、实际路径、模型模式和端点；不记录密钥。
4. **准备与发现端点**：调试端口按需显式配置，启动前检查冲突；场景服务优先由操作系统动态绑定。桌面宿主保持 `--port 0`，启动后通过该实例的受控启动回执或其渲染页连接状态发现实际端点，并核验监听 PID 与进程归属。IPC ready 供壳内部使用，不假定外部启动器可直接订阅。禁止从全机端口列表猜目标或把认证 URL 原文写入证据；记录脱敏端点。固定 19387 的自检单独加锁串行执行，或完成参数化后另行验收。检查空闲与绑定间仍有竞争，绑定失败明确返回，不连接其他实例充数。
5. **启动核验**：记录 exe、PID、命令行、CDP 页面地址、实际 home/data/browser 路径与安装哈希；下一次工具调用再次确认存活。传入子进程的 DSH 自有路径按实例设置，保留系统与外部工具环境；不通过改 HOME、APPDATA 或系统 TEMP 来实现隔离。
6. **运行场景**：各实例持有独立会话、页面和工作区；真实 agent loop 按 [打包态对话驱动](打包态对话驱动.md) 发起。多个对话共享一个实例时用于验证标签归属，不计为实例间隔离测试。
7. **保留结果**：写入可独立核查的证据，退出目标实例后保留其数据；重跑创建新 run-id。产物升级创建新 artifact-id，已运行实例继续固定旧版本。清理由用户按明确路径手动执行。

构建发布与实例装配需要单写者控制：完成标记前读者不可进入；实例运行期间不得 refresh、改 profile 或改 app。凭据使用当前本机凭据加载契约按实例注入，禁止进入公共产物、manifest、日志和证据。

### 构建输入与产物完成条件

- 构建前为插件及本轮需要重建的 harness 建立输入清单，覆盖实际消费的源码、非 TS 资产、脚本、配置、锁文件及相关未跟踪文件。显式记录缺失和删除的输入；排除用户数据、凭据、证据及旧输出，不能把整个工作树无差别复制为快照。
- 在全新目录物化输入，核对复制前后的源清单与快照哈希；发现并发编辑导致不一致即拒绝该快照，保留失败目录。从校验完成的快照构建，编译与 copy-assets 必须使用同一个 snapshot-id。
- 工作区依赖不能通过 junction 偷渡回可变源码：构建消费的 workspace 包及其预构建 lib 必须纳入输入闭包并固定。实现前先列清现有相对路径、link 依赖与工具链解析方式；闭包无法固定时明确失败，不发布“可复现快照”的完成标记。
- 若过渡实现只能在原工作区构建，至少比较构建前后的完整输入清单，变化即失败；此结果标为“工作区构建、前后校验”，不能获得正式快照构建的复用资格，也不能证明构建期间没有短暂改写。
- 完成标记绑定 manifest 摘要；消费时重新核验文件集合和哈希，额外文件、缺文件或内容变化均拒绝。装配先以独占创建获得实例目录，再复制校验，最后写实例完成标记；只有完成实例允许启动。完成标记不能仅以“文件存在”判成功。
- 产物和实例操作锁按目标目录独占，不用一把全局锁串行化所有复制；遗留锁需检查记录的 PID 与启动身份，不能因超时自动删除或抢占。重跑使用新目录，旧结果保留。

## 4. 分步落地

| 阶段 | 修改范围 | 完成判据 |
|---|---|---|
| A：便携构建复用 | 固定输入与产物 manifest；复制 app、模板和插件到全新实例；完成标记与校验 | 同一 artifact 装配 A/B，插件构建只执行一次；安装哈希一致；输入变化、残缺或被篡改产物及已存在目录均被拒绝 |
| B：便携并行测试 | 便携启动和检查脚本消费实例描述；动态发现宿主端点；固定端口自检串行 | A/B 同时存活；实际端点归属正确；调试端口冲突明确失败；双实例真实对话及数据隔离通过 |
| C：开发态快照（后续） | 固定桌面入口、host、primary runtime 与全部运行依赖，移除指回可变工作区的运行链接 | A/B 运行时重新构建另一版 harness，A/B 加载文件仍固定；重启后仍为原版本；独立数据与调试端口通过回归 |
| D：共享 app 目录（可选） | 桌面壳增加受校验的测试实例根契约，在单实例锁前生效 | 同一 app 启动 A/B，各自 home/data/锁隔离；默认双击行为通过回归；app 树运行前后哈希一致 |

首期仅完成 A/B，不改开发启动链和正式便携数据归属契约。C 单独实施与验收；D 只有在磁盘和装配耗时测量显示必要时再做。

## 5. 验收与测量

最少准备两个实例 A/B，使用同一 artifact；记录构建耗时、首次和第二次装配耗时、app/profile 复制字节数、启动到可用耗时、实际磁盘占用。没有本轮测量前不写节省比例。

- **身份**：同源 A/B 安装文件哈希一致；源码或配置变化生成另一产物身份；残缺缓存拒绝消费。
- **输入一致性**：构建时编辑原工作区，已固定快照及其输出不受影响；快照物化中输入变化必须拒绝。编译与资产复制使用不同 snapshot-id、依赖指回可变工作区时拒绝完成标记。相关未跟踪输入变化同样影响身份。
- **失败与并发**：中断构建或装配后不得启动半成品；标记存在但文件被改动时拒绝；两个装配者竞争同一实例目录时只能一个成功。对不同实例的装配可以并行。
- **隔离**：A 写会话、工作区文件、持久 Cookie/localStorage，B 不可见；A 退出重启可读回。B 持续运行，A 的退出和重启不影响 B。
- **启动与冲突**：不同实例各有窗口，同实例重复启动聚焦已有窗口；预占调试端口时返回明确失败。A/B 的宿主 HTTP 动态端口各自发现并验证归属；页面重连或宿主重启后重新核验端点，不沿用旧端口。固定端口自检不得与另一固定端口自检同时执行。
- **真实对话**：A/B 各经 UI 发独立 prompt，检查 agent 身份、页面操作回执和实际页面效果；回放模式与真实模型结果分别报告。
- **版本固定**：准备新插件产物并装配第三实例，A/B 的 app、插件、运行依赖与实际加载版本保持原哈希，退出重启后仍固定；禁止向运行实例推更新。后续开发态 C 必须另验重新构建 harness 对既有实例的影响，不能用只换插件的测试代替。
- **数据与工具兼容**：实例目录各有数据哨兵，装配和重启后保留；外部 Python/npm 等继承环境保持原值。测试产生的数据与证据位于 D 盘。

类型检查、脚本回归、装配校验、双实例 GUI、真实 agent loop、页面效果分别记录结果。当前文档升级未执行这些运行态验收，不能据此宣称已支持安全并行。

### 6.2 已通过的判据

- **同一 artifact 装配 A/B，插件构建只执行一次**：A/B 均来自 `v0.2.19-a4p-mi1`，安装树各 19 文件逐文件哈希一致（Python 侧独立复算，树摘要同为 `036bb9f6…`）。
- **命令行拒例**：重复装配同名实例（「实例目录已存在」）、不存在的产物（`产物不存在：…/artifacts/nope`）、CDP 端口被占（`CDP 端口 9333 已被占用（PID … DeepSeek Harness.exe）`，本机 9333/9433 都被早先起的实例占着）。另有 25 项单测（`src/local-multi-instance.test.ts`）覆盖缺文件/多文件/内容变化拒绝消费、完成标记绑定摘要、并发装配只有一个成功。
- **双实例并行**：A PID 40340/CDP 19533/宿主 51837，B PID 49736/CDP 19534/宿主 62781；`netstat` 核验每个 CDP 端口的 LISTENING PID 就是该实例主进程，宿主端口各自独立。
- **同目录重复启动聚焦**：再 WMI 起一份 A（ReturnValue=0，新 PID 54328），12s 后按 exe 路径清点只剩原主进程 —— 第二个实例把焦点交给已有窗口后退出，没有第二份壳。
- **真实对话（双实例，本地夹具 `scripts/mi-fixture.mjs`，端口 9790）**：A/B 各经渲染页 UI 发独立 prompt；服务端账本（`http://127.0.0.1:9790/log`）为
  `A×2 client=1aa88109-…`、`B×2 client=206f5f78-… / c787d377-…` —— 三个 client 互不相同，没有跨实例的 client 复用（共用浏览器 profile 时会立刻出现在同一 client 名下）。
- **重启 A 不影响 B**：A 走 `mi:stop`（taskkill 未生效后由 CDP `Browser.close` 优雅关闭），期间 B 的回话与工具调用继续；A 随后重新 `mi:launch` 成功取得新宿主端口 64881（未沿用旧端口）。

### 6.3 实跑踩到的两个坑（已固化进脚本）

1. **另一个实例在前台时，目标实例页面是 `visibility: hidden`，输入被静默丢弃**：`Input.insertText` 的回执仍是空的 success，composer 读出来却是空字符串 —— 「已发送」就是这样假出来的。调度器在发消息前先查 `document.visibilityState`，不可见就用单实例锁（再起一次同一个 exe）把目标窗口提到前台；注入后必须能从 composer 读到完整原文才继续，读不到就明确失败（最多重试 5 次，每次带 visibility/focus/editors 诊断），不把回执当证据。
2. **实例重启后会停在「选择一个工作区」**，此时页面上根本没有输入框 —— 调度器先补一步「点默认工作区」再找 composer，而不是报「找不到 composer」了事。

### 6.4 遗留阻塞（下一轮要做的）

- **`webpage_*` 工具疑似同时只能被一个实例持有**：A/B 同 running 时 B 侧模型答「没有任何 webpage 开头的工具」，A 停掉之后 B 再起一轮就能导航并点击（账本里两次 `who=B` 点击都产生在这之后）。反向（B 持有时 A 取不到）本轮没复验 —— A 重启后模型请求连续重试失败（`正在重试模型请求（5/5）`），不能拿「没跑通」当证据。**因此不宣称实例间网页能力可并行**，列为阶段 B 未关闭项。下一轮先排查两个方向：宿主侧能力服务是否只允许一个客户端，或 provider 是否抢了本机某个固定资源。**2026-10-18 复跑未复现**：隔离实例与固定测试实例同时各跑 3–4 次网页调用，两侧都拿到 `webpage_*`、零失败（`disc-restart` / `disc-handoff`），故“同时只能被一个实例持有”降级为未稳定复现；同日仍确认另一条边界——并行时一侧窗口可能被 park 到 `(-16000,-16000)`，需要真实鼠标输入的步骤会连续回 `BROWSER_TAB_NOT_VISIBLE`，输入类验证仍应独占实例。详见 [披露验证](渐进式披露合入验证.md#2026-10-18rc2-上补齐重启恢复交还接管与猜隐藏工具名)。
