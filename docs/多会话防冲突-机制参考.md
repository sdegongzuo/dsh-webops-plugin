# 多会话防冲突机制参考

本文件保留其他文档引用所需的机制约束。当前标签占用任务按 [实施方案](多会话防冲突-实施方案.md) 执行。

## 1. 既有页面保护

写前门保留文档身份与元素有效性检查。文档身份使用 scheme、host、path；仅 query/hash 变化标脏，不按换文档作废。

区域快照 adopt 可在 semanticKey 唯一命中时改绑同一 ref 的 backendNodeId；回执用 reboundRefs 报告，保持“只报不作废”。这项已随页面变化通知交付，不能重新列作待实现。

写前门不能证明同一节点的业务含义不变，也不能代替宿主对话占用检查。源码入口见 `src/browser-cdp/provider.ts`、`refs.ts`、`dirty.ts`；函数位置以当前源码为准。

`evicted` 在 publish/invalidate 时清空，不跨快照累积。一次超大快照仍可能造成较大的导出绑定数据。

## 2. 人工接管

现有实现为 A 档唯键盘：页面视图按 holder 限制键盘输入，标签条提供接管/交还按钮。

接管时作废 ref 并拒绝 agent 写操作；交还时解除拒写，不恢复旧 ref。DevTools takeover 与显式 holder 按来源分别记录和撤销。

不锁标签条，不设 holder 空闲计时器。对话租期释放只改变调用权，详细规则见实施方案 §2.3。

## 3. 增量快照的实施约束

增量快照属于上下文优化，另按 [上下文膨胀方案](上下文膨胀-实施方案.md) 排期，不并入标签占用批次。

1. 主键使用 backendNodeId；semanticKey 仅在未命中且两侧唯一时兜底。
2. changed 比较包含 value 与 reported properties，不能只比较 name。
3. 节点重建、存活率不足时退回全量；存活率阈值建议 50%，实施时显式配置和验证。
4. 提供 full: true；首次、导航后以及超过配置步数时强制全量。
5. diff 基于模型所见视图，包含折叠与 unfoldedLines 语义，不直接比较全量 rows。
6. changed 与 droppedElements、foldedRepeats、truncatedByBudget 分开报告。

收益测量先按同文档分组，并剥离 ref 编号后比较行文本。回执体积与 outline 体积不能混用。
