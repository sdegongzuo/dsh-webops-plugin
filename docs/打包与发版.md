# 打包与发版

本文件给出执行路径与完成判据。执行前读 [验证与发版规则](agent-rules/验证与发版.md)；补丁和历史排障按需查 [机制参考](打包机制参考.md)。

| 任务 | 从哪里开始 |
|---|---|
| 日常插件更新 | §9，使用已有桌面壳 |
| 首次制作完整桌面包或升级上游 | §1–§8 |
| 发布新版本 | §10 |
| Actions 红色、压缩或启动失败 | §7、§11；先查失败步骤日志 |

## 1. 四个前置（缺一必挂）

1. harness 依赖与所需构建产物齐全；本机配置由 scripts/local-env.mjs 读取。
2. 桌面补丁基线与 workflow 的 HARNESS_REF 同源，核对 docs/harness-desktop-build.patch 能应用。已有工作树补丁先查状态，不重复 apply。
3. electron-builder 的 rename 重试补丁适配当前版本。
4. harness 的 apps/desktop/.env.windows 满足当前桌面政策契约；CI 的 harness 使用短路径，避免 LibreOffice 载荷超过路径限制。

升级前保存本地改动，逐条核对补丁理由、上游新增启动契约和运行时布局。具体依据见 [机制参考 §1](打包机制参考.md#1-四个前置缺一必挂)。

## 2. 命令链

命令与参数以 package.json 和 scripts 源码为准。先核对整个调用链的文件行为；包含删除、清空或覆盖旧产物的路径按 AGENTS.md 处理，不能关闭保护绕过。

⚠️ 本仓构建一律走 `pnpm exec tsdown --no-clean`：`pnpm build` 展开是 `tsdown && node scripts/copy-assets.mjs`，而 tsdown 第一个 bundle 配了 `clean: true` —— 默认构建等于先整目录删除 `lib/` 再重建，属删除分支。`--no-clean` 下产物与既有文件并存，chunk 名带内容哈希不会互相覆盖。

本机目录用 .env.local 配置，环境变量优先；运行 rtk node scripts/portable-dev.mjs env 核对来源。产物与暂存放 D 盘且在工作区外，使用未存在的明确输出路径。

### 本体缓存：按 dsh 版本分槽

缓存按 dsh 版本隔离，完成标记 cache.json 与文件完整性均通过后才可复用。写入顺序为 mkdir → 复制 → 校验 → 完成标记。缓存键同时考虑上游与补丁变化。实现依据见 [机制参考](打包机制参考.md)。

### 产物放工作区外（DSH_DESKTOP_BUILD_ROOT）

DSH_DESKTOP_BUILD_ROOT 是构建产物、缓存与暂存的根；DSH_PORTABLE_TEST_DIR 是固定实测目录。实际值和来源使用 portable-dev.mjs env 查看。

### 本地测试的固定目录（别再每轮解压一份）

首次铺底使用全新目标目录；后续只更新插件。portable:refresh、set-app、clean 可能删除文件，不能直接当作保留模式使用。插件保留模式见 §9。启动使用 rtk node scripts/portable-dev.mjs launch --cdp 9333，并在下一次工具调用确认进程和 CDP 仍存在。

### 本机重编桌面端（pnpm harness:build）

网络与镜像从本机配置取得。重编前核对 scripts/harness-build.mjs 及上游子脚本的文件行为和补丁恢复逻辑；改 packages 后先构建相应 host 产物。细节见机制参考对应章节。

### harness 必须放在短路径下（LibreOffice 载荷会撞 MAX_PATH）

Office→PDF 验收必须覆盖 DOCX、XLSX、PPTX。构建与最终解压目录都保持路径简短；具体症状与守卫见机制参考。

## 3. profile 物化

完整包预置 home/profiles/desktop 下的插件登记与真实文件。当前宿主由 app/resources/dsh 提供核心包，不再要求旧版 profile 链接或 desktop-runtime-state.json。

增量包只写插件目录，保留用户 profile/package.json。插件版本与 bundle 判定从已安装插件目录读取。

### 随包第三方插件（vendor 通道）

`vendor/plugins/manifest.json` 是随包第三方插件的登记表（单一真相源）：plugins 登记插件本体（npm tarball + sha512，与 registry `dist.integrity` 逐字节一致），`runtimeDependencies` 登记运行时真正需要嵌套物化的依赖（如 better-sidebar 的 ws/yaml、dsh-context 的 zod——`dependencies` 里其余包是构建期打进 chunk 的，运行时不解析，**不**按它物化）。

打包脚本从 manifest 派生 profile 的 `dependencies`（精确版本）与 `bundles`（追加在内置两个 bundle 与本插件之后），再调用 `scripts/materialize-vendored-plugins.mjs --profile-dir <STAGE>/home/profiles/desktop` 物化（sha512 校验失败/身份不符即中止打包）。新加插件只需：tgz 放 `vendor/plugins/`、登记 manifest（连 integrity 一起换）、manifest 的 JSON 合法性由物化校验兜底。manifest 登记但未物化/未登记的 plugin 会被 `verify:portable` 的 [2/5]/[3/5] 断言拦下。

better-sidebar 自带 `dsh.bundle.patch`（单条 insert + `!!js` 防双挂载守卫），随 bundles 由 profile boot 自动合并，不需要写进用户的 cordis.patch.yml。

### DSH_HOME 的便携兜底

桌面补丁在 resolveDesktopPaths 前为未显式配置的 DSH_HOME 使用便携目录的 home；显式配置优先。Electron userData 仍由 Electron 管理，便携数据边界以 home 为准。

## 4. 四道自检

执行前核对脚本是否删除临时文件，确认 19387 无其他实例。下表给出验收职责，不自动授权运行删除路径。

| 自检 | 完成判据 | 目录条件 |
|---|---|---|
| verify-portable | 运行时完整性、插件登记、真实 applyRelease、出货 patch、客户端加载均通过 | 新解压、未启动 |
| verify-ptc | 真 patch 引擎 compose，包内 Node 命中并可求值 | 按脚本核对副本行为 |
| verify-settings | 用户层设置投影与真实模型配置接受 | 按脚本核对副本行为 |
| verify-browser-host | 包内 exe 开窗口，导航、ref、截图及 provider 正反验证 | 可已启动过 |
| verify-plugin-update | 三轮宿主的探针无→有→无，bundle 比较剥除动态 rev | 已有便携目录；保留模式见 §9 |

## 5. 真机验证（自检过不了这一关的都不能算过）

1. 正常退出目标实例，更新后重新启动；热刷新不替代重启。
2. 核对用户数据保留、插件版本和实际加载文件。
3. 按 [打包态对话驱动](打包态对话驱动.md) 用渲染页 UI 发真实 prompt；19387 的直接接口不能验证 agent 身份归属。
4. 按 [用户故事](用户故事与实测场景.md) 运行独立场景，分别记录页面效果、原始工具结果、模型偏差与环境阻塞。
5. 核对真实鼠标交互、模型回复和工具调用。启动成功、标题非空、静态检查通过均不能替代此门禁。

## 6. 包内 node 路径（打包态专有坑，已修）

打包态 process.execPath 是 Electron 主 exe。PTC 与沙箱子进程使用实际包内 Node，当前路径为 app/resources/runtime/primary-runtime/dependencies/node/bin/node.exe；由描述符和存在性校验确认，不沿用旧路径或依赖环境变量的 shim。故障依据见 [机制参考 §6](打包机制参考.md#6-包内-node-路径打包态专有坑已修)。

## 7. zip 与解压

先验 zip 的 testzip，再验解压文件前 32 字节无 NUL。CRC 正常不能证明写盘内容正常；使用 scripts/unzip-portable.py 解到明确目标目录。

scripts/zip-stage.py 使用共享读压缩，输出与错误输出统一 UTF-8；即使 Windows runner 默认 cp1252，也应完整打印中文路径和失败原因。压缩前输出路径必须不存在，脚本当前仍有旧输出删除分支。

完成判据：压缩 exit=0、testzip=None、结构和实际文件一致、SHA256 对应最终上传附件。

## 8. 出货 patch 的红线

生产 cordis.patch.yml 及生产导出不得包含 fake-llm、llm-replay 或 mock-llm 的 llm/stream 劫持。开发回放仅用于开发态，不能证明真实模型验收。

桌面构建补丁与插件配置补丁分别核对，PTC nodeExecutable 覆盖使用插件 cordis.patch.yml 的真实 compose 验证。机制见参考文档，不以文本存在代替加载生效。

## 9. 插件增量更新包（不必重下 472MB）

只更新插件时使用已有桌面壳。以下占位路径必须换为本轮 D 盘路径，构建目录和 ZIP 目标均新建，保留暂存证据：

~~~powershell
rtk pnpm exec tsdown --no-clean --out-dir <本轮构建目录>
rtk node scripts/copy-assets.mjs --out-dir <本轮构建目录>
rtk node scripts/package-plugin-update.mjs --lib-dir <本轮构建目录> --stage-root <D盘暂存父目录> --keep-stage --out <未存在的ZIP路径>
rtk node scripts/verify-plugin-update.mjs --dir <便携目录> --lib-dir <本轮构建目录> --scratch-root <D盘暂存父目录> --keep
~~~

保留自检只正常退出自建宿主，拒绝 --in-place。默认打包暂存位置为系统临时目录，默认自检会删除暂存文件，本机必须显式传上述目录与保留参数。

包内仅含 home/profiles/desktop/node_modules/dsh-webops-plugin 的 lib、package.json、cordis.patch.yml，以及根目录更新说明.txt。打包会核对五个 Electron 资产，排除 fake-llm 文件及导出。

安装前正常退出，覆盖本轮明确文件，保留用户 home、profile 登记与旧 chunk；然后重启核对版本、数据哨兵与 GUI。生产插件只加载新入口，旧 chunk 无需清理。三轮生效自检和真实最终 ZIP 安装分别记录。

### 纯插件便携包（package-portable 的保留安全模式）

两个插件打包脚本都必须显式传入 `--lib-dir <本轮构建目录>`，遗漏时在写入前拒绝，防止仓库旧 `lib` 被贴上新版本号出货。`scripts/package-portable.mjs` 因此进入**保留安全模式**：暂存是 stage-root 下 mkdtemp 的唯一新目录（全程不删除，`--keep-stage` 仅为参数面对齐）、输出 zip 必须尚不存在（存在即报错）、零 rmSync。原兼容删除分支保留在源码中，但裸调用会因缺少 `--lib-dir` 被拒绝。

~~~powershell
rtk node scripts/package-portable.mjs 0.2.13 --lib-dir <本轮构建目录> --stage-root <D盘暂存父目录> --keep-stage --out <未存在的ZIP路径>
~~~

包内含完整生产 lib 运行时（含 browser-electron 资产，排除 fake-llm）、cordis.patch.yml、发布版 package.json（剔除 devDependencies/scripts 与 fake-llm 导出）、README、LICENSE 与 INSTALL.md；缺任一文件打包前置即报错，不会打出残包。

保留模式会创建输出父目录，路径作为参数直接交给 Python，不拼接 PowerShell。两个插件打包脚本均使用 `zip-stage.py --no-overwrite`：压缩器通过独占创建拒绝既有 ZIP 和检查后出现的目标，保留原文件；未传该参数的历史覆盖分支仍受删除禁令约束，不得运行。`src/package-portable.test.ts` 实际压缩、检验 ZIP，覆盖缺失父目录、含单引号路径、生产文件剔除及拒绝覆盖后的哈希不变。

## 10. 发版

| tag | workflow | 产物 |
|---|---|---|
| v* | release.yml | 插件便携包与增量包 |
| desktop-v* | release-desktop.yml | 完整桌面便携包 |

1. 完成本机类型检查、单测、打包态自检与真实 GUI 门禁，记录版本和提交。
2. package.json 版本与新 tag 一致；两个 workflow 均显式签出 tag。dispatch 的 tag/version 输入决定源码，不能用 main 的修复冒充旧 tag。
3. 选择新版本，核对远端 tag 与 Release 不存在，再发布。已发布 tag 保持原提交，附件保持原内容。
4. 等待对应 Actions 结束，查看步骤结论和失败原文；同时核对 Release 发布状态、确定文件名、大小和 SHA256。两项分别报告。
5. 若本机已上传验收附件而自动 workflow 随后失败，报告“附件已发布 / 自动链失败”，按失败步骤定位；不要用附件存在推断 CI 全绿。

release.yml 已改为**保留式发布**（2026-10-08）：构建走 `tsdown --no-clean`（不删 lib/）；两个打包脚本显式传 `--lib-dir/--stage-root/--keep-stage/--out`（唯一新暂存、既有输出拒绝）；「发布 Release」只在 Release 不存在时新建，同名 Release 已存在时**明确失败并提示换新版本号** —— 旧写法的 `gh release upload --clobber` 覆盖附件分支已按文件删除禁令移除。本机同理：任何输出路径必须未存在，不覆盖、不清理。

本机发版前准备（占位路径换成本轮 D 盘唯一新目录；构建目录、stage-root、三个 zip 全部新建，保留全部暂存证据）：

~~~powershell
rtk pnpm exec tsdown --no-clean --out-dir <本轮构建目录>
rtk node scripts/copy-assets.mjs --out-dir <本轮构建目录>
rtk node scripts/package-portable.mjs <版本> --lib-dir <本轮构建目录> --stage-root <D盘暂存父目录> --keep-stage --out <未存在的便携包ZIP>
rtk node scripts/package-plugin-update.mjs --version <版本> --lib-dir <本轮构建目录> --stage-root <D盘暂存父目录> --keep-stage --out <未存在的增量包ZIP>
rtk node scripts/verify-plugin-update.mjs --dir <便携目录> --lib-dir <本轮构建目录> --scratch-root <D盘暂存父目录> --keep
~~~

发布链依赖与并发设计由 src/bundle-patch.test.ts 约束：发布 workflow 不承担需要本机构建 harness 的类型检查/单测；同 tag 串行等待；收尾 Summary 无论成败记录产物；保留式打包契约（no-clean、保留参数、无 clobber）也在其中锁定。修改 workflow 后按验证规则重跑单测。

## 11. 按症状排障

| 症状 | 先查什么 |
|---|---|
| UnicodeEncodeError / cp1252 | Python 子进程 stdout、stderr 编码；运行中文路径和错误路径回归 |
| host never announced a port | Electron 实际异常、是否误 external 化、运行时依赖；不能只延长超时 |
| GUI 退出 0 且无输出 | ELECTRON_RUN_AS_NODE、NODE_OPTIONS 与打包入口 |
| 界面能见但点不动 | 其他窗口是否遮挡、shell 页面是否正常加载 |
| 压缩或重命名 EBUSY/EPERM | 精确文件和持有者，参考共享读与工作区外构建策略 |
| 发布步骤失败 | tag、附件状态、权限和失败原文；不默认删除重发 |

机制和历史原文见 [打包机制参考](打包机制参考.md)，本机操作边界见 [本机排障规则](agent-rules/本机排障.md)。
