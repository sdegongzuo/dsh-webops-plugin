**「省了多少字符」不是判据。** 本轮一律按这三条判：

| # | 判据 | 为什么 |
|---|---|---|
| **J1** | 有没有**错误信号** —— 工具是否在下「做贵的事」的指令，或回执是否自相矛盾 | 正确性，与膨胀无关也该修 |

### 1.1 口径（可复现）

会话记录在 `$DSH_PORTABLE_TEST_DIR/home/sessions/--D-dev-cli-dsh-webops-plugin--/*/session.v3.jsonl.zstd`：

4. 「行重复率」= 相邻两份快照的**行多重集合**交集 ÷ 后一份行数；「剥 ref 后」= 先删 `[ref=eNN]` 再算（理由见 §1.5）。

### 1.5 P4 门禁口径订正（本轮顺手落，已在 §8 回写）

实测同文档相邻快照：

| 会话 | 对 | 原始行文本重复率 | **剥 ref 后** |
|---|---|---|---|

## 2. 施工清单

### T-A2 · 脏标签分级 + 指令修正（必做，命中 J1）

#### 现状与症状（实测，2026-09-20 12:57 Google 会话）

回执原文：

```
PAGE CHANGED OUTSIDE THIS SESSION: since your last full webpage_snapshot this page had 1 in-page
navigation(s) (history.pushState / replaceState / location.hash). No call in this session reported
that, so a ref you took before that snapshot may now point at a different element — run
webpage_snapshot (full, not regional) before your next ref-based call.
```

时序（`95a282ea`）：`open`（URL 无 `mstk`）→ `fill` 后 URL 冒出 `mstk=`（该条回执**没有** PAGE CHANGED）
→ `press` 后 `mstk` 未再变 → `wait` 后 `mstk` 换成新值 → **PAGE CHANGED 出现在 `wait` 上**。
触发它的变化**只是页面自己换了遥测令牌**（正文剥 ref 后 99.5% 相同）。该会话 7 张快照，
其中 4 张尺寸几乎逐字节相同（10,667 / 10,676 / 10,676 / 10,676）。

两处缺陷：

1. **分级缺失**：`formatPageChanged`（`tool-browser/index.ts:401` 参考点）对**所有**脏信号都用
   「run webpage_snapshot (full, not regional)」。而同一段文案里 `address_drift` 那半句刚说完
   「NOT invalidated」—— **自相矛盾**。
2. **系统提示同一口径**：`tool-browser/index.ts:2345` 参考点写的是「Treat every ref … as unverified and
   run webpage_snapshot (full) again」，只给 `address_drift` 开了例外。**软导航（`within_document`）仍被
   无条件升格成全页重拍** —— Google 那次报的就是 `within_document=1`。

#### 改什么

1. `formatPageChanged` 收尾**按最强信号分级**：
   - `navigated > 0`（真换文档）→ 保持强指令：`The document changed, so every ref you took before that
     snapshot is dead — run webpage_snapshot (full, not regional) before your next ref-based call.`
   - 否则（仅 `within_document` / `address_drift` / `takeover_window`）→
     `The document itself did not change, so your refs are probably still valid — verify the one you are
     about to use with webpage_revalidate (one cheap CDP call) instead of re-running the full snapshot.
     Take a full snapshot only if that reports BROWSER_STALE_REF, or if the outline you hold no longer
     matches the page.`
2. 系统提示那一句同步：把「全页重拍」的适用范围限定为 `navigated`，软导航改「先 `webpage_revalidate`」。
   依据：`webpage_revalidate` 回执实测只有几百字符量级，全页快照是 10.7K —— **用便宜探测代替贵重拍**。
3. 文案不再出现「you took before that snapshot may now point at a different element」这种**断言失效**的话
   （软导航下插件证不了这件事，与 §6.2「措辞是『本会话之外』而不是『有人』」同一条纪律）。

#### 不做（写下来免得被当成漏项）

- **不放宽 `expectSelfNavigation` 的一次性抵账**（`absorb()` 消费一条就返回）。虽然「一次交互触发
  多次 `replaceState`」很像 Google 那次的成因，但 D-21/§6.3 明确选了「一条动作抵一次」，放宽后
  一笔赊账会在 TTL 内吞掉多笔变化 —— 包括**真的人工导航**。方向反了。
- **不加遥测键白名单**（`mstk` / `sxsrf` …）：键名是页面自己的事，列不全，且漏一个就退回今天的错误信号。
  分级做法不需要知道哪个键是什么。

#### 文件 / 单测 / 完成标准

| 项 | 内容 |
|---|---|
| 文件 | `src/tool-browser/index.ts`（`formatPageChanged` + 系统提示那一句）；`src/browser-cdp/dirty.ts` **只读不改** |
| 单测 | `src/tool-browser/index.test.ts`：钉两套文案 —— ① `navigated>0` 必须含 `run webpage_snapshot (full, not regional)`；② 仅 `within_document`/`address_drift` 时**必须不含**该句，且必须含 `webpage_revalidate`；③ 干净时整段不出现（既有用例，别删） |
| 完成标准 | 上述三条绿；`pnpm typecheck` 干净；真机对照：Google 场景里 `mstk` 换值不再产出「跑全页快照」的指令（§3.2 第 ① 项） |

#### T-C2 实施结果（2026-09-20，守卫口径 = `JSON.stringify({name, description, parameters}).length` 逐工具求和）

**口径先说清**：§2.T-C2 上面那张基线表是**日志 `request/header` 口径**（24,822）；
守卫用例量的是**同一份 schema 在进程内的 JSON 序列化长度**。两者差 ~1.1K（序列化细节不同），
**不能混用**。下表一律用守卫口径，判据是**同口径的前后差**。

| 项 | 守卫口径基线（HEAD，含 16×155 的 untrusted 声明） | T-C1 后（实测 21,282） | 本轮完成（实测 17,953） | 说明 |
|---|---|---|---|---|
| `webpage_*` 16 个合计 | **23,762** | 21,282 | **17,953** | **−24.4%**；≤18,000 ✓ |
| 其中顶层 `description` | 13,828 | 11,348 | 9,913 | 只降到 9,913，**没有**达到本节早先写的「≤7,500」 |
| 其中 `parameters` | 9,019 | 9,019 | 7,133 | 掉得比描述多（`SESSION_ID_PARAMETER` 落在这一栏） |
| JSON 骨架 / 属性名 / enum | 915 | 915 | 907 | **不动** |

- **哪一刀贡献最大**（按守卫口径实测）：`SESSION_ID_PARAMETER` 的描述在 15 处各写一遍
  （`'Session id returned by webpage_open. Reuse it for every later call on the same tab.'`）→
  压成 `'Session id from webpage_open.'`，**一句省 ≈840**（系统提示词里已有等价句
  「pass it to every later call」，不是删信息）。其次：16×155 的 untrusted 声明（T-C1，−2,480）、
  `region_*` 三个参数各写一遍的「不使其他 ref 失效 / 互斥」（−330）、`wait` 四个参数各写一遍的
  「Exactly one of time_ms / text / ref / until.」（−176）。
- **「顶层描述 ≤7,500」这条次级指标没达成，也不再作为门禁**：达到它要求把每个工具的
  「什么时候用 / 什么时候不用 / 失效语义 / 失败码 / 下一步」压到平均 ~470 字符，
  实测压到 9,913 时已经出现「再压就要开始丢判据」的迹象（例如 `webpage_execute` 的
  `BROWSER_EXECUTE_RESULT_UNSERIALIZABLE`、`~250 层深度`、顶层 `let/const` 跨调用存活三条
  都是硬判据，只能改措辞不能删）。**门禁只留总量 ≤18,000**，且是**行为门禁**（§3.2）在先。
- **门禁覆盖面已补（2026-09-20 评审时发现缺口，已修）**：原断言只扫 7 个锚点
  （`BROWSER_STALE_REF` / `BROWSER_SNAPSHOT_REQUIRED` / `opened_tabs` / `region_ref` / `occluded_by` /
  `folded` / `webpage_revalidate`），**而上一段点名的 `BROWSER_EXECUTE_RESULT_UNSERIALIZABLE`
  根本不在里面** —— 也就是说「只能改措辞不能删」这句话当时**没有任何断言兜着**：
  把那段散文删掉，总量照样 <18,000、关键词也不命中，没有门禁会红。
  现已补 8 个**只出现在散文里、又没有任何结构性断言保护**的锚点
  （3 个失败码 `BROWSER_EXECUTE_{NOT_ALLOWED,RESULT_UNSERIALIZABLE}` / `BROWSER_NAVIGATION_FAILED`，
  外加 `replay_truncated` / `document_changed` / `node_gone` / `identity_mismatch` / `mime_type`），
  并**单独锚在 `description` 上**而不是整个 schema 上（参数名有 `parameters` 形状兜着、回执字段名有
  `output.schema` 兜着，散文是唯一没人管的层）。
  反向验证：故意把 `BROWSER_EXECUTE_RESULT_UNSERIALIZABLE` 从散文里删掉 → 该用例**单独转红**
  （`1 failed | 80 passed`），还原后 551 passed / 5 skipped。**不是装饰性断言。**
  ⚠️ 这类锚点是从真机 `request/header` 的 schema 里正则扫 `[A-Z][A-Z0-9_]{4,}` 与 `snake_case`
  逐个定位「只出现在 desc」得来的，将来加文案时可照此复查。
- ⚠️ **本轮读数含并行会话的在写内容**：`webpage_execute` 的 schema 在此期间被另一个会话
  从 1,296 涨到 2,385（新增 `timeout_ms` 参数与三段措辞），本轮对该工具的描述按「保事实、砍措辞」
  压到 1,408（`timeout_ms` 语义、顶层 `let/const`、受控组件三条**一条没删**）。
  也就是说 **17,953 是「含对方新增内容」的量**；对方若继续往描述里加字，需重测。

### T-B2 · spill 阈值 50000 → 16000 —— **本轮撤回**（2026-09-20 实测后撤）

**撤回理由（两条，都是查证出来的，不是判断）**

1. **它是全局 host 平面的旋钮，不是浏览器工具的旋钮。** `@deepseek-ai/dsh-spill-policy` 是一个
   `tools/post-execute` 瀑布（`packages/spill/spill-policy/src/index.ts`：`inject = ['tools']`），
   对**所有**工具的所有纯文本回执生效，只放过 `read`（防 read→spill→read 循环）。
   覆盖方式确实存在（本仓 `cordis.patch.yml` 的**顶层 entry** 就是「覆盖已存在行的 config」，
   `ptc-runtime` 那条已用同样手法），但改它的代价是：**每个装了本插件的用户，他任何一次对话
   里任何工具的大回执都被改行为** —— 这与本仓 `cordis.patch.yml` 抬头自己写的纪律
   「加之前先问自己『用户装了这个，他的真实对话会不会被改变行为』」正面冲突。

2. **改成 16K 会把插件自己的快照 spill 掉，正好打掉插件的设计不变量。** 关键数字：

   | 常量 | 值 | 位置 |
   |---|---|---|
   | `NETWORK_LIST_MAX_CHARS` | **40,000** | `src/browser-cdp/network.ts:69` |
   | `CONSOLE_RESULT_MAX_CHARS` | **40,000** | `src/browser-cdp/console.ts:85` |
   | `DEFAULT_SNAPSHOT_LIMITS.maxOutlineChars` | **40,000** | `src/browser-cdp/snapshot.ts:79` |
   | `MAX_SNAPSHOT_LINES` × 60 字符/行 | 可到 **300,000** | `src/browser-cdp/snapshot.ts:91,94` |
   | 出厂 `spill-policy.maxInlineBytes` | **50,000** | harness `packages/bundle/base/cordis.patch.yml:396` |

   插件的三个输出预算**都取 40K**，含义很清楚：**故意压在出厂 spill 线（50K）以下**，
   这样回执永远原样进上下文（快照的 ref 表、network 的 request_id 都不会被外置成附件）。
   把线压到 16K，等于把上面三条全部推到线下 —— 快照首个超线就只剩头尾预览，
   **ref 表被外置掉**（本项目最不能接受的一种退化）。

3. 顺带纠一条原依据：`network list` / `console` 的 34,214 **不是「没被拦」**，
   它们本来就撞在插件自己的 40K 闸门上，并如实回 `truncated_by_budget`。
   要收紧，正确的旋钮是那两个插件自己的常量，**不是** host 的 spill 线。

**如果将来仍要收紧**（只记方向，本轮不做）：调 `NETWORK_LIST_MAX_CHARS` / `CONSOLE_RESULT_MAX_CHARS`
（插件内、可回滚、只影响这两个工具），或给 P2 工具加一个 `max_chars` 参数让调用方自己收；
两者都不碰其它插件与其它 surface 的对话。

**E 的两条独立结论**

**(1) `OVERLAY` 不出是正确行为，是判据/夹具形状不匹配。** `OVERLAY_PROBE_EXPRESSION`（`provider.ts:2801-2827`）
要求浮层在**视口中心**且**盖住 ≥60% 视口**（`visible(node) >= 0.6 * vw * vh`）；夹具那块遮罩只有 320×72
（视口 1279×840 的 ~0.4%），**按定义就不该出**。真 Chrome 上 B2-d 探针把两条都验了：
`scripts/probe-webpage-j.ts` 用「`position:fixed` 全屏 veil + `<a href>` 目标」→ **7/7 PASS**，含
`OVERLAY at viewport center: div #veil — ...` 出现、以及**关掉浮层后 OVERLAY 行消失（不误报）**。
→ **结论：这条判据要验，靶子必须是「整屏 modal」，不是小块遮罩。**

**(2) `occluded_by` 在桌面端不稳定，根因已定位但与本轮改动无关。** 观测：

| 观测 | 会话 | 目标 | `occluded_by` |
|---|---|---|---|
| 1 | `session-54f3604c`（23:35，完全按 §6 E 步骤） | `button "立即领取 ¥50 优惠券（被盖住）"` | ❌ **没出**（回执只有「has no href (probably a JS control)」） |
| 2 | `session-dad328e6`（23:40，`scroll` 后再点） | 同一个 button | ✅ 出了：`role=dialog name="登录后查看" hint=#login` |

排除「插件坏了 / 夹具错了」，三条独立证据：

1. **纯页面侧**：真 Chrome 里对该夹具跑 `HIT_TEST_FUNCTION` 的同一段逻辑 →
   `elementFromPoint` 返回 `DIV#login`、`hit="other"`、`node={role:"dialog",name:"登录后查看",hint:"#login"}`。**算法正确**。
2. **provider 真代码**：`CdpBrowserProvider` + 真 Chrome + **同一个夹具页** →
   被小块遮罩盖住的 button 正常报 `occluded_by`，未被盖住的对照按钮报 `null`。**provider 正确**。
   （复现脚本 `.probe-occl-btn.ts`，跑法 `DSH_CDP_ENDPOINT=http://127.0.0.1:9444 node node_modules/tsx/dist/cli.mjs .probe-occl-btn.ts`）
3. **桌面端环境退化**（`session-84a0c2d9`，页面内实测）：同一时刻读到
   `innerWidth=0, innerHeight=0, outerWidth=0, outerHeight=0, visibilityState="hidden", document.hidden=true,
   document.hasFocus()=false`，且被 `scrollIntoView` 推到「视口中心」后元素 rect 变成 `x=-160, y=-36.125`，
   算出的落点是 `(0,0)`，`document.elementFromPoint(0,0)` 返回 **null**。
   → `hitTest` 拿到 `hit="none"`（**与「真没遮挡」回执完全同形**），且点击坐标本身是垃圾值。

关键联动：**不依赖坐标的交互照常工作、依赖坐标的会退化**。这解释了同一天里 A 场景为什么是好的 ——
`webpage_fill`（原生 setter / `Input.insertText`）与 `webpage_press`（`Input.dispatchKeyEvent`）**都不需要落点**；
而 `webpage_click` 要先 `scrollIntoView` + `getBoundingClientRect` 算落点、再用 `elementFromPoint` 校验，
**整条链都建立在已布局的视口上**。夹具里 `<a href="/">` 点 + Enter 都不导航（D 场景实测），同一个原因。

静默放大的地方：`hitTest` 的 `catch { return undefined }`（`provider.ts:2063-2065`）把「查不出」与「真没遮挡」
压成同一个回执 —— 这是**已知**问题（`.workbuddy/memory/MEMORY.md` 已记「同一份 0.2.7 代码 12:37 没出、12:52 出了」）。

**归因**：本轮三项改动只碰**指令文案**与**工具描述**（`src/tool-browser/index.ts` 的常量），
不碰 `provider.ts` 的任何动作路径；且证据 1/2 证明同一份 provider 代码在真 Chrome 上是好的。
→ **这是桌面端既有缺陷，不是本轮回归。** 触发条件（会话切换后布局未重跑？窗口遮挡？）**本次 2 次观测定不下来**，
可疑机制记在 `docs/CDP实测事实.md` 类的位置：`host.cjs:258-261` 的 `layout()` 在
`isMinimized() || !isVisible()` 时直接 return，且只在 resize 时重跑。

**建议（不在本轮范围，未动手）**：给 `click` 补 `ensureForeground`（全仓目前只有 `scroll` 有，见
`provider.ts:2174`/`2198`），或把落点校验改成「算不出就如实说算不出」而不是静默吞掉。
