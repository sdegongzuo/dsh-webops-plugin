## 1. 依据：实测读数

### 1.1 口径（可复现）

会话记录在 `$DSH_PORTABLE_TEST_DIR/home/sessions/--D-dev-cli-dsh-webops-plugin--/*/session.v3.jsonl.zstd`：

1. `/d/app/msys64/usr/bin/zstd -d` 解压；
2. 按 `tool/call.callId` ↔ `tool/result.message.source.callId` 配对，取 `tool-result` 里 `type:"text"` 全文 —— **这就是模型看到的东西**；
3. 体积用**字符数**（不用 token 数：精确 token 要目标模型的 tokenizer，收益比较要的是可比体积）；
4. 「行重复率」= 相邻两份快照的**行多重集合**交集 ÷ 后一份行数；「剥 ref 后」= 先删 `[ref=eNN]` 再算（理由见 §1.5）。

样本：`95a282ea` Google AI 模式（09-20 12:57）、`e0288ca7` 知乎登录（09-20 13:07）。**两个都是单 turn**，
不是跨用户消息的多轮。

### 1.5 P4 门禁口径订正（本轮顺手落，已在 §8 回写）

实测同文档相邻快照：

| 会话 | 对 | 原始行文本重复率 | **剥 ref 后** |
|---|---|---|---|
| Google | step7→12 / 12→15 / 15→19 / 19→23 | 73.8% / 74.3% / 74.3% / 74.3% | **98.5% / 99.5% / 99.5% / 99.5%** |
| Google | step23→28 | 53.6% | **72.3%**（AI 回答真出来了，refs 56→78） |
| 知乎 | step3→6 / 6→8 / 8→10 | 60.2% / 60.2% / 57.3% | **99.0% / 99.0% / 97.8%** |
| 知乎 | step10→33 / 33→42 | 56.2% / 53.6% | **96.6% / 89.9%** |

**门禁一律改成剥 ref 后再算；实现必须按 `backendNodeId` 比对**（§8 硬要求 1 已要求，这里只是把口径对齐）。

## 2. 施工清单

> 行号是**参考点**，动代码前按符号名核对（本仓库有并行会话在改）。

### T-A2 · 脏标签分级 + 指令修正（必做，命中 J1）

#### 现状与症状（实测，2026-09-20 12:57 Google 会话）

回执原文：

```
PAGE CHANGED OUTSIDE THIS SESSION: since your last full webpage_snapshot this page had 1 in-page
navigation(s) (history.pushState / replaceState / location.hash). No call in this session reported
that, so a ref you took before that snapshot may now point at a different element — run
webpage_snapshot (full, not regional) before your next ref-based call.
```

时序（`95a282ea`）：`open`（URL 无 `mstk`）→ `fill` 后 URL 冒出 `mstk=`（该条回执**没有** PAGE CHANGED）
→ `press` 后 `mstk` 未再变 → `wait` 后 `mstk` 换成新值 → **PAGE CHANGED 出现在 `wait` 上**。
触发它的变化**只是页面自己换了遥测令牌**（正文剥 ref 后 99.5% 相同）。该会话 7 张快照，
其中 4 张尺寸几乎逐字节相同（10,667 / 10,676 / 10,676 / 10,676）。

两处缺陷：

1. **分级缺失**：`formatPageChanged`（`tool-browser/index.ts:401` 参考点）对**所有**脏信号都用
   「run webpage_snapshot (full, not regional)」。而同一段文案里 `address_drift` 那半句刚说完
   「NOT invalidated」—— **自相矛盾**。
2. **系统提示同一口径**：`tool-browser/index.ts:2345` 参考点写的是「Treat every ref … as unverified and
   run webpage_snapshot (full) again」，只给 `address_drift` 开了例外。**软导航（`within_document`）仍被
   无条件升格成全页重拍** —— Google 那次报的就是 `within_document=1`。

#### 改什么

1. `formatPageChanged` 收尾**按最强信号分级**：
   - `navigated > 0`（真换文档）→ 保持强指令：`The document changed, so every ref you took before that
     snapshot is dead — run webpage_snapshot (full, not regional) before your next ref-based call.`
   - 否则（仅 `within_document` / `address_drift` / `takeover_window`）→
     `The document itself did not change, so your refs are probably still valid — verify the one you are
     about to use with webpage_revalidate (one cheap CDP call) instead of re-running the full snapshot.
     Take a full snapshot only if that reports BROWSER_STALE_REF, or if the outline you hold no longer
     matches the page.`
2. 系统提示那一句同步：把「全页重拍」的适用范围限定为 `navigated`，软导航改「先 `webpage_revalidate`」。
   依据：`webpage_revalidate` 回执实测只有几百字符量级，全页快照是 10.7K —— **用便宜探测代替贵重拍**。
3. 文案不再出现「you took before that snapshot may now point at a different element」这种**断言失效**的话
   （软导航下插件证不了这件事，与 §6.2「措辞是『本会话之外』而不是『有人』」同一条纪律）。

#### 不做（写下来免得被当成漏项）

- **不放宽 `expectSelfNavigation` 的一次性抵账**（`absorb()` 消费一条就返回）。虽然「一次交互触发
  多次 `replaceState`」很像 Google 那次的成因，但 D-21/§6.3 明确选了「一条动作抵一次」，放宽后
  一笔赊账会在 TTL 内吞掉多笔变化 —— 包括**真的人工导航**。方向反了。
- **不加遥测键白名单**（`mstk` / `sxsrf` …）：键名是页面自己的事，列不全，且漏一个就退回今天的错误信号。
  分级做法不需要知道哪个键是什么。

#### 文件 / 单测 / 完成标准

| 项 | 内容 |
|---|---|
| 文件 | `src/tool-browser/index.ts`（`formatPageChanged` + 系统提示那一句）；`src/browser-cdp/dirty.ts` **只读不改** |
| 单测 | `src/tool-browser/index.test.ts`：钉两套文案 —— ① `navigated>0` 必须含 `run webpage_snapshot (full, not regional)`；② 仅 `within_document`/`address_drift` 时**必须不含**该句，且必须含 `webpage_revalidate`；③ 干净时整段不出现（既有用例，别删） |
| 完成标准 | 上述三条绿；`pnpm typecheck` 干净；真机对照：Google 场景里 `mstk` 换值不再产出「跑全页快照」的指令（§3.2 第 ① 项） |

### T-C1 · 去掉 16 份重复的 untrusted 声明（值得做，命中 J2）

- 现状：`UNTRUSTED_PAGE_CONTENT_NOTICE`（`tool-browser/index.ts:109` 参考点，**155 字符**）被
  **16 个工具描述各拼一份** = **2,480 字符**；系统提示里另有一份全局声明。
  实测：`request/header.tools` 里含该声明的工具数 = **16/16**。
- 改什么：工具**描述**里不再拼它；系统提示那份保留并写明「适用于所有 `webpage_*` 回执」；
  **回执里保留**（`UNTRUSTED_PAGE_CONTENT_NOTICE` 的 `notes` 用法不动 —— 那才是不可信内容真正到达的位置）。
- 完成标准：`request/header` 里含该声明的工具数从 16 → 0（描述层），回执侧不变（用单测锁 `notes` 仍在）。

### T-C2 · 顶层描述瘦身（值得做，命中 J2）

**基线（实测，`request/header` 口径）**：

| 项 | 字符 | 说明 |
|---|---|---|
| `webpage_*` 16 个合计 | **24,822** | |
| 其中顶层 `description` | **14,457** | 本轮主要工作面 |
| 其中参数内 `description` | **5,509** | 只砍冗余措辞 |
| 其余（JSON 骨架、属性名、enum） | 4,856 | **不动** |

最肥的六个：`webpage_execute` 1,490 / `webpage_snapshot` 1,259 / `webpage_wait` 1,151 /
`webpage_locate` 1,121 / `webpage_click` 1,093 / `webpage_find` 1,016（均含 155 的声明）。

- 改什么：
  - 每个工具**保留**：什么时候用 / 什么时候**不**用、失效语义（谁作废谁）、失败码、下一步动作；
  - 砍掉：与系统提示重复的公共口径、同义铺陈、能从参数名直接读出的解释；
  - **目标：合计 ≤ 18,000 字符（−27%）**，其中顶层描述 ≤ 7,500。
- **修正上一版的估算**：早先写的「≤12K / 每步省 13K」是错的 —— 那要求顶层描述压到 ~2K，
  等于把刚交付的措辞契约砍光。按实测基线，可达目标是 **≤18K**，折算每步省 ≥6.8K，
  即知乎 ≈ 374K（占 6.7%）、Google ≈ 224K（占 5.2%）。
- 文件 / 单测：`src/tool-browser/index.ts`；
  **新增体积守卫用例**（`index.test.ts`）：序列化 16 个工具的 schema（含 `description`、`parameters`）
  断言 `≤ 18_000` 字符，并断言关键契约句仍在（至少：`BROWSER_STALE_REF`、`opened_tabs`、`region_ref`、
  `folded`、`webpage_revalidate` 各至少出现一次）。
- 完成标准：守卫用例绿；`pnpm typecheck` + `pnpm test` 绿；§3.2 第 ② 项读数下降。
- **回滚条件**：实测轮里 §6 场景 A/D/E 的照做率明显回退 → 按工具逐个回滚描述（不动守卫用例阈值）。

### T-B2 · spill 阈值 50000 → 16000（顺手做）

- 依据（实测分布）：快照中位 ~5.5K、最大 **13,750**（**不能被 spill**，否则 ref 表被外置掉）；
  `network list` 34,214 / `console` 类（**应该被 spill**，本来就是可截取日志）。
- 改什么：把 `dsh-spill-policy` 的 `maxInlineBytes` 覆盖成 `16_000`。**先查清覆盖方式**：
  出厂值写在 harness 仓库的 `packages/bundle/base/cordis.patch.yml`（`maxInlineBytes: 50000`），
  本仓能覆盖就落本仓的 profile patch；不能就走打包侧写 profile 级 patch。
- **完成标准**：不是「配置写了」，而是**实测生效** —— 造一条 >16K 的回执，回执里出现 spill 定位信息与预览，
  且全文可按段取回；同时确认 13.8K 的快照**没有**被 spill。
