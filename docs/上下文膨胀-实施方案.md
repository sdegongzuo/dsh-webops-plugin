## 2. 施工清单

### T-A2 · 脏标签分级 + 指令修正（必做，命中 J1）

#### 现状与症状（实测，2026-09-20 12:57 Google 会话）

回执原文：

```
PAGE CHANGED OUTSIDE THIS SESSION: since your last full webpage_snapshot this page had 1 in-page
navigation(s) (history.pushState / replaceState / location.hash). No call in this session reported
that, so a ref you took before that snapshot may now point at a different element — run
webpage_snapshot (full, not regional) before your next ref-based call.
```

时序（`95a282ea`）：`open`（URL 无 `mstk`）→ `fill` 后 URL 冒出 `mstk=`（该条回执**没有** PAGE CHANGED）
→ `press` 后 `mstk` 未再变 → `wait` 后 `mstk` 换成新值 → **PAGE CHANGED 出现在 `wait` 上**。
触发它的变化**只是页面自己换了遥测令牌**（正文剥 ref 后 99.5% 相同）。该会话 7 张快照，
其中 4 张尺寸几乎逐字节相同（10,667 / 10,676 / 10,676 / 10,676）。

两处缺陷：

1. **分级缺失**：`formatPageChanged`（`tool-browser/index.ts:401` 参考点）对**所有**脏信号都用
   「run webpage_snapshot (full, not regional)」。而同一段文案里 `address_drift` 那半句刚说完
   「NOT invalidated」—— **自相矛盾**。
2. **系统提示同一口径**：`tool-browser/index.ts:2345` 参考点写的是「Treat every ref … as unverified and
   run webpage_snapshot (full) again」，只给 `address_drift` 开了例外。**软导航（`within_document`）仍被
   无条件升格成全页重拍** —— Google 那次报的就是 `within_document=1`。

#### 改什么

1. `formatPageChanged` 收尾**按最强信号分级**：
   - `navigated > 0`（真换文档）→ 保持强指令：`The document changed, so every ref you took before that
     snapshot is dead — run webpage_snapshot (full, not regional) before your next ref-based call.`
   - 否则（仅 `within_document` / `address_drift` / `takeover_window`）→
     `The document itself did not change, so your refs are probably still valid — verify the one you are
     about to use with webpage_revalidate (one cheap CDP call) instead of re-running the full snapshot.
     Take a full snapshot only if that reports BROWSER_STALE_REF, or if the outline you hold no longer
     matches the page.`
2. 系统提示那一句同步：把「全页重拍」的适用范围限定为 `navigated`，软导航改「先 `webpage_revalidate`」。
   依据：`webpage_revalidate` 回执实测只有几百字符量级，全页快照是 10.7K —— **用便宜探测代替贵重拍**。
3. 文案不再出现「you took before that snapshot may now point at a different element」这种**断言失效**的话
   （软导航下插件证不了这件事，与 §6.2「措辞是『本会话之外』而不是『有人』」同一条纪律）。

#### 不做（写下来免得被当成漏项）

- **不放宽 `expectSelfNavigation` 的一次性抵账**（`absorb()` 消费一条就返回）。虽然「一次交互触发
  多次 `replaceState`」很像 Google 那次的成因，但 D-21/§6.3 明确选了「一条动作抵一次」，放宽后
  一笔赊账会在 TTL 内吞掉多笔变化 —— 包括**真的人工导航**。方向反了。
- **不加遥测键白名单**（`mstk` / `sxsrf` …）：键名是页面自己的事，列不全，且漏一个就退回今天的错误信号。
  分级做法不需要知道哪个键是什么。

#### 文件 / 单测 / 完成标准

| 项 | 内容 |
|---|---|
| 文件 | `src/tool-browser/index.ts`（`formatPageChanged` + 系统提示那一句）；`src/browser-cdp/dirty.ts` **只读不改** |
| 单测 | `src/tool-browser/index.test.ts`：钉两套文案 —— ① `navigated>0` 必须含 `run webpage_snapshot (full, not regional)`；② 仅 `within_document`/`address_drift` 时**必须不含**该句，且必须含 `webpage_revalidate`；③ 干净时整段不出现（既有用例，别删） |

### T-B2 · spill 阈值 50000 → 16000 —— **本轮撤回**（2026-09-20 实测后撤）

**撤回理由（两条，都是查证出来的，不是判断）**

1. **它是全局 host 平面的旋钮，不是浏览器工具的旋钮。** `@deepseek-ai/dsh-spill-policy` 是一个
   `tools/post-execute` 瀑布（`packages/spill/spill-policy/src/index.ts`：`inject = ['tools']`），
   对**所有**工具的所有纯文本回执生效，只放过 `read`（防 read→spill→read 循环）。
   覆盖方式确实存在（本仓 `cordis.patch.yml` 的**顶层 entry** 就是「覆盖已存在行的 config」，
   `ptc-runtime` 那条已用同样手法），但改它的代价是：**每个装了本插件的用户，他任何一次对话
   里任何工具的大回执都被改行为** —— 这与本仓 `cordis.patch.yml` 抬头自己写的纪律
   「加之前先问自己『用户装了这个，他的真实对话会不会被改变行为』」正面冲突。

2. **改成 16K 会把插件自己的快照 spill 掉，正好打掉插件的设计不变量。** 关键数字：

   | 常量 | 值 | 位置 |
   |---|---|---|
   | `NETWORK_LIST_MAX_CHARS` | **40,000** | `src/browser-cdp/network.ts:69` |
   | `CONSOLE_RESULT_MAX_CHARS` | **40,000** | `src/browser-cdp/console.ts:85` |
   | `DEFAULT_SNAPSHOT_LIMITS.maxOutlineChars` | **40,000** | `src/browser-cdp/snapshot.ts:79` |
   | `MAX_SNAPSHOT_LINES` × 60 字符/行 | 可到 **300,000** | `src/browser-cdp/snapshot.ts:91,94` |
   | 出厂 `spill-policy.maxInlineBytes` | **50,000** | harness `packages/bundle/base/cordis.patch.yml:396` |

   插件的三个输出预算**都取 40K**，含义很清楚：**故意压在出厂 spill 线（50K）以下**，
   这样回执永远原样进上下文（快照的 ref 表、network 的 request_id 都不会被外置成附件）。
   把线压到 16K，等于把上面三条全部推到线下 —— 快照首个超线就只剩头尾预览，
   **ref 表被外置掉**（本项目最不能接受的一种退化）。

3. 顺带纠一条原依据：`network list` / `console` 的 34,214 **不是「没被拦」**，
   它们本来就撞在插件自己的 40K 闸门上，并如实回 `truncated_by_budget`。
   要收紧，正确的旋钮是那两个插件自己的常量，**不是** host 的 spill 线。

**如果将来仍要收紧**（只记方向，本轮不做）：调 `NETWORK_LIST_MAX_CHARS` / `CONSOLE_RESULT_MAX_CHARS`
（插件内、可回滚、只影响这两个工具），或给 P2 工具加一个 `max_chars` 参数让调用方自己收；
两者都不碰其它插件与其它 surface 的对话。
