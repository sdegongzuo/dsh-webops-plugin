# 上下文膨胀实施方案

更新：2026-10-12。状态：工具描述、全工具参数校验、区域读取、等待附快照及旧引用错误附观察已交付至 v0.2.17；click/press 操作后观察候选已完成三组真实模型对比，尚未发布；工具逐步披露已定案、待实现（§3.1）。已有验收与限制见 [验收记录](验收记录.md)，成本测量尚不足以确认稳定费用下降。

## 1. 目标与范围

减少每次模型请求的工具描述成本和无效全页快照，同时保留工具契约与恢复指引。

本方案管理工具 schema、页面变化提示、输出预算和快照优化。遮挡、点击落点、错误回执与 GUI 行为回归统一按 [网页交互方案](webpage交互改进-实施方案.md) 执行；标签调用权按 [多会话方案](多会话防冲突-实施方案.md) 执行。

## 2. 已交付规则与维护约束

### 2.1 页面变化分级

| 信号 | 回执与系统提示的下一步 |
|---|---|
| navigated > 0，文档变化 | 旧 ref 失效；优先使用回执已附的新全页观察，没有附带时先拍完整快照 |
| 仅 within_document、address_drift 或 takeover_window | 不因信号无条件重拍；调用时由运行时检查引用。可信旧引用拒绝随错误附新观察，模型从新 refs 重新选择；大纲与页面不符时主动重拍 |

回执与系统提示使用同一分级规则。仅 query/hash 变化不得同时宣称“ref 未作废”与“所有 ref 已失效”。人工 holder 的拒写规则仍优先执行；交还后必须完成完整观察，内部身份检查不能解除观察门禁。公开 revalidate 已取消，恢复细节统一见 [网页交互方案 §3.4](webpage交互改进-实施方案.md)。

不新增遥测 query 键白名单，不放宽 expectSelfNavigation 的一次性抵账。

### 2.2 工具描述与预算

- 全部 webpage 工具的 schema 预算：逐项计算 `JSON.stringify({name, description, parameters}).length` 后求和，合计 ≤13000 字符。以现有测试守卫为准，不混用宿主 request/header 口径。
- 工具描述保留用途、失效语义、失败码与下一步动作；删去公共重复声明和同义铺陈。
- untrusted 声明保留在系统提示与工具回执中，不逐工具重复拼进 description。
- 关键参数、输出字段和仅存在于 description 的契约锚点分别测试，不能只断言总体积。
- 描述精简后，若真实会话不再正确使用工具，恢复受影响的契约文案，再优化其他冗余。
- 公共 ref 恢复与生成回复操作流程由系统提示统一说明；工具保留最小恢复入口与自身参数条件。有限选项用 enum 声明，区域矩形声明四个必填数值字段；数值范围仍由参数说明和运行时校验共同约束，不使用宿主尚未支持的 minimum/maximum。
- 公共系统提示 ≤6500 字符；与逐工具 schema 求和合计 ≤19000 字符，两项一并守卫，避免仅转移文案。导航 history、标签 action/scope 等有限选项也必须声明 enum；参数依赖关系仍由运行时验证。
- 每次网页工具执行先按公开 schema 拒绝未知字段、类型/枚举错误和非法 JSON 数值，再执行少量范围、非空标识及跨字段规则；统一回 `BROWSER_INVALID_PARAMS`，不修正、不重跑，也不调用浏览器服务。字段允许集直接取自 schema，不另维护副本。

维护位置：注册入口 `src/tool-browser/index.ts`、公共执行包装 `tool-runtime.ts`、参数规则 `parameter-validation.ts`；契约回归见 `index.test.ts` 和 `parameter-validation.test.ts`。

### 2.3 连续对话等待与区域读取

- 优先等待当前回复独有的完成标记；完成标记同时证明已提交时只等一次，不再分别等输入回显与回复完成。
- 未知完成标记时先做一次必要的区域观察，不用固定 sleep、stable 或反复全页快照轮询生成进度。
- `webpage_wait` 命中或正常超时都会附带完整快照并刷新 find 缓存；先用其新 refs，内容完整时直接继续，只有截断或需要精确长文时再 find/区域读取。首次观察仍使用完整快照。
- 操作后观察候选：click/press 已知下一步可见正文时用 wait_text，在同一次调用等待并返回新 refs；立即变化且未知标记时用 observe=true。已附观察不重复重拍，默认动作及 fill/scroll 不增加快照。参数、失败语义统一见 [网页交互方案 §3.5](webpage交互改进-实施方案.md#35-click--press-后观察)；当前只进入测试便携目录，尚未发布。
- region_box 使用 CSS 像素；高 DPI 下按 Page.getLayoutMetrics 取得的实际比例与 DOMSnapshot 坐标对齐，事实依据见 [CDP 实测](CDP实测事实.md#区域裁剪坐标2026-10-01-补验)。

### 2.4 宿主与插件输出预算

维持既有输出预算与宿主 spill/compaction 配置。不得为缩短单条回执而直接把全局 spill 阈值从 50000 降到 16000；该操作会把快照等正常回执一并外置。

新增输出优先使用既有预算、分页与截断机制，不另建一套插件落盘或压缩系统。字符数不能当作精确 token、字节或费用。

## 3. 后续任务与启动条件

### 3.1 工具逐步披露定案（2026-10-11，待实现）

采用「初始四项含 execute、成功打开后自动展开基础操作、其他工具逐项加载」；保持专用工具及现有参数校验，不合并成带大量 action 分支的大工具。状态属于对话，不属于浏览器窗口或插件全局。原常用 13 项并非不可拆分的依赖；execute 从初始阶段就展示，console 与 network 完全独立。旧引用实测后采用 [网页交互方案 §3.4](webpage交互改进-实施方案.md)，取消公开 revalidate，基础组调整为 9 项。

| 阶段 | 可见网页工具 | 触发与调用成本 |
|---|---|---|
| 首次进入网页任务 | `webpage_open`、`webpage_tabs`、`webpage_execute`、新增 `webpage_tools` | 提前展示核心脚本能力；execute 仍需先取得有调用权的 session_id，未打开或领取标签时不能执行 |
| 基础操作 | 上述四项，加 navigate、snapshot、click、fill、press、wait | open 或 tabs.claim 成功后、下次模型请求前自动展开；9 个现有工具加加载入口。旧引用失败随回执带新观察，模型无需调用 revalidate |
| 搜索、滚动、定位、视觉 | 分别按需加 find、scroll、locate、screenshot | 每项独立加载；明确需要多项时可在一次调用中列出所需工具 |
| 控制台 | 按需加 console | `webpage_tools(tools=["webpage_console"])`，不加载 network |
| 网络诊断 | 按需加 network | `webpage_tools(tools=["webpage_network"])`，不加载 console |

`webpage_tools` 只有必填顶层参数 `tools`，为非空数组；元素枚举为 webpage_find、webpage_scroll、webpage_locate、webpage_screenshot、webpage_console、webpage_network。execute 初始可见，不经过加载入口。未知名字拒绝，重复名字按集合去重；只展开请求的工具，不按用途暗中捆绑。需要同时检查控制台与请求时，模型可以明确传入两项，但加载其中一项不会自动加载另一项。不提供 diagnostics 或 all 模式。

加载入口不需要 session_id，不操作页面，不索取脚本代码。description 简短列出可加载工具与用途；返回实际新增工具名、已可见工具名以及「下次模型请求可调用」的提示，不回传全部 schema。重复加载幂等。需求明确时，可以一次列出所需多项工具，或和 open 在同一批调用中加载；状态采用集合并集，完成顺序不能覆盖另一分支。不能承诺所有模型都会并行调用；顺序加载的额外调用必须计入验收。

execute 用于页面脚本、结构化提取、计算与专用工具难以表达的任务，从初始阶段就提供 schema 和超时、副作用规则，取得标签后直接调用，无需加载。基础组保留 snapshot，让首次观察、导航后重拍和交还恢复直接可用；wait 保留完整观察回执。旧 ref 的失败观察按网页交互方案统一处理，不另暴露恢复工具。find、scroll、locate、screenshot 改为逐项加载。代价是首次使用某个按需工具可能多一次加载调用；多项合并请求可减少往返，后续保持已加载状态。基础阶段为 9 个现有工具加 1 个入口，全量为 15 个现有工具加 1 个入口；验收看完整请求成本和任务成功，不只看总注册数。

#### 状态和宿主接线

1. 注册所有配置允许的工具，再通过 `agent/created` 的真实 agent.ctx 安装 scoped `tools.restrict({deny})`；只屏蔽尚未展开的本插件网页工具。不得使用全局 ctx，不用 allow 列表屏蔽其他插件。宿主现有限制继续取交集，加载入口不能越过权限或启用 config=false 的工具。
2. 状态集中在一个披露模块，包含 `coreOpened` 和已加载工具名集合。open/claim 的实际成功结果才提升基础组，失败不提升；加载入口只提升所请求的工具，不额外展开基础组。变更时释放本模块旧限制，再安装新限制；空 deny 时只释放。同步变更在工具返回前完成，下一次请求必须使用新工具集合。
3. 同一对话只展开、不回缩。关闭最后一个标签、释放租约、人工接管、交还、压缩上下文都不收起已经展示的工具，避免下一步恢复或重新打开时重复加载，也避免工具 schema 前缀反复变化。展开不授予标签所有权，真实调用仍通过现有租约、人工接管和 ref 校验。
4. 使用宿主 `sessionProjections` 注册网页能力投影：按 callId 配对本对话成功的 open/claim、加载工具调用与结果，维护 `coreOpened` 和已加载工具名集合。初始化 agent 时先取得已回放完成的投影，再与现有自有标签合并，最后安装限制；切换会话、重启和压缩不能造成重复加载。投影按会话 ID 隔离，fork 只从继承前缀之后的自有事件提升，不继承父对话的加载状态。追加成功事件驱动投影，同时在工具返回前完成当前作用域的集合提升；两条路径幂等。不得新增 `snapshotEvents`、`eventAt` 或 `ownEvents` 历史扫描，也不另存页面内容或 API 凭据。agent 销毁和插件卸载释放 disposer 及内存状态，恢复依赖宿主原有事件持久化与投影回放。
5. 系统提示包含初始指引、基础操作规则与逐工具扩展规则，按实际可见工具拼接。当前「snapshot 不可见就返回空提示」必须调整：初始阶段仍说明 open/tabs/加载入口、标签归属和不可信页面边界。基础阶段保留旧 ref、导航、遮挡、等待、接管交还恢复；execute 的副作用与超时规则只随 execute 展开，console 与 network 的提示分别展开。长页搜索、滚动定位、截图规则只随对应工具展示；尚未加载时简短说明加载入口。所有错误指引引用的恢复工具必须在当前基础组中，或明确给出可调用的加载入口。
6. 浏览器运行时只负责标签和页面状态，不维护第二份披露计数。模型工具清单、lookup、dispatch 使用宿主同一可见性解析器；模型在隐藏阶段直接猜工具名不能绕过限制。请求包含配置禁用的工具时，整次加载拒绝并列出不可用名字；不部分加载、不静默报告成功。

#### 实施与验收门禁

- 先实现独立披露模块和加载工具，再接成功结果、agent 生命周期与分段提示；现有 15 项执行 schema 的公共校验保持不变。加载参数也使用公开 schema 校验，拒绝未知键和非法 enum。
- 契约验证覆盖初始清单、成功/失败升级、幂等加载、并行结果顺序、配置禁用、其他插件可见性、两个 agent 隔离、销毁/卸载、恢复会话与接管交还。反向验证至少覆盖「全局误限制」「旧 disposer 没释放」「下一请求仍使用旧 schema」三种缺陷。
- 实测复用一个便携实例中的独立对话，至少覆盖：初始表单；已有标签 claim；连续回复等待；截图；首次 execute；仅 console 时 network 保持隐藏；仅 network 时 console 保持隐藏；明确请求多项时一次展开；关闭再打开；模型尝试隐藏工具；两对话隔离；人工接管交还及重启恢复。通过标准是实际模型请求清单正确、页面效果正确、无新增参数/不可见工具失败、基础流程零额外加载调用；不是只测 tools.restrict 返回值。
- 保存每一步 request/header、tool/call、tool/result 和页面记录，测量完整工具定义、系统提示、加载回执、模型调用轮数以及真实输入/缓存 token。历史诊断的 16 项为 12990 字符；0.2.17 发布基线的 15 项为 12357、基础 9 项为 7307、初始 open/tabs/execute 为 1835；公共提示 5500，完整定义加提示共 17857 字符。操作后观察候选已改变定义与公共提示，当前成本以最新验收记录为准；加入加载入口及分阶段提示后必须重新测量，不沿用历史子集估算，也不把字符数当精确 token。验收额外确认首次请求含 execute、取得标签后首次脚本调用无需加载；初始系统提示不得引用尚未展示的 snapshot 而不说明自动展开条件。
- 本定案尚未实施隐藏清单；本轮真实模型回归验证完整 15 项集合；它不证明逐步披露后的清单。本轮后续开发验收需单独证明逐步披露后的成功率与请求清单；通过后再按发版规则同时提供独立插件包和完整便携包。

| 任务 | 启动条件 | 实现要求 |
|---|---|---|
| 回执补目标描述 | 实测证明动作目标不明确导致额外工具往返 | 只补必要目标信息；比较新增回执与减少往返的总成本 |
| 增量快照 | 存在长会话反复观察同一文档的真实样本，且收益测量达标 | 按 [机制参考 §3](多会话防冲突-机制参考.md#3-增量快照的实施约束) 实现；保留 full 逃生路径 |
| 调整压缩或 spill | 真实请求接近有效上下文阈值，或确有预算故障 | 先查宿主配置、模型窗口与触发链，再针对原因调整 |
| 继续压 schema | 现有预算不足且新增成本可定位 | 不以删恢复指引换取体积达标；新增功能同步维护预算守卫 |

这些任务不因单次总 token 偏高自动开工。先区分请求前缀、工具回执、模型输出、调用步数与缓存计费，再确定工作范围。

## 4. 执行步骤

1. 用 [测量口径](上下文膨胀-测量口径.md) 取得同类任务基线，记录插件版本、模型、请求步数和配置。
2. 定位成本来源；行为或错误回执问题转入网页交互方案，不继续在本文维护一份待办。
3. 修改工具文案时，同步更新页面变化分级、schema 预算和契约测试。
4. 运行 `pnpm typecheck`、`pnpm test`。对新增守卫做反向验证，恢复后复验。
5. 按 [打包与发版](打包与发版.md) 更新固定测试目录并重启，运行下方回归。
6. 按同一口径比较前后读数，记录收益与行为退化；无受控对照时不宣称因果改善。

## 5. 验收

| 项 | 通过条件 |
|---|---|
| schema 预算 | 现有 ≤13000 守卫通过；关键契约锚点保留 |
| 不可信内容边界 | description 不重复公共声明；系统提示与回执仍声明不可信内容 |
| 真导航 | 指导完整快照，旧 ref 不被继续使用 |
| 同文档变化 | 不无条件要求全页重拍；可信旧引用错误附新观察，模型使用新 refs 继续，不调用公开 revalidate |
| 搜索与连续对话 | 使用文本等待；不以反复完整快照代替等待结果 |
| 长页面 | 完整观察后使用 find/region_ref；只有截断时才增加快照预算 |
| 输出边界 | 正常快照未因全局 spill 改动被意外外置 |
| 行为兼容 | 网页交互方案的搜索、旧 ref、浮层场景无新增退化 |

Google AI 模式使用 `https://www.google.com/ai`。账户或地区不可用时记录环境阻塞，改用可访问的流式页面验工具；不得把站点不可用算成工具失败或连续对话通过。

完成记录只保留提交、版本、测试结果、前后同口径读数与未完成项。
