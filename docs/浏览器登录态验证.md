# 浏览器登录态验证

验浏览器宿主的 profile 生命周期（隔离、关标签、重启读回）时才读本文件。日常打包与发版主线见 [打包与发版](打包与发版.md) §4。

探针通过 `tsx` 执行 `scripts/verify-browser-profile-persistence.ts`。不带 `--bundle` 时执行当前源码 bridge；带 `--bundle` 时把本轮构建复制到唯一证据子目录并动态导入该 bundle，依赖由指定 app 的 `resources/dsh/node_modules/@deepseek-ai` 提供。每次使用新的、尚不存在的 D 盘证据根目录；脚本只新增目录与文件，不清理既有数据。

## 1. 源码 bridge 模式

~~~powershell
rtk pnpm exec tsx scripts/verify-browser-profile-persistence.ts --electron <本轮 Electron.exe> --host <本轮 lib\browser-electron\host.cjs> --evidence D:\dsh-build\browser-profile-evidence --bundle <本轮 lib\browser-electron\index.js> --runtime-app <含 resources\dsh 的 app 根目录>
~~~

判据：

- 两个同时运行的 profile 互相隔离；
- 关闭标签后 localStorage 与两类 Cookie 保留；
- 宿主正常退出并立即重启后，localStorage 与持久 Cookie 读回；
- session Cookie 重启后的表现只记录，不作为门槛。

只用本地夹具 Cookie，不登录真实网站，不能替代真实账号或真实 agent loop 验收。

## 2. 候选 app 模式

`--app-mode --app-root <候选包根目录>` 改用候选 app exe 和 `data/browser` 做单 profile 检查，runtime 默认取该 app。

候选 app 用保留式脚本生成（输入 app 只读，输出必须是新的 D 盘路径，原 app.asar 保持不变）。基包已包含便携数据接线，不重跑只支持 alpha.2 旧主进程锚点的 `prepare-release-app.mjs`：

~~~powershell
rtk node scripts/prepare-browser-profile-candidate.mjs --app <win-unpacked\app> --stage-root <新的 D 盘暂存父目录> --out <新的 D 盘候选根目录\app>
~~~

候选 app 目录在 `<候选根>\app`，配合 DSH shell 选路检查时还需在候选根创建 `home`。生命周期验收：

~~~powershell
rtk pnpm exec tsx scripts/verify-browser-profile-persistence.ts --electron <候选根>\app\DeepSeek Harness.exe --host <本轮 lib\browser-electron\host.cjs> --evidence <新的 D 盘证据目录> --bundle <本轮 lib\browser-electron\index.js> --app-mode --app-root <候选根>
~~~
