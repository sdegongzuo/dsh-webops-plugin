# 本机打包与验收

用于本机构建插件、更新固定测试实例和发布前验收。日常发版从 [打包与发版](打包与发版.md) 进入；重编 DSH 走 [桌面本体升级](桌面本体升级.md)。

先读 [验证与发版规则](agent-rules/验证与发版.md)。以下命令在仓库根目录的 Windows PowerShell 逐条执行，成功后再继续；占位符替换为实际值。这是一份操作指南，不表示检查已完成。

## 1. 准备目录和环境

本机路径由 .env.local 配置、scripts/local-env.mjs 读取，环境变量优先。先查看实际值和来源：

~~~powershell
rtk node scripts/portable-dev.mjs env
~~~

| 输入 | 要求 |
|---|---|
| DSH_DESKTOP_BUILD_ROOT | 构建、缓存与暂存的根目录，放在工作区外的 D 盘 |
| DSH_PORTABLE_TEST_DIR | 固定测试目录，首次铺底后复用 |
| 本轮构建目录、ZIP 输出 | 明确的 D 盘路径，必须尚不存在 |
| 暂存父目录 | 明确的 D 盘目录，脚本在其下创建独立暂存 |
| 基包 app | 来自已验收基包，按 release.yml 的确定附件名和 SHA256 校验 |

先检查脚本及整个调用链的文件行为。包含删除、清空或覆盖旧输出的分支按 AGENTS.md 处理，不绕过保护。测试环境准备及类型检查、单测命令见 [开发指南](开发指南.md#2-类型检查与测试)。

## 2. 构建插件

~~~powershell
rtk pnpm exec tsdown --no-clean --out-dir "<本轮构建目录>"
rtk node scripts/copy-assets.mjs --out-dir "<本轮构建目录>"
~~~

两步均成功且 Electron 资产齐全后，才可打包。默认 pnpm build 会先删除 lib，不用于保留式构建。

## 3. 三轮增量验证

使用已有桌面壳和本轮构建：

~~~powershell
rtk node scripts/verify-plugin-update.mjs --dir "<便携目录>" --lib-dir "<本轮构建目录>" --scratch-root "<D盘暂存父目录>" --keep
~~~

通过条件：原始包无探针、更新包有探针、恢复包无探针；比较 bundle 时只剥除动态 rev，其他字节一致。该检查不能替代最终 ZIP 安装和数据保留验收。

--keep 保留证据，只正常退出自建宿主；不能与 --in-place 合用。默认自检会删除暂存，不使用默认清理路径。

需要单独制作 overlay 自检包时才运行：

~~~powershell
rtk node scripts/package-plugin-update.mjs --lib-dir "<本轮构建目录>" --stage-root "<D盘暂存父目录>" --keep-stage --out "<未存在的自检ZIP路径>"
~~~

overlay 仅供自检，不作 Release 附件；包结构见 [机制参考](打包机制参考.md#包类型与组装)。

## 4. 固定测试目录与真实 GUI 验收

首次用全新目录铺底，之后复用固定目录、仅更新明确的插件文件。portable:refresh、set-app、clean 可能删除文件，先查源码和规则；不能将它们直接当作保留模式。

1. 正常退出目标实例，安装本轮插件，保留用户 home、data、profile 登记与旧 chunk；用户安装步骤见 [安装说明](portable-install.md)。
2. 重启目标实例，核对 exe、PID、CDP、实际加载文件、插件版本和数据哨兵。热刷新不能代替重启。
3. 按 [打包态对话驱动](打包态对话驱动.md) 从渲染页 UI 发真实 prompt，再按 [用户故事](用户故事与实测场景.md) 验鼠标交互、模型回复和实际工具调用。
4. 分别记录页面效果、原始工具结果、模型偏差与环境阻塞。三轮探针和最终 ZIP 安装结果分别记录。

启动固定目录实例使用：

~~~powershell
rtk node scripts/portable-dev.mjs launch --cdp 9333
~~~

在下一次工具调用确认进程和 CDP 仍存在。19387 的直接接口不能证明 agent 身份归属；窗口出现、标题非空或绿测试不能替代 GUI 和真实工具结果。

多实例测试见 [本地多实例测试方案](本地多实例测试方案.md)，共享同一 app 目录尚未验收；浏览器 Cookie 与存储生命周期单独按 [浏览器登录态验证](浏览器登录态验证.md) 执行。

## 5. 打包态自检

执行前检查脚本的临时文件行为，并确认宿主端口无其他实例占用；端口检查方法见验证规则。

| 自检脚本 | 通过条件 | 目录条件 |
|---|---|---|
| verify-portable | 运行时完整性、插件登记、真实 applyRelease、出货 patch、首次启动准备及完整客户端图通过 | 固定目录可复用；验证副本行为见脚本 |
| verify-ptc | 真实 compose 和 schema 解析通过，包内 Node 可求值 | 先查副本与清理行为 |
| verify-settings | 用户设置投影及真实模型配置接受 | 先查副本与清理行为 |
| verify-browser-host | 包内 exe 开窗口，导航、ref、截图及 provider 正反验证通过 | 可使用已启动过的目录 |
| verify-plugin-update | 三轮探针无→有→无 | 见 §3 |

首次启动检查保留临时证据：

~~~powershell
rtk node scripts/verify-portable.mjs --dir "<便携目录>" --keep-temp
~~~

其他自检的参数和文件行为先对照对应脚本。所有必需项通过后，将版本、提交、产物身份、命令结果及未验项写入 [验收记录](验收记录.md)。

## 6. 手动打发布包

仅在本机验最终包或排障时执行；日常 Release 由 Actions 自动打包。先完成 §2，版本取本仓 package.json.version。

~~~powershell
rtk node scripts/package-portable.mjs "<版本>" --lib-dir "<本轮构建目录>" --stage-root "<D盘暂存父目录>" --keep-stage --out "<未存在的独立插件ZIP>"
rtk node scripts/package-release-portable.mjs --app "<已验收基包app目录>" --plugin-zip "<本轮独立插件ZIP>" --version "<版本>" --stage-root "<D盘暂存父目录>" --out "<未存在的完整便携包ZIP>"
~~~

两个命令的插件 ZIP 路径须对应。脚本拒绝既有输出；独立插件包和完整包的结构、兼容检查见 [机制参考](打包机制参考.md#包类型与组装)。

压缩用 scripts/zip-stage.py，解压用 scripts/unzip-portable.py。通过条件：压缩 exit=0、testzip=None、解压文件前 32 字节无 NUL、结构与实际文件一致、SHA256 对应实际附件。CRC 通过仍要检查写盘内容，见 [压缩与解压机制](打包机制参考.md#7-压缩解压与诊断)。

## 失败处理

失败时保留输入、暂存和原始错误，停止后续发布；修复后重跑受影响的验收。发布状态核对回到 [发版入口](打包与发版.md#失败处理)。

| 症状 | 先查什么 |
|---|---|
| UnicodeEncodeError / cp1252 | Python stdout、stderr 编码，运行中文路径及错误路径回归 |
| host never announced a port | Electron 异常、误 external 化、运行时依赖，不能只延长超时 |
| GUI 退出 0 且无输出 | ELECTRON_RUN_AS_NODE、NODE_OPTIONS 和打包入口 |
| 界面可见但点不动 | 其他窗口遮挡、shell 页面加载 |
| 压缩或重命名 EBUSY/EPERM | 精确文件与持有者；共享读和工作区外构建策略 |

更多本机操作边界见 [本机排障规则](agent-rules/本机排障.md)。
