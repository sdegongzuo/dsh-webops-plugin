# 网页观察优化方案

用途：部分实现的混合方案，供继续设计与验收时查阅。范围按下方 2026-10-17 状态及各阶段说明判断；已实现的工具行为查 [快照与上下文](快照与上下文.md) 和 [网页交互](网页交互.md)，未验收目标不作交付承诺。

状态：2026-10-17续验，A正确性机制及B局部观察机制已有实现与历史实测；本轮补正动作内等待信号与加载入口指引，并以相同预算的正文首尾预览减少尾部补读。固定聊天对照每条件五例已结束：候选任务5/5且零工具错误，对照任务5/5但一次参数拒绝，两组零错误门禁未过。保留全部尝试的诊断比较显示累计输入中位数约低42.4%、峰值约低8.2%，只作为后续判断线索；整体上下文目标尚未验收，暂不做增量。最新候选已恢复安装，继续补齐其他场景回归。历史对照、失败采样和本轮试跑分别登记，不合并成当前版本的通过率。目标仍是提高实际任务正确性，同时减少调用与上下文。源码候选契约见 [快照与上下文](快照与上下文.md)、[网页交互](网页交互.md)，安装身份按验收哈希判断。

## 1. 决策与适用范围

实施顺序：先修正搜索、范围与完整性信息，再验证区域观察的使用路径；增量作为有条件的观察返回模式，暂不新增独立工具。

- `webpage_find` 保持独立、缓存只读搜索；匹配扩展到本次已采集的完整正文，不静默刷新页面。
- `webpage_snapshot` 保持全页与区域入口；已观察到的明确 ref 可直接操作，不强制 find→区域观察。
- 区域选择解决“读哪里”，增量返回解决“同一区域哪些内容变化”。完整区域始终可用。
- 保留其他区域有效 ref 的现有行为；区域观察不能解除交还后的全页观察门禁。

固定场景、提示词和页面验收在 [用户故事 S11–S16](用户故事与实测场景.md#4-观察优化场景-s11s16)。基线结果统一登记到 [验收记录](验收记录.md)，成本按 [测量口径](上下文膨胀-测量口径.md)。

## 2. 基线取证与判断方式

先固定安装目录、exe/PID、CDP、插件哈希与实际请求中的模型及工具清单。从渲染页 composer 给六个独立对话发送任务，经真实 agent loop 调用；夹具服务端记录实际选择、提交、排序、弹窗与删除。真实网站另验，定向诊断另列。

逐条对照提示与持久化 user/message；最后 turn/end 证明对话结束，不证明任务正确。读任务逐字对照夹具正文和最终输出；操作任务对照服务端事件与页面回执。tool/call 与 tool/result 按 callId 配对。

分别统计显式全页/区域 snapshot、wait 与动作附观察、find、execute、错误和回执字符；输入、缓存读取和输出 token 从实际 usage 汇总。回执少于原来的比例不等于累计输入或费用下降。

本轮每个任务一次，仅用于发现具体弯路，不估计稳定成功率。候选实施后须重复前后对照；本轮不承诺增量或更短回执已经改善成本。

### 2.1 实测对方案的约束

2026-10-13 的六个自然任务基线是安装态 0.2.18；2026-10-15 恢复后的诊断与真实站复验使用 0.2.19。工具入口哈希相同，但浏览器接线与其他宿主工具环境已变，分组记录，不能把 token 差异作为候选 A/B。实际读数与原始会话索引见 [本轮验收](验收记录.md#2026-10-1315网页观察优化探索基线与补验)。

| 实测发现 | 设计决策 |
|---|---|
| 长文已经获得完整代码，仍反复 find 并两次 execute | 优先让完整正文可直接匹配，明确原文完整性；不先增加新的搜索工具 |
| 项目乙选择正确，但最终回答丢失代码缩进；工具回执原文正确 | 内容忠实度单独验收，提示保留原文；不能把“点击成功”当整个任务通过 |
| 甲→乙→甲只需一次全页和三次区域观察，旧锚点可用 | 区域能力保留；先修范围回执，多层缓存暂缓 |
| 表单两次提交准确，但 wait_text 首次用了原本存在的字段标签“手机号” | 完成标记要来自本次业务结果；以异步错误夹具补验，不能用字段存在证明提交完成 |
| 连续回复重复完整观察，使用observe后再stable；输入与预设字符串不同且旧提示有歧义 | 优先减少重复调用、使用本轮完成标记，正式提示明确字面值并强调逐字保持；不能只做diff |
| 商品排序前后行多重集合完全相同，顺序却已变化 | 行重复率只能测体积线索，增量必须保存结构/顺序与节点身份；重排不确定时完整回退 |
| MDN首次观察前两次find被拒；读Parameters后搜索Return value零命中，但最终答案来自此前全页 | 明确先完整观察再检索；范围与观察来源必须展示，不把缓存零命中当整页不存在，不信模型对操作顺序的自述 |
| 尾部定向find零命中，但按段落前缀取full_text含同一关键词 | 完整正文匹配属于已复现问题；不增加CDP搜索或自动扩大范围 |

两项未达预设判据：输出缩进丢失，以及输入与预期字符串不同。2026-10-15复核发现旧聊天提示未给“第一问蓝天”等字面值加引号，可能被理解为轮次说明；不能仅凭此认定模型擅自缩写。正式对照使用明确引号与逐字要求，旧记录保留并单列。输入/输出忠实度与页面效果、调用成本分别验收，增量不能自动修复这些问题。

## 3. 第一阶段：搜索与回执

### 3.1 搜索已缓存的完整正文

原基线的 `searchOutline()` 先匹配大纲行，`full_text` 仅在命中后附加完整正文，导致已缓存尾部关键词无法命中。A阶段已修正为同时搜索缓存正文；以下保留设计与验收要求。实现入口为 `src/tool-browser/snapshot-cache.ts`，注册与渲染为 `tools/discovery.ts`。

1. 同时匹配大纲与其对应的完整正文/正文块。相同条目一次命中，保留稳定对应关系。
2. 默认返回关键词周围的有界片段及结构定位；`full_text=true` 返回所需原文，保留空白与尾部。
3. 同一正文块多行命中只返回一次全文；不合并两个文本相同但位置不同的章节。
4. 命中数量预算与正文字符预算分别记录。正文截断时明确完整性与续读办法，不能仍声称完整原文。
5. 多检查一条匹配以确定是否还有结果，修正恰好到达 limit 就宣称截断的现有判断。
6. 搜索不增加 CDP 命令，不扩大已观察范围，不发布新的可操作权限。正文无 ref 时只授予读取信息。

验收：尾部关键词可以直接命中；完整代码空白与结束标记准确；同块重复输出消失；真实模型不需要以 execute 补救已有正文。

### 3.2 范围与完整性显式化

原基线缓存记录 region 类型而find未展示。A阶段回执已增加全页/区域、区域标识和观察版本；epoch 标识引用纪元，不能代替每次区域观察的版本。

- 区域零命中只表示本次缓存区域未命中；提示使用已知区域外锚点读取所需区域。
- 尚未观察时明确“先完整snapshot，再find”；导航失效与首次无缓存区分。成功全页snapshot替换并建立新缓存，不再沿用当前错误里“每次全页snapshot删除缓存后仍需再拍”的错误表述。
- 全页截断、匹配分页、正文截断分开表达；“没有命中”不能推断整个当前页面不存在。
- 明确 cached 表示观察时内容，不保证现在仍在页面上；真实操作继续经过写前门。
- 若相应字段增加常驻 schema，计入现有 schema/提示预算，不以移动文案制造虚假节省。

暂不建立自动拼接的新旧区域缓存。S13 可以用保留的全页锚点切换区域，先修范围表达；只有反复找区域外目标确实导致全页重拍，才评估单独的导航索引。索引与正文观察时间须明确区分。

### 3.3 正确表达观察范围与下一步

原基线的 `snapshot-output.ts` 建议已知控件再 find→区域观察；A阶段已改为目标明确即可直接使用，只有缺细节或消歧时读取更多。

区域回执区分本次可见控件/锚点与会话保留的 ref。原基线 `page-observation.ts` 直接返回 `session.refs.list()`；A阶段已取本次发布与存活引用的交集，不能将整张保留表数量当本区域控件数。

`outsideRegion` 取全页与区域 rows 差，包含只读锚点；A阶段已按条目口径表达，不再称全部为 actionable elements。区域零控件提示使用“此区域”，不能断言整页零控件。

不因精简回执删去不可信内容、引用恢复、派发状态和接管门禁。明确“原文已完整”不代表业务完成；页面完成仍需独有文本标记或页面结果。

公共提示增加简短正向规则：用户指定的输入原样完整填写；原文块直接保留空白与尾部；本轮完成标记可用时在提交 click/press 中等待该标记。已有完整原文或附观察满足任务时直接继续。通过 S12/S15 的严格任务验收核对提示效果，不把重新措辞视为已解决模型偏差。

## 4. 第二阶段：区域读取与消歧

### 4.1 区域边界与原文读取

现有标题区域采用标题至下一同级/高级标题，限制在最近 section/article/main/body 中。先补真实形状的边界回归：嵌套章节、重复标题、标题末尾、长回复、区域外弹窗。

回执标明所选区域类型与实际截断。需要完整原文时，评估在区域观察内按需返回正文，减少 snapshot→find 的必要往返；这属于候选接口，实施前比较完整区域正文与 find 正文检索的实际成本。默认大纲保持紧凑。

原文过长时以同一观察版本续读，声明偏移、剩余与完成状态；版本变化则拒绝混拼并要求重新读取。复用已有预算/分页路径；不额外建立插件落盘体系。分页不能把同一节反复全部返回。

### 4.2 同名目标

find 的 context 当前从大纲缩进推断，无法确定祖先时回退到之前标题/文本。改进候选为结构化章节/列表项路径，输出短上下文，精确名称与角色优先。

S12 一次正确点击只证明现有路径可完成该夹具，不证明消歧已经不足或新增过滤参数必要。先增加标题所属项目与按钮上下文的困难样本，出现实际误选再实施额外筛选参数。不凭同名项数量直接加入语义搜索。

## 5. 第三阶段：局部增量的启动条件

先优化以上路径并重新测 S14/S15。若完整区域仍大且反复相同，才试增量；若主要重复来自默认 wait 的全页观察，先评估等待成功后的区域观察，避免直接用全页 diff 解决范围错误。

等待条件与观察范围是两个概念。局部附观察不能解除交还门禁；首次、真导航后和交还后仍需要完整观察。未知范围保持全页，新弹窗必须有发现路径。任何范围扩展均需与 `tools/mutations.ts` 和共享 snapshot/cache 路径统一，不能产生第二套 find 状态。

### 5.1 候选返回契约

增量作为 snapshot 可选模式，初版显式启用并保留完整返回入口；参数名在实现评审时定案。范围与模式独立：相同区域有可靠基线才输出变化，否则明确返回完整观察及原因。

输出包含基线/当前观察标识、范围、增加/修改/删除、必要父级上下文与当前控件；删除条目标记不可操作。value、选中/禁用等 reported properties 参与比较。ref 节点身份与引用纪元独立处理，不能仅复用文本编号。

以完整的变化单元返回，例如字段＋错误、回复标题＋变化正文、完整新弹窗。新弹窗或全局阻断信号独立提示；区域输出不能宣称区域外没有变化。

保持缓存中本次完整逻辑视图，find 搜完整观察视图而非仅变化行，并明确其范围。增量输出不得引入模型从未观察过的可操作映射；基线基于模型可见的折叠/截断语义。回执失败、取消与持久化不确定时放弃基线，避免只因内部采集成功就推进。

基线按对话owner、session、租约代次、文档身份、区域和视图预算隔离；领取/移交后不用原owner的增量基线。初版不另持久化页面正文。实现前核对宿主工具结果落地事件与下一请求之间的顺序，不能确认基线已进入模型上下文时返回完整。

全页snapshot继续publish并作废旧ref；局部增量须沿区域adopt的引用路径设计，不为省字符修改全页契约。节点替换/改绑仍报告rebound，重复名称不能充当稳定身份。必要当前引用信息计入回执成本；文本很少但引用映射很大时也可能没有增量收益。

### 5.2 强制完整回退

首次、真导航、人工交还、范围改变、基线缺失、节点大范围重建、列表重排身份不确定、折叠或预算差异无法解释时返回完整观察。模型可随时要求完整。自动回退不能重放原动作。

节点比较与回退细节遵守 [既有增量机制约束](多会话防冲突-机制参考.md#3-增量快照的实施约束)，其中 50% 存活阈值只是待验证建议，不作为已确认参数。重启/压缩后不能假定模型保留基线；初版允许丢弃增量状态，恢复用完整观察。

## 6. 实施与验收顺序

| 批次 | 改动 | 验收 |
|---|---|---|
| A | 完整正文匹配、范围/完整性、精确 has-more、去重与准确计数/引导，输入/原文忠实度与独有完成标记指引 | 尾部和范围诊断通过；S11–S13 原文与选择正确；S15输入逐字保持；已有代码后的重复读取减少 |
| B | 区域原文按需输出/续读、必要消歧信息、评估等待后局部观察 | S11–S16 全部正确；每轮回复完整，两次表单提交，弹窗不遗漏；普通动作不默认增加读取 |
| C | 局部增量与完整回退 | 可靠基线下回执下降，累计输入有收益；新增/删除/属性变化与重建回退正确，任务无新增误选/补拍 |

每批先跑对应契约，再安装候选并重启核对身份，复跑真实桌面对话。保存前后提示、request/header、call/result、usage、页面事件和最终原文；真实页面单列。样本固定模型、任务、页面、预算和其他工具；按多次独立新对话比较分布，缓存命中单列。

候选进入主实现的必要条件：原文和页面任务全部达标，无错误或重复副作用；预算守卫保留；新增查询成本计入累计输入。没有受控 A/B 时只报告机制正确，不宣称稳定成功率或费用改善。

验收矩阵增加延迟变体：表单错误异步出现；回复先静默超过stable窗口再继续；排序复用节点但业务身份交换；弹窗在观察区域外；正文关键词仅在尾部；原文超过输出预算。逐项验证真实状态，尤其避免同步夹具掩盖过早等待与隐式重试。

进入C前至少取得三次同模型、同任务、同范围的B阶段长会话样本，确认重复仍来自必要的观察；区分背景、历史回复与必要上下文。回执重复多但区域本身很小，或重复调用尚未解决时不进入C。候选最终每条件至少五次独立对照，报告完成率、调用/回执与累计输入的中位数和范围；样本量只是本方案工程验收门槛，不等于统计显著性。稳定费用结论需另行核对计费与缓存数据。

## 7. 实施进度与交付边界

### 7.4 动作后默认区块观察（2026-10-18 实施）

上一节把「默认全页」定为唯一未闭合项，本节的改动就是它：不传`region_ref`时，click/press的附观察默认落在**被操作元素所在的区块**，区块解析不出来才静默回退全页。观察触发条件一个都没动（不传`observe`/`wait_text`的click/press仍然零观察），首次、真导航、交还、新浮层仍强制全页。

实现分三层，取舍都写在源码注释里：

1. 页面脚本`ENCLOSING_BLOCK_FUNCTION`把元素自内向外换成最近的块级容器（`section/article/main/nav/form/li/tr/td/details`或块级`role`），到`body`/`html`就返回null——**不把整页当区块**，否则等于没优化还骗过了全页兜底。
2. provider按`resolveNode`→页面脚本→`DOM.describeNode`三步拿到区块的`backendNodeId`，再用DOM快照的`parentIndex`求子树，与AX树求交后走现有的区域过滤与`adopt()`。用DOM子树而不是AX父子链，是因为区块元素在AX里可能被折叠（`display:contents`、`aria-hidden`包着），而它在DOM里一定在。
3. 三档「不可用」全部回退全页且**不报错**：元素已被这次动作换掉、区块在AX里没有可呈现内容、区块就是body。附观察跑在动作之后，把它打成`observation_error`等于对调用方撒谎。

真机证据（无头Chrome + S15同源`chat`夹具，脚本`.probe-enclosing-block-20261018.mts`，走与provider相同的三步）：`#send`的区块是那个`<section>`；全页大纲3879字符/28行→区块93字符/3行；点一次「发送」后区块249字符且含`第1轮回复`与`【第1轮完成】`（本轮结果确实落在区块内，这是它能替代全页观察的前提）；把按钮从文档里摘掉后同一路径拿不到区块（返回null，生产代码据此回退全页）。单测另覆盖区块只回本块、解析不出回退、AX为空回退、`region.enclosing`与`region.ref`互斥、以及`Browser.mutate`的四步装配顺序（首次全页/默认区块/显式优先/wait无默认）。schema守卫未抬预算（14000与9000仍绿），`observe`与`region_ref`的描述同步压缩抵掉新增字数。
